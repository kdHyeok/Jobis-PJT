# 20. 통합 실험판 잔여 구현 일괄 결정

- 확정일: 2026-08-06
- 적용 범위: `C:\jobiss-service-v3-integration-lab`과 승인된 additive 변경에 한해
  `C:\jobiss-capability-graph-lab`
- 목적: D010, D016~D020, D035~D036, D043~D045의 미확정 경계를 한 번에 고정하고
  잔여 구현·검증을 추가 질문 없이 진행할 수 있게 한다.
- 보호 원칙: Legacy AI와 기존 사용자 데이터는 보존한다. Git 커밋·Push와 데이터 초기화는
  별도 요청 전까지 수행하지 않는다.

## 1. 완료 목표

- 현재 통합 실험판을 기능과 자동 검증 기준으로 완성한다.
- 실제 운영 배포와 V3 전면 전환은 실제 사용자 표본·운영 인프라·비용 자료를 확보한 뒤 별도
  출시 결정으로 남긴다.

## 2. 공고 원문 확인

- URL HTML, 이미지, OCR/VLM 결과는 사용자가 확인한다.
- 정확성을 계약으로 보장하는 공식 구조화 API만 향후 `TRUSTED_DIRECT_SOURCE`가 될 수 있다.
- 현재 자동 확인 출처는 없다.

## 3. 신규 역량 승인

- 승인된 canonical key, display name 또는 exact alias와 원자 범위가 일치하면 자동 재사용한다.
- 신규·유사·범위 변경 후보는 운영자 검토 전 공용 그래프에 승격하지 않는다.

## 4. 적합도 표시와 계산

- 하나의 종합 점수로 합치지 않고 형식적 지원 자격, 필수 역량, 우대 역량, 프로젝트 준비도,
  검증 준비도를 분리한다.
- 역량 상태 값은 `VERIFIED=100`, `EVIDENCED=70`, `CLAIMED=30`, `NOT_MET=0`으로 계산한다.
- `UNKNOWN`은 분모에서 제외하고 분모가 0이면 `계산 불가`와 reason code를 표시한다.
- 형식 조건과 필수 역량을 판정에 우선하며 우대사항은 지원 자체를 차단하지 않는다.

## 5. AI provider와 Legacy

- 통합 실험판 기본 provider는 V3로 설정한다.
- 운영 기본 provider는 출시 검증 전까지 Legacy로 유지한다.
- Legacy 코드는 삭제하지 않는다.
- V3 실패를 사용자 모르게 Legacy 결과로 대체하지 않는다.
- 모델은 환경 변수로 선택하고 처리 시간·사용량을 기록한다.

## 6. Capability Graph 발행

- `C:\jobiss-capability-graph-lab`에 운영자 전용 staged import API를 additive 방식으로 추가할 수 있다.
- 흐름은 `release bundle → 미리보기 import → 계약·출처·순환 검증 → 운영자 활성화 → 새 graph version`
  순서로 고정한다.
- 소비자 조회 API는 계속 read-only이며 기존 활성 버전은 명시적 활성화 전까지 변하지 않는다.

## 7. 관련 취업과 경력 증거

- 자기 신고는 `CLAIMED`, 재직·프로젝트 근거가 있으면 `EVIDENCED`, 운영자 또는 검증 절차를
  통과하면 `VERIFIED`다.
- 경력 구간의 진행 표시는 `EVIDENCED` 이상부터 시작한다.
- AI는 관련성을 제안하고 코드는 canonical role family와 핵심 역량 관계를 검증한다.

## 8. 최소·최대 경력

- 현재 공고 적합도에서는 최소·최대 경력을 모두 지원 조건으로 사용한다.
- 장기 로드맵에서는 최소 경력만 진행 관문이며 최대 경력은 현재 공고 기준 경고다.
- 미래 재공고는 새 revision 또는 새 posting 조건으로 다시 판정한다.

## 9. 프로젝트 완료와 역량 검증

- 필수 project task와 완료 기준, 코드 저장소 또는 결과물 근거, 필수 원자 역량 검증을 모두
  충족해야 프로젝트를 완료할 수 있다.
- 우대 task는 bonus이며 프로젝트 완료를 차단하지 않는다.
- 검증 완료는 자동 만료하지 않는다. 수행 범위 또는 노드 버전이 바뀔 때 부족한 부분만 재검증한다.

## 10. 현재 목표와 최종 목표

- 현재 목표 공고는 사용자가 최종 선택하고 AI는 후보와 이유만 제안한다.
- 최종 목표는 자유 입력 또는 공고 선택을 지원한다.
- AI가 사용자의 목표를 자동 교체하지 않는다.

## 11. 보존과 삭제

- 활성 자료는 사용자가 보관하는 동안 유지한다.
- 사용자 삭제 데이터는 운영 DB에서 즉시 논리 삭제하고 비동기 물리 삭제한다.
- 삭제 데이터는 백업에서 최대 30일 안에 폐기한다.
- 민감 원문을 최소화한 AI 진단 로그는 30일, 원문 없는 보안·운영 감사 로그는 1년 보존한다.
- 계정 탈퇴는 비동기 삭제 작업과 상태를 제공한다.

## 12. 암호화

- 전송 구간은 TLS를 사용한다.
- 저장소 OAuth token의 AES-GCM을 유지한다.
- 이력서·공고 원문·검증 답변은 application-level AES-GCM 대상으로 한다.
- 중복 검색은 평문 대신 별도 HMAC fingerprint를 사용한다.
- 암호화 키는 DB와 분리된 환경 비밀값으로 관리하고 운영자 열람을 감사한다.

## 13. 인증 세션

- access token은 2시간, 회전형 refresh token은 14일로 한다.
- 사용자가 `로그인 유지`를 선택하면 refresh 수명은 30일이다.
- refresh token 재사용이 탐지되면 해당 token family를 모두 폐기한다.
- 로그아웃은 서버에서 token family와 현재 access token을 무효화한다.
- 만료 전 자동 갱신을 지원하고 재인증이 필요해도 작성 중 입력을 보존한다.

## 14. 분석 동시 실행과 검증 허용

- 사용자당 동시 분석 2개, 로컬 전체 worker 동시 실행 2개를 기본값으로 한다.
- 초과 작업은 취소 가능한 명시적 대기열에 두고 중복 요청은 새 작업을 만들지 않는다.
- Vitest, Vue Test Utils, Playwright 테스트 의존성과 브라우저 설치를 허용한다.
- 기존 사용자 DB와 분리된 전용 테스트 DB를 자동 시작·종료할 수 있다.
- 공개·합성 공고 5개를 Legacy/V3 각각 2회, 최대 20회의 실제 AI 비교 평가를 허용한다.
- 외부 사용량 제한이 발생하면 완료된 측정과 미완료 이유를 구분해 기록한다.
