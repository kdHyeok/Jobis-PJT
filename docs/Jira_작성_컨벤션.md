# C202 팀 Jira 작성 컨벤션

> Jira는 팀원의 업무와 진행 상황을 공유하기 위한 협업 도구입니다.
> 실제 업무 상태와 Jira 상태가 일치하도록 관리합니다.

* **Jira 보드:** https://ssafy.atlassian.net/jira/software/c/projects/S15P11C202/boards/14291
* **적용 대상:** C202 팀 전원

---

## 1. 기본 운영 규칙

### 매일 아침

* 본인이 오늘 진행할 업무를 확인합니다.
* 등록되지 않은 업무는 `작업`으로 생성합니다.
* 실제 작업을 시작하면 상태를 `진행 중`으로 변경합니다.

### 퇴근 전

* 오늘 완료한 내용과 현재 진행 상황을 업데이트합니다.
* 남은 작업이나 문제가 있다면 댓글에 기록합니다.
* 완료된 업무는 결과물 링크를 첨부하고 `완료`로 변경합니다.

---

## 2. 이슈 유형 구분

### 에픽

이번 주에 진행할 **큰 업무 단위**를 등록합니다.
에픽은 여러 개의 작업으로 나눌 수 있는 기능 또는 업무 단위로 작성합니다.

```text
[AI] 채용공고 분석 에이전트 구현
[RAG] 채용공고 검색 시스템 구축
[BE] 사용자 경험 관리 기능 개발
[FE] 취업 준비 로드맵 화면 구현
```

### 작업

당일 또는 2~3일 이내에 완료할 수 있는 **구체적인 업무 단위**를 등록합니다.

```text
[AI] 채용공고 요구사항 추출 프롬프트 작성
[RAG] 문서 청크 분할 로직 구현
[BE] 사용자 경험 등록 API 구현
[FE] 로드맵 카드 컴포넌트 구현
```

하나의 작업이 너무 크거나 여러 기능을 포함한다면 에픽과 여러 작업으로 나눕니다.

---

## 3. 제목 작성 규칙

모든 이슈 제목은 다음 형식으로 작성합니다.

```text
[태그] 구체적인 작업 내용
```

### 담당 영역 태그

| 태그        | 영역                       |
| --------- | ------------------------ |
| `[AI]`    | AI 모델, 에이전트, 프롬프트        |
| `[RAG]`   | RAG, 임베딩, 검색, 벡터 데이터베이스  |
| `[BE]`    | 백엔드, API, 서버 로직          |
| `[FE]`    | 프론트엔드, UI                |
| `[DATA]`  | 데이터 수집 및 정제              |
| `[INFRA]` | 서버, 배포, Docker           |
| `[DB]`    | 데이터베이스 설계 및 관리           |
| `[PM]`    | 일정 및 프로젝트 관리, 문서화, 발표 준비 |

업무가 여러 영역에 걸쳐 있더라도 **가장 중심이 되는 태그 하나를 사용**합니다.

```text
[AI] 채용공고 분석 에이전트 구현
[RAG] 채용공고 검색 파이프라인 구현
[BE] 사용자 경험 등록 API 구현
[FE] 취업 로드맵 화면 구현
[DATA] 채용공고 데이터 정제
[INFRA] 개발 서버 Docker 배포
[DB] 사용자 경험 테이블 설계
[PM] 중간 발표 자료 작성
```

제목은 이슈를 열지 않아도 작업 내용을 파악할 수 있도록 구체적으로 작성합니다.

```text
나쁜 예: [BE] API 개발
좋은 예: [BE] 사용자 경험 수정 API 구현
```

오류 수정이나 테스트 업무는 별도의 태그를 만들지 않고 해당 기능 영역의 태그를 사용합니다.

```text
[BE] 로그인 토큰 만료 오류 수정
[FE] 회원가입 입력값 검증 테스트
[RAG] 검색 결과 정확도 테스트
```

## 4. 필수 작성 항목

모든 이슈에는 다음 항목을 작성합니다.

* 담당자
* 마감 기한
* 관련 에픽
* 작업 내용
* 완료 조건

```markdown
## 작업 내용

- 수행할 작업을 구체적으로 작성합니다.
- 필요한 구현, 수정, 조사 내용을 작성합니다.

## 완료 조건

- [ ] 작업 결과가 정상적으로 동작한다.
- [ ] 필요한 테스트 또는 확인을 완료한다.
- [ ] MR, 문서 등 결과물 링크를 첨부한다.
```

담당자가 여러 명이어도 대표 담당자 1명을 지정합니다.

---

## 5. 상태 관리

| 상태    | 기준                     |
| ----- | ---------------------- |
| 할 일   | 아직 시작하지 않은 업무          |
| 진행 중  | 실제로 작업 중인 업무           |
| 리뷰·확인 | 구현 후 리뷰 또는 테스트가 필요한 업무 |
| 완료    | 완료 조건을 모두 충족한 업무       |

실제 작업을 시작했을 때 `진행 중`으로 변경하고, 필요한 테스트와 리뷰까지 끝난 후 `완료`로 변경합니다.

---

## 6. 진행 상황 업데이트

작업이 끝나지 않았다면 퇴근 전에 현재 진행 상황을 기록합니다.

```markdown
## 진행 상황

- 완료: API 기본 구현
- 진행 중: 예외 처리 및 테스트
- 문제 사항: 응답 스키마 확인 필요
- 다음 작업: 테스트 완료 후 MR 생성
```

진행이 어려운 문제나 블로커가 발생하면 혼자 기다리지 않고 Jira에 기록한 뒤 팀에 공유합니다.

---

## 7. 결과물 링크 첨부

업무가 완료되면 관련 결과물 링크를 Jira 이슈에 첨부합니다.

* GitLab MR
* Commit 또는 Branch
* API 명세서
* Notion 문서
* Canva 디자인
* 테스트 결과
* 배포 주소
* 관련 Jira 이슈

```markdown
작업 완료했습니다.

- MR: 링크
- API 명세서: 링크
- 테스트 결과: 링크

주요 변경 사항:
- 사용자 경험 등록 API 구현
- 입력값 검증 추가
- 예외 처리 추가
```

---

## 8. Mattermost 공유

다음 상황에서는 관련 Jira 이슈 링크와 함께 Mattermost에 공유합니다.

* 작업 완료 및 리뷰 요청
* 일정 변경
* 블로커 발생
* 설계 또는 정책 결정 필요
* 다른 팀원의 업무에 영향을 주는 변경

```text
[BE] 사용자 경험 등록 API 구현 완료했습니다.
Jira: 이슈 링크
MR: 링크
예외 처리와 테스트까지 완료했습니다.
리뷰 부탁드립니다.
```

Mattermost에만 공유하고 Jira를 업데이트하지 않거나, Jira에만 작성하고 팀에 알리지 않도록 주의합니다.

## 9. 일일 Jira 사용 흐름

### 업무 시작 전

1. Jira 보드를 확인합니다.
2. 본인에게 할당된 이슈를 확인합니다.
3. 당일 업무가 없다면 작업을 생성합니다.
4. 담당자와 마감 기한을 지정합니다.
5. 작업 시작 시 `진행 중`으로 변경합니다.

### 업무 진행 중

1. 중요한 진행 상황을 기록합니다.
2. 블로커가 발생하면 즉시 공유합니다.
3. 작업 범위가 커지면 여러 작업으로 분리합니다.

### 퇴근 전

1. 완료한 내용을 기록합니다.
2. 남은 작업과 문제 사항을 기록합니다.
3. 실제 업무에 맞게 상태를 변경합니다.
4. 완료된 업무에 결과물 링크를 첨부합니다.
5. 공유가 필요하면 Jira 링크와 함께 Mattermost에 전달합니다.

* [ ] 관련 에픽에 연결했는가?
* [ ] 작업 내용과 완료 조건을 작성했는가?

### 퇴근 전

* [ ] 오늘 진행 상황을 업데이트했는가?

* [ ] 블로커나 일정 변경 사항을 공유했는가?
* [ ] 필요한 내용을 Jira 링크와 함께 Mattermost에 전달했는가?

## 11. 핵심 규칙 요약

1. 매일 아침 본인의 당일 업무를 확인하거나 생성합니다.
2. 주간 단위의 큰 업무는 `에픽`으로 작성합니다.
3. 당일 또는 2~3일 이내의 업무는 `작업`으로 작성합니다.
4. 제목은 `[태그] 구체적인 작업 내용` 형식을 사용합니다.
5. 담당자와 마감 기한을 반드시 지정합니다.
6. 실제 업무 상태와 Jira 상태를 일치시킵니다.
7. 퇴근 전 진행 상황과 남은 작업을 업데이트합니다.
8. 완료 시 MR, 문서 등 결과물 링크를 첨부합니다.
9. 블로커가 발생하면 즉시 Jira에 기록하고 공유합니다.
10. 팀 공유가 필요하면 Jira 링크와 함께 Mattermost에 전달합니다.
