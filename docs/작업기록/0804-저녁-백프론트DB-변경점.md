## 2. 백엔드 — 파일 1개 신설, 1개 수정

### 신설 `career/repository/DocumentText.java`

업로드 파일(base64) → 텍스트. **새 의존성 없음**(`build.gradle` 무변경).

- docx 는 ZIP 안의 `word/document.xml` 이므로 표준 라이브러리 `java.util.zip` 으로 푼다.
  Apache POI(수 MB · 전이 의존성 다수)를 들이지 않았다 — 필요한 것은 그 XML 의 글자뿐이다.
- md·txt·csv·json 은 UTF-8 로 그대로 읽는다.
- 형식은 **파일명 확장자**로 가른다. 브라우저 MIME 은 OS 설정에 따라 비거나 틀리게 온다
  (docx 가 `application/octet-stream` 으로 온다).
- 실패는 `ApiException` **400 `INVALID_FILE`** — 잘못된 파일에 500 을 주면 사용자가 고칠 수
  없다. 원인 예외는 `initCause` 로 붙여 둔다(400 은 스택이 로그에 안 남는다).
- 서식·표·이미지는 버린다. 단락·줄바꿈·탭은 **태그를 지우기 전에** 공백 문자로 바꾼다 —
  순서를 뒤집으면 모든 단락이 한 줄로 붙어 하류 파서가 항목 경계를 잃는다.

### 수정 `career/repository/CareerRepositoryController.java`

`POST /api/career-sources` 요청 본문이 넓어졌다. **하위 호환된다** — 기존 호출(rawText 만)은
그대로 동작한다.

```diff
 public record CreateSourceRequest(
     String sourceType,        // TEXT|FILE|URL  (변화 없음)
     String title,             // (변화 없음)
     String sourceUrl,         // (변화 없음)
-    @NotBlank @Size(min = 20, max = 100_000) String rawText
+    @Size(max = 100_000) String rawText,          // ← @NotBlank 제거
+    @Size(max = 2_800_000) String fileBase64,     // ← 신설(선택)
+    @Size(max = 260) String fileName              // ← 신설(선택)
 )
```

- `rawText` 의 `@NotBlank` 를 뗀 이유: docx 업로드는 원문 없이 바이트만 오므로 그대로 두면
  **400 으로 막힌다.** 대신 `@AssertTrue hasContent()` 가 "원문 20자 이상 **또는** 파일"을
  검사한다 — 둘 다 없으면 여전히 400 이다.
- `fileBase64` 상한 2,800,000 = 원문 2MB 가 base64 로 약 1.34배 커지는 값.
- 컨트롤러는 파일이 오면 `DocumentText.fromUpload()` 로 텍스트를 만들어 **기존
  `CreateSource.rawText` 자리에 넣는다.** 그 아래(서비스·SQL·추출 워커·AI)는 전부 무변경.

## 3. 프론트엔드

### 신설 `src/resumeFile.ts`

업로드 파일 읽기를 **한 곳으로 모았다.** 두 화면이 각자 읽으면 한쪽만 docx 를 지원하는 상태가
조용히 생긴다 — 실제로 커리어 저장소 화면은 `file.text()` 로만 읽어서 **docx 를 올리면 깨진
바이트가 원문으로 등록되고 있었다.**

- docx → `fileBase64`(서버가 푼다), 그 밖 → `rawText`.
- base64 변환은 32KB 씩 쪼갠다 — 2MB 를 인자 스프레드로 한 번에 넘기면 `RangeError` 로 죽는다.
- 상수 공개: `RESUME_ACCEPT`(`.md,.txt,.docx,.csv,.json`), `RESUME_MAX_BYTES`(2MB),
  `RESUME_MIN_CHARS`(20 — 서버 검증과 같은 값. 여기서만 통과시키면 등록 시 400).

### 수정 `src/api.ts`

`createCareerSource` 페이로드에 `fileBase64?`·`fileName?` 추가(선택 필드).

### 수정 `src/views/ChatView.vue` — 요청받은 변경

대화 컴포저의 공고 첨부 옆에 **이력서 첨부 버튼**을 넣었다. 지금까지 이 자리는 공고만 받았다.

- `<label>` 이 파일 입력을 품는 형태. 입력은 `display:none` 이 아니라 **투명하게 겹쳐 둔다** —
  숨긴 입력은 일부 브라우저·스크린리더에서 포커스를 못 받아 키보드로 파일을 고를 수 없다.
- 등록은 `POST /api/career-sources` (커리어 저장소). **파편 확정은 자동으로 하지 않는다** —
  저장소 화면에서 사용자가 고른다.
- 추출은 비동기(`CareerExtractionWorker`)라 끝난 척하지 않고 "저장소에서 조각을 고를 수 있어요"
  까지 알린다. 성공 문구는 `error` 가 아니라 새 `notice` 로 낸다(빨간 글씨로 성공을 알리지 않는다).
