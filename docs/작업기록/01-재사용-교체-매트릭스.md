# 01. 재사용·개선·교체 매트릭스

- 기준: 현재 구현의 작성 주체가 아니라 JOBIS v3의 책임 경계와 정확성
- 판정: `REUSE`, `ADAPT`, `REPLACE`, `REFERENCE_ONLY`

## 1. 판정 정의

| 판정 | 의미 |
|---|---|
| `REUSE` | 의미 판정과 독립적이며 공개 계약을 확인한 뒤 그대로 사용한다. |
| `ADAPT` | 기반은 유지하되 새 계약이나 안전 게이트에 맞게 얇은 변경이 필요하다. |
| `REPLACE` | 기존 결론이 새 설계와 충돌하므로 새 구현의 판단 근거로 사용하지 않는다. |
| `REFERENCE_ONLY` | 아이디어·실패·테스트 패턴만 참고하고 실행 코드로 가져오지 않는다. |

## 2. AI팀 코어

| 영역 | 판정 | 근거와 처리 |
|---|---|---|
| LLM 공급자·Claude CLI 실행 | `REUSE` | 모델 호출, 타임아웃, 환경 설정은 의미 판정과 분리되어 있다. |
| 에이전트 manifest | `ADAPT` | 전제·산출·무거움·동의 개념은 유지하고 v3 능력 목록으로 다시 선언한다. |
| planner | `ADAPT` | 자유 대화 의도 분류는 유지하되, 공고 분석은 검증된 원문 상태를 전제로 제한한다. |
| orchestrator 상태 전이 | `REUSE` | 에이전트가 세션을 직접 바꾸지 않는 원칙과 observe 구조를 유지한다. |
| trace·progress 수집 | `ADAPT` | 내부 LLM 반복이 사용자에게 멈춤처럼 보이지 않도록 세부 공개 이벤트를 추가한다. |
| 구조화 응답 검증·repair | `REUSE` | JSON 계약 검증은 필수다. repair가 의미를 새로 만들지 못하도록 제한한다. |
| URL·HTML·iframe 수집 | `ADAPT` | 수집기는 유지하지만 출력에 출처·세그먼트·경고·버전을 추가한다. |
| 이미지 타일 분할·VLM | `ADAPT` | 원본 영역과 타일 중복 정보를 보존하고 사용자 확인 전에는 신뢰 데이터로 사용하지 않는다. |
| RAG 어댑터 | `REUSE` | 검색 기반은 유지하고 추천의 최종 순위와 존재 검증은 서버가 담당한다. |
| 세션 자산 모델 | `ADAPT` | `VerifiedPostingSnapshot`, 선택 포지션, 사용자 정정 내역을 자산으로 추가한다. |
| `role_taxonomy.py` 최종 판정 | `REPLACE` | 폐쇄형 별칭과 본문 빈도로 직무를 확정하지 않는다. 정규화 사전으로만 새로 구성한다. |
| `classify_seniority` 최종 판정 | `REPLACE` | 숫자·키워드 우선순위로 경력을 확정하지 않는다. 포지션별 근거 기반 해석으로 교체한다. |
| `graph/read_nodes.py` 룰 우선 병합 | `REPLACE` | “룰이 LLM을 이긴다”는 의미 필드에 적용하지 않는다. 규칙은 모순 검출만 한다. |
| 현재 `NormalizedJobPosting` | `REPLACE` | 단일 직무·단일 경력·평평한 요구사항 계약을 `positions[]`로 교체한다. |
| gap matcher | `ADAPT` | unknown 보존과 근거 매칭은 유지하고 `CLAIMED/EVIDENCED/VERIFIED`를 분리한다. |
| semantic judge | `ADAPT` | 근거가 제공된 제한된 관련성 판정에만 사용하고 이진 결론보다 신뢰도·불확실성을 보존한다. |
| 자연어 renderer | `REUSE` | 정형 결정을 바꾸지 않고 표현만 담당하는 원칙을 유지한다. |
| 공고 추천 agent | `ADAPT` | 실제 카탈로그 후보만 사용하고 사용자별 적합도와 공용 후보 검색을 분리한다. |
| 기존 planner/eval 하네스 | `ADAPT` | 라우팅 평가에 계속 사용하고 의미 정확성 데이터셋을 별도로 추가한다. |

## 3. v2bridge

| 영역 | 판정 | 근거와 처리 |
|---|---|---|
| HTTP·인증·기본 오류 변환 | `ADAPT` | 새 계약 버전과 오류 코드를 지원하는 얇은 어댑터로 축소한다. |
| trace의 UI 이벤트 변환 | `ADAPT` | 동적 단계 UI는 유지하되 source/verification 단계 이벤트를 추가한다. |
| 실제 결과 컨테이너 포장 | `REUSE` | AI 결과를 임의로 바꾸지 않는 원칙은 유지한다. |
| 원문 기반 사전 직무 질문 | `REPLACE` | 구조화 전에 전체 원문 키워드로 복수 직무를 판단하는 경로를 제거한다. |
| `role_catalog.py` 최종 판정 | `REPLACE` | 게임·웹·보안 목록은 alias seed로 참고하되 최종 직무 판정기로 사용하지 않는다. |
| `taxonomy.py` 요구사항 판정 | `REFERENCE_ONLY` | 현재 분류 순서와 마커는 실패 사례와 seed 자료로만 사용한다. |
| 공고 요건→로드맵 직접 mapping | `REPLACE` | 분석된 요구사항과 학습 커리큘럼 제안을 분리한다. |
| 근거 없는 fallback 문장 | `REPLACE` | 출처 근거가 없으면 `null`과 경고를 반환한다. |
| 질문 `CHOICE/TEXT` 계약 | `ADAPT` | 기본 형식은 유지하고 질문 목적·대상 포지션·해소할 ambiguity를 추가한다. |
| 분석 convergence 처리 | `ADAPT` | 반복 상한은 유지하되 같은 빈 질문이 반복되는 원인을 상태 계약으로 차단한다. |

| 로드맵 좌표·간선 알고리즘 | `ADAPT` | 입력 계약만 바꾸고 배치 알고리즘은 별도 회귀로 보호한다. |
| 운영자 감사·되돌리기 | `REUSE` | 신규 기술·중복 공고·AI 이상 결과 검토에 확장한다. |

## 6. 보존해야 할 팀의 결정

- 모르는 정보는 미충족이 아니다.
- 외부 변경과 최종 확정은 사람의 승인 대상이다.
- 도구는 근거 데이터를 반환하고 사용자 문장은 표현 계층이 만든다.
- 세션 상태 전이는 오케스트레이터가 독점한다.
- AI가 존재하지 않는 공고나 증거를 만들지 않는다.
- 경고와 fallback 이유를 숨기지 않는다.
- 프롬프트·모델이 바뀌면 실제 모델 평가를 다시 수행한다.
- 총점뿐 아니라 케이스별 정확성과 안정성을 본다.

## 7. 새 설계에서 금지할 이전 패턴

- 사전에 있는 단어 하나로 직무·경력을 확정하지 않는다.
- 원본 위치가 없는 OCR 문장을 확정 근거로 사용하지 않는다.
- 공고 하나를 강제로 단일 직무로 축약하지 않는다.
- adapter가 AI에 없는 근거·기술·프로젝트를 만들어내지 않는다.
- 공고의 복합 문장을 그대로 기술 노드 제목으로 사용하지 않는다.
- 이력서의 기술명 언급만으로 검증 완료 처리하지 않는다.
- 테스트 기대값을 현재 구현 출력에 맞춰 사후 변경하지 않는다.
- 새 버전 검증 전에 기존 버전을 삭제하거나 대체하지 않는다.
