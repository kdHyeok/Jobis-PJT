# 05. 실제 실패 기반 회귀 시나리오

- 목적: 현재 구현의 출력을 그대로 답으로 삼지 않고, 실제 공고 의미와 제품 결정을 기대값으로 고정한다.
- 등급: `P0` 결과 전체를 오염, `P1` 주요 기능 왜곡, `P2` UX·복구·운영 문제
- 상태: 시나리오 정의 완료, 원본 fixture 수집·비식별화는 구현 Phase 0에서 수행

## 1. 직무와 포지션

## 10. 평가 방법

### 결정론적 계약 지표

- schema validity: 100%
- evidence reference validity: 100%
- cross-user leakage: 0건
- unverified source analysis: 0건
- duplicate job/question creation: 0건

### 의미 정확성 지표

- position precision/recall
- experience exact match와 false-positive rate
- required/preferred classification
- requirement atomicity
- evidence span precision
- unknown과 not_met 혼동률
- roadmap-ineligible requirement leakage

### 안정성 지표

- 같은 모델·프롬프트로 각 fixture 최소 3회
- `correct and stable`, `stable-wrong`, `unstable`을 별도 집계
- 평균 정확도만으로 통과하지 않음
- P0 케이스는 한 번이라도 잘못 확정하면 실패

### 평가셋 관리

- 기대값 변경에는 제품 결정 또는 원문 근거를 기록한다.
- 기존 구현 출력에 맞추기 위한 기대값 변경을 금지한다.
- 모델·프롬프트·taxonomy·계약 변경 시 같은 fixture를 재측정한다.
- 실제 공고 원문은 이용 조건과 개인정보를 확인해 비식별 fixture로 보관한다.
