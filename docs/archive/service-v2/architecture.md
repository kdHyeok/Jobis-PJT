# JOBISS 아키텍처

## 실행 구조와 신뢰 경계

```text
Browser
  └─ HTTPS ─> Vue/Nginx
                └─ /api ─> Spring Boot
                              ├─ transaction-scoped RLS ─> PostgreSQL
                              └─ authenticated internal HTTP ─> AI server
                                                                  └─ Claude
```

- 인증은 HttpOnly `jobiss_access` 쿠키, 변경 요청 보호는 CSRF 토큰을 사용합니다.
- 브라우저가 보낸 `userId`는 소유권 판단에 사용하지 않습니다.
- Spring Security가 인증한 UUID만 `app.current_user_id`에 트랜잭션 로컬 값으로 설정합니다.
- PostgreSQL 정책은 앱 역할에도 `FORCE ROW LEVEL SECURITY`로 적용됩니다.
- AI 서버는 DB 자격 증명을 갖지 않고 내부 공유 비밀 헤더가 있어야 호출할 수 있습니다.
- 외부 입력의 프롬프트 명령은 데이터로 취급하며 AI 출력은 엄격한 JSON 계약으로 검증합니다.

## 핵심 데이터 흐름

### 자유 대화

사용자와 AI 메시지는 `conversations`, `conversation_messages`에 저장됩니다. 사용자 메시지는 먼저 저장되어 화면에 즉시 표시되고, `chat_reply_job_queue`의 워커가 답변을 생성합니다. 공고가 없어도 대화할 수 있으며 AI가 실패해도 사용자 메시지는 보존되고 해당 답변 작업을 재시도할 수 있습니다.

### 커리어 저장소

1. 사용자가 이력서·프로젝트 설명·경력 자료의 원문을 등록합니다.
2. `career_source_queue`에 파편화 작업을 넣고 즉시 응답합니다.
3. AI가 기술·프로젝트·경력·교육·자격·성과·링크 조각을 제안합니다.
4. 제안은 `SUGGESTED` 상태로 보관되며 사용자가 수정·선택한 조각만 `CONFIRMED`가 됩니다.
5. 확정된 조각만 이후 대화와 공고 분석의 사용자 근거로 전달됩니다.

조각은 검색·정렬·수정·병합·보관·복원·삭제할 수 있고, 원본 자료 분석 실패는 최대 횟수 안에서 재시도할 수 있습니다.

### 공고 분석

1. 공고 원문과 대화 연결을 저장합니다.
2. `analysis_job_queue`에 작업을 넣고 즉시 응답합니다.
3. 워커가 권한 제한 함수로 작업 하나를 점유합니다.
4. 해당 사용자의 RLS 문맥에서 그래프와 확정된 커리어 조각을 읽습니다.
5. AI가 먼저 결과를 크게 바꾸는 모호함이 있는지만 작은 구조화 응답으로 판단합니다.
6. 확인이 필요하면 질문 하나를 저장하고 큐에서 작업을 제거합니다. 사용자가 답하면 같은 작업을 다시 큐에 넣습니다.
7. 질문이 없거나 답변으로 해소되면 AI가 지원 판단과 간결한 그래프 변경안을 반환합니다.
8. 사용자가 변경안을 승인하거나 거절합니다.
9. 승인 시에만 서버가 그래프에 병합하고 버전을 증가시킵니다.

작업은 `QUEUED → RUNNING → WAITING_FOR_INPUT → QUEUED` 흐름을 최대 세 번 반복할 수 있고, 최종적으로 `SUCCEEDED | FAILED`가 됩니다. 질문은 한 번에 하나만 제공하며 답변 이력을 저장해 같은 질문을 반복하지 않습니다. 실패 작업은 최대 횟수 안에서 재시도할 수 있습니다.

### 증빙 검증

전문 노드는 프로젝트·코드·자격증·경험·문서 증빙을 받습니다. `evidence_verification_queue`에서 비동기로 처리하고, AI의 `VERIFIED` 신뢰도가 0.75 이상일 때만 노드를 완료합니다. 링크 내용은 실제로 읽었다고 가정하지 않고 사용자가 함께 제출한 설명만 평가합니다.

## 그래프 불변 조건

- 사용자마다 누적 그래프는 하나입니다.
- 노드 정체성은 이름만이 아니라 `canonicalKey + level + 정규화된 scopeDefinition`입니다.
- 재사용 노드는 기존 UUID를 정확히 지정해야 합니다.
- 노드 참조와 간선 종류는 허용 목록으로 검증합니다.
- 전체 그래프에 대해 순환을 거부하고 위상 정렬로 rank를 다시 계산합니다.
- 분석 중 그래프 버전이 바뀌면 오래된 변경안을 거부하고 재분석을 요구합니다.
- 공고 수정 후 새 기회 노드를 승인하면 같은 공고의 이전 기회 노드와 연결은 보관 처리합니다.
- 공고별 필수·우대 조건은 승인된 최신 변경안으로 교체합니다.

## 보안과 운영

- PostgreSQL 마이그레이션 역할과 앱 역할을 분리합니다.
- 로그인은 IP+이메일, 가입은 IP 기준으로 제한합니다.
- AI 사용량은 DB에 사용자별 시간 단위로 기록해 서버가 여러 대여도 동일하게 제한합니다.
- 대화 답변, 공고 분석, 커리어 파편화, 증빙 검증은 서로 구분된 사용량 한도를 가집니다.
- 운영 프로필은 강한 JWT/AI 비밀값, Secure 쿠키와 명시적 비로컬 CORS 도메인이 없으면 기동하지 않습니다.
- 각 HTTP 응답은 `X-Request-ID`를 반환하고 로그에도 같은 ID를 남깁니다.
- 헬스체크는 API 프로세스뿐 아니라 DB 연결도 확인합니다.
