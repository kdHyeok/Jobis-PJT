# 역량 검증을 학습형 통과 관문으로 운영

- 날짜: 2026-07-31
- 상태: 결정됨 · 핵심 구현 완료
- 범위: 역량 검증 문제, AI 채점, 학습 피드백, 로드맵 진행과 잠금

## 배경

현재 AI 역량 검증은 개념, 코드, 상황형 문제를 회사의 실제 업무 맥락에
대입해 출제한다. Java 검증에서 예외 선택, Spring 트랜잭션, 결제 멱등성과
같은 깊이 있는 문제가 나왔고, 사용자는 모르는 내용을 배우고 실제 회사에
대입해 생각하는 경험을 긍정적으로 평가했다.

반면 다음 단계로 가려면 이전 단계를 통과해야 하는 로드맵에서는 높은 난도가
사용자를 영구적으로 막을 수 있다는 우려가 생겼다. 또한 잘한 답변의 고급
키워드를 AI가 따라가며 현재 역량의 범위를 벗어나거나, 개념 문제에 실패해도
무조건 더 어려운 코드 문제로 진행하는 문제가 확인됐다.

## 결정

문제의 깊이와 회사 맞춤 상황은 유지한다. 대신 미통과를 종료가 아닌
학습-재도전 과정으로 만들고, 현재 역량의 핵심 검증과 인접한 현업 확장을
분리한다.

### 1. 문제 수준을 단순 퀴즈로 낮추지 않는다

검증은 암기 여부만 확인하지 않는다.

- 핵심 개념을 자신의 말로 설명하는가
- 짧은 코드의 동작과 문제를 판단하는가
- 선택의 근거와 트레이드오프를 설명하는가
- 회사와 직무의 상황에 적용할 수 있는가

회사 맞춤 상황은 JOBISS의 핵심 학습 경험으로 유지한다.

### 2. 핵심 검증과 현업 확장 문제를 분리한다

현재 노드의 `scopeDefinition`과 `requiredLevel` 안에 있는 문제만 해당 노드의
통과 점수에 반영한다. 인접 기술이나 더 높은 수준의 문제는 학습 가치가
있더라도 현업 확장 또는 보너스 문제로 분류한다.

예를 들어 Java 검증에서는 다음처럼 구분한다.

- Java 예외 체계와 예외 처리 코드: Java 핵심 검증
- Spring 트랜잭션 롤백: Spring 트랜잭션 현업 확장
- 결제 멱등성·락·유니크 제약: 백엔드 설계 또는 회사 맞춤 프로젝트 심화

사용자가 현업 확장 문제를 풀지 못해도 Java 핵심 검증을 통과했다면 Java
노드는 완료할 수 있다. 부족한 인접 기술은 별도 추천 노드나 보너스 퀘스트로
연결한다.

### 3. 미통과는 “아직 통과 전”으로 취급한다

최대 문제 수에 도달해도 사용자를 영구 탈락시키지 않는다. 세션 결과에는
다음을 제공한다.

- 확인된 강점
- 부족한 평가 기준
- 정답에 접근하는 사고 과정
- 복습할 개념과 키워드
- 짧은 학습 설명 또는 학습 자료
- 재도전해야 할 문제 유형

서비스의 메시지는 실패나 자격 없음이 아니라 “아직 준비되지 않은 부분과
다음 학습”을 안내하는 코치의 언어를 사용한다.

### 4. 통과한 평가 영역은 재도전에서 유지한다

개념, 코드, 상황 적용 중 이미 기준을 충족한 영역은 일정 기간 유효한
통과 기록으로 유지한다. 예를 들어 개념 90점, 코드 50점, 상황형 80점이면
새 세션에서 전체를 반복하지 않고 코드 영역만 새로운 변형 문제로 재검증한다.

재도전 횟수는 제한하지 않는다. 단순 정답 암기를 막기 위해 같은 평가 기준의
새로운 문제를 생성한다.

### 5. 난이도는 요구 수준으로 조정하고 합격 기준은 일관되게 유지한다

현재의 평균 75점 이상, 각 핵심 문제 60점 이상 기준은 문제 범위와 수준이
정확하게 보정된다는 전제에서 유지할 수 있다. 쉬운 합격 기준을 만드는 대신
수준 1과 수준 3에 맞는 문제 자체의 복잡도를 다르게 한다.

- 수준 1: 핵심 개념 설명과 안내된 단순 적용
- 수준 2: 일반적인 개발 문제에 독립적으로 적용
- 수준 3: 현재 기술 범위 안의 트레이드오프 판단과 장애 진단
- 수준 4: 복잡한 운영 환경의 설계와 개선
- 수준 5: 조직 수준의 기준 수립과 지도

강한 답변을 했다는 이유로 요구 수준을 넘어서는 인접 분야까지 자동으로
통과 조건에 포함하지 않는다. 심화 도전은 별도 보너스로 제공한다.

### 6. 다음 단계의 내용은 볼 수 있고, 공식 통과만 잠근다

사용자는 잠긴 다음 단계의 설명과 학습 내용을 미리 탐색할 수 있다. 학습
순서를 완전히 강제하지 않고, 공식 완료와 지원 준비도 반영만 선행 검증에
연결한다.

### 7. 잠금은 관련된 경로에만 적용한다

회사별 필수 기술은 해당 회사 지원 경로만 잠근다. 다른 회사나 분야의 경로는
계속 진행할 수 있다.

예를 들어 Kafka가 A사의 필수이고 Redis가 B사의 필수라면 Kafka 미통과는
A사 지원 노드만 막고 B사 Redis 경로는 막지 않는다. 우대 역량과 보너스
문제는 회사 지원 자체를 잠그지 않는다.

회사 맞춤 프로젝트는 여러 기술을 통합해 실제 결과물을 만드는 핵심 검증으로
유지한다. 기술별 짧은 문제만으로 프로젝트 수행 능력이나 실무 전체를
통과했다고 판단하지 않는다.

### 8. AI 채점은 이의 제기와 재검토가 가능해야 한다

AI의 단일 채점 결과가 사용자를 영구적으로 막지 않아야 한다. 평가 기준,
점수 근거, 부족한 항목을 사용자에게 보여주고 재채점 또는 검토 요청 경로를
제공한다. 질문에 필수 전제가 빠졌거나 정답이 여러 개인 경우에는 사용자에게
불리하게 판정하지 않는다.

## 현재 구현과의 차이

현재 구현은 핵심 통과 관문, 선택적 재도전, 확장 학습 분리와 재검토 절차를
충족한다.

- 회사 맞춤 개념·코드·상황형 문제와 3~5문항 평가가 구현되어 있다.
- 각 핵심 유형의 최고 점수 평균 75점, 유형별 최소 60점 기준이 구현되어 있다.
- 같은 역량·수준에서 최근 30일 안에 통과한 유형을 이월하고 부족한 유형만
  새로운 변형 문제로 재검증한다.
- 질문과 채점에 `coreCriteria`, `futureExtensions`를 별도 저장하고 미래 확장은
  통과 점수에 반영하지 않는다.
- 답변 채점과 다음 문제 생성을 독립 호출로 분리해 답변 속 인접 기술이 필수
  문제로 확장되는 것을 막는다.
- 미통과 사용자는 이의제기할 수 있고 운영자가 근거와 답변을 검토해 승인·
  반려한다.

## 수용 기준

- 핵심 문제는 현재 역량의 범위와 요구 수준을 벗어나지 않는다.
- 인접 기술의 심화 문제는 학습용으로 유지하되 현재 노드의 통과를 막지 않는다.
- 미통과 시 구체적인 부족 항목, 학습 안내, 재도전 경로가 제공된다.
- 통과한 개념·코드·상황 영역은 재도전에서 불필요하게 반복하지 않는다.
- 재도전은 새로운 변형 문제를 사용하며 횟수로 사용자를 차단하지 않는다.
- 필수 역량 미통과는 관련 회사 경로만 잠그고 다른 회사·분야 경로는 유지한다.
- 우대 역량과 보너스 문제는 지원 노드를 잠그지 않는다.
- AI 채점 결과의 근거를 확인하고 재검토를 요청할 수 있다.
