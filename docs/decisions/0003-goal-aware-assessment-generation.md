# 현재 목표와 최종 목표를 활용한 문제 생성

- 날짜: 2026-07-31
- 상태: 결정됨 · 부분 구현
- 범위: 사용자 목표, 지원 자격 판단, 역량별 요구 수준, AI 문제 생성
- 관련 결정:
  [역량 검증을 학습형 통과 관문으로 운영](./0002-competency-assessment-learning-gates.md)

## 배경

기술 이름과 공고 맥락만 AI에게 전달하면 문제의 범위가 지나치게 좁아져
뻔해지거나, 반대로 회사의 전체 기술 스택과 사용자의 고급 답변을 따라가며
현재 기술의 범위를 벗어날 수 있다.

실제 Java 검증에서는 Java 예외 문제에서 시작해 Spring 트랜잭션과 결제
멱등성 문제까지 확장됐다. 문제 자체의 학습 가치는 높았지만, 이 내용을
Java 노드의 필수 통과 조건으로 사용하는 것은 적절하지 않았다.

사용자의 현실적인 지원 목표와 장기적인 도달 목표를 구분하면 공정한 통과
문제와 흥미로운 확장 문제에 서로 다른 기준을 적용할 수 있다.

## 목표의 정의

### 현재 목표

현재 목표는 경력, 필수 자격증, 필수 학위 등 명시적인 지원 자격을 현재
충족하고 있어 현실적으로 지원할 수 있는 공고다.

기술 역량이나 프로젝트가 부족하다는 이유만으로 현재 목표에서 제외하지
않는다. 이런 부족은 로드맵 학습과 회사 맞춤 프로젝트로 보완할 대상이다.

현재 목표는 “지금 합격할 수 있음”이 아니라 다음 의미다.

> 형식적으로 지원할 수 있으며, 역량을 보강하면 현실적으로 도전할 수 있는
> 공고

### 최종 목표

최종 목표는 현재 경력이나 자격이 부족하더라도 사용자가 장기적으로
도달하려는 회사, 공고, 직무 또는 역할이다. 실제 공고를 선택하거나 자유롭게
작성할 수 있다.

너무 추상적인 목표는 AI가 직무, 수준, 도메인을 질문해 구체화하되 사용자의
방향을 임의로 변경하지 않는다.

### 확인된 사용자 경험

문제 생성에는 사용자가 커리어 저장소에서 확인한 경력, 자격, 프로젝트와
검증된 역량 수준만 사용한다. 정보가 없다는 이유로 경험이 없다고 단정하지
않는다.

## 결정

### 1. 현재 목표는 핵심 통과 문제의 기준이다

현재 목표 공고에서 해당 역량에 명시적으로 요구하는 범위와 수준을 현재
노드의 통과 문제에 사용한다.

예를 들어 현재 목표가 이스트게임즈 신입 백엔드이고 공고가 Java/Kotlin을
사용한 백엔드 개발 경험만 요구하며 설계·장애 대응을 명시하지 않는다면,
Java 핵심 문제는 Java 언어와 표준 라이브러리 안에서 출제한다.

- 객체 동등성
- 예외 처리
- 컬렉션
- 제네릭
- Java 동시성
- 회사 도메인을 소재로 한 Java 코드 판단

Spring 트랜잭션과 분산 결제 설계를 못 풀었다는 이유로 현재 Java 노드의
통과를 막지 않는다.

### 2. 최종 목표는 미래 확장 문제의 기준이다

최종 목표에서 요구하는 더 높은 수준과 인접 기술은 `FUTURE_EXTENSION`
문제로 사용한다.

예를 들어 최종 목표가 네이버웹툰 경력 백엔드라면 Java 핵심 검증 이후
Spring 트랜잭션, 멱등성, 동시성, 대용량 트래픽과 같은 내용을 미래 확장
문제로 제안할 수 있다.

확장 문제는 다음 원칙을 따른다.

- 현재 노드의 통과 점수에는 반영하지 않는다.
- 사용자가 왜 이 문제를 배우는지 최종 목표와 연결해 설명한다.
- 통과하거나 관심을 보이면 별도 기술 노드, 보너스 퀘스트 또는 다음 학습
  추천으로 연결한다.
- 문제를 풀지 못해도 현재 목표 경로를 막지 않는다.

### 3. 같은 역량을 수준별로 누적 검증한다

한 번 통과한 기술을 완전히 끝난 것으로 취급하지 않는다. 사용자별
`verifiedLevel`을 유지하고 목표가 높아질 때 부족한 상위 수준만 추가로
검증한다.

예:

```text
Java 수준 2
이스트게임즈 현재 목표에 필요한 수준
→ 통과

Java 수준 3
네이버웹툰 최종 목표에 필요한 수준
→ 미래 학습 및 추가 검증
```

수준 3에 도전할 때 수준 1과 2의 전체 문제를 처음부터 반복하지 않는다.

### 4. 현재 목표와 최종 목표를 프롬프트에서 명시적으로 분리한다

두 목표를 설명문 하나로 합쳐 전달하지 않는다. 문제 생성 계약에서 목적을
구조화한다.

예시:

```json
{
  "competency": {
    "canonicalKey": "lang.java",
    "title": "Java",
    "verifiedLevel": 0
  },
  "currentTarget": {
    "company": "이스트게임즈",
    "requiredLevel": 2,
    "purpose": "CORE_GATE"
  },
  "finalTarget": {
    "company": "NAVER WEBTOON",
    "requiredLevel": 3,
    "purpose": "FUTURE_EXTENSION"
  }
}
```

`CORE_GATE` 문제만 현재 노드의 통과 점수에 반영한다.
`FUTURE_EXTENSION`은 별도 문제와 학습 추천에 사용한다.

### 5. 회사 맥락과 평가 기준의 책임을 분리한다

현재 목표의 회사·도메인은 문제의 현실적인 소재와 상황을 제공한다. 어떤
지식을 알아야 통과하는지는 현재 역량의 범위와 요구 수준이 결정한다.

최종 목표의 회사·도메인은 미래 확장 문제의 소재와 다음 학습 방향에만
사용한다.

핵심 문제인지 판단할 때 다음 질문을 사용한다.

> 현재 역량을 요구 수준까지 충분히 공부했지만 인접 기술을 모르는 사용자가
> 이 문제를 풀 수 있는가?

풀 수 없다면 현재 노드의 핵심 통과 문제가 아니라 복합 또는 확장 문제다.

### 6. 확인된 경험은 질문 방식과 기대 깊이를 조정한다

경력이 없는 사용자에게 운영 장애를 직접 해결한 경험이 있다고 가정해
답하도록 요구하지 않는다. 가상의 상황을 주고 판단하게 할 수는 있지만,
실제 경험을 전제로 채점하지 않는다.

검증된 실무 경력이 있다면 같은 기술 범위 안에서 장애 진단, 트레이드오프,
운영 환경의 선택과 같이 더 깊은 설명을 기대할 수 있다.

정보가 없는 상태는 미충족으로 보지 않는다. 문제 수준에 영향을 주는 경력과
자격 정보가 없으면 확인 질문을 하거나 기본 수준으로 출제한다.

### 7. 여러 현재 목표는 평가 대상을 명확히 선택한다

여러 현재 목표가 같은 기술에 서로 다른 수준을 요구할 때 모든 요구 수준을
무조건 합쳐 가장 어려운 문제를 만들지 않는다.

- 사용자가 선택한 현재 목표를 기준으로 검증하거나
- 로드맵에서 현재 진행 중인 대표 목표를 기준으로 검증한다.

높은 수준을 통과하면 낮은 수준의 현재 목표에도 재사용할 수 있다. 낮은
수준만 통과한 사용자는 더 높은 목표를 선택할 때 차이만 추가 검증한다.

## 문제 생성 흐름

권장 흐름은 다음과 같다.

1. 지원 자격과 목표의 용도를 구조화한다.
2. 현재 목표에서 이번 핵심 평가 목표와 요구 수준을 선택한다.
3. 확인된 사용자 경험으로 질문 방식과 전제조건을 조정한다.
4. 회사 맥락으로 문제의 상황을 개인화한다.
5. 생성된 문제가 현재 역량만으로 풀 수 있는지 검수한다.
6. 핵심 검증이 끝나면 최종 목표에 연결된 확장 문제를 별도로 제안한다.

채점과 다음 문제 생성은 분리한다. 채점기는 사용자 답변 전체를 볼 수 있지만,
다음 핵심 문제 출제기에는 현재 역량에서 확인한 평가 기준과 부족한 기준만
전달한다. 사용자가 자발적으로 언급한 인접 기술 키워드는 확장 문제 후보로
보관하고 핵심 통과 조건에 자동으로 포함하지 않는다.

## 현재 구현과의 차이

현재 목표와 최종 목표의 저장·전달 및 핵심 범위 제한은 구현됐고, 미래 확장
문제의 완전한 분리는 남아 있다.

- 사용자는 분석 완료 공고 하나를 현재 목표로 선택하고 최종 목표를 자유
  텍스트로 별도 저장할 수 있다.
- 두 목표는 `target.currentGoal`, `target.finalGoal`의 서로 다른 필드로 AI에
  전달된다.
- 프롬프트는 현재 목표만 핵심 통과 범위에 사용하고 최종 목표가 통과 조건을
  넓히지 못하도록 제한한다.
- 역량별 `verifiedLevel`은 유지되지만 상위 수준 차이만 자동으로 산출하는 평가
  청사진은 아직 없다.
- 미래 확장 문제는 핵심 문제와 별도 용도·점수로 DB에 저장되지 않는다.
- 채점과 다음 문제 생성을 독립 AI 호출로 처리하며 핵심 기준과 미래 확장
  제안을 각각 저장한다.

## 수용 기준

- 현재 목표의 명시적인 요구 범위와 수준만 핵심 통과 문제에 반영된다.
- 최종 목표의 심화 내용은 별도 확장 문제로 제공되고 현재 통과를 막지 않는다.
- 현재 목표와 최종 목표가 구조화된 서로 다른 필드로 AI에 전달된다.
- 같은 역량의 낮은 수준을 통과한 사용자는 상위 수준 차이만 추가 검증한다.
- 회사 맥락은 현실적인 문제 표현에 사용되지만 숨겨진 인접 기술을 통과
  조건으로 만들지 않는다.
- 사용자의 검증되지 않은 경력이나 경험을 문제와 채점의 전제로 사용하지 않는다.
- 여러 현재 목표가 있을 때 검증 대상 목표를 사용자 또는 시스템이 명확히
  선택한다.
- 핵심 문제와 미래 확장 문제는 DB에서도 서로 다른 용도와 점수 반영 여부로
  저장된다.
