# 실제 작업 기반 AI 단계와 공통 분석 재사용

- 날짜: 2026-08-01
- 상태: 결정됨 · 구현 완료
- 범위: 공고 분석 AI 서버, 진행 시각화, 공통 분석 캐시

## 결정

AI 진행 시각화는 역할 이름을 붙인 고정 타이머가 아니라 실제 실행 경계를
표시한다. 최초 분석은 맥락 조립, 공고 구조화, 계약 검증, 결과 조립을 수행한다.
추가 질문이 필요할 때만 질문 단계를 넣는다. 동일한 원문과 동일한 추가 답변이
이미 분석됐다면 공통 구조를 재사용하고 사용자별 적합도만 새로 계산한다.

공통 캐시에 넣을 수 있는 값은 회사·직무·경력·마감·표준 역량·필수/우대 조건·
회사 맞춤 프로젝트 정의뿐이다. 사용자의 이력, 검증 상태, 준비도, 대체 공고와
대화는 공용 캐시에 넣지 않는다.

AI는 구조를 읽고 표현하지만 다음 값은 백엔드가 결정적으로 검증한다.

- 필수 역량 충족률과 최종 지원 판정
- 역량 정체성, 범위와 참조 무결성
- 로드맵 노드·간선·경력 관문과 좌표
- 실제 카탈로그 기반 대체 공고 순위
- 역량 검증의 유형별 최소 점수와 평균 점수

## 진행 단계

```text
CONTEXT_ASSEMBLY
  ├─ CLARIFICATION (필요할 때만)
  ├─ POSTING_ANALYSIS (최초 분석)
  └─ SHARED_REUSE → FIT_ANALYSIS (공통 분석 재사용)
       ↓
CONTRACT_VALIDATION → RESULT_ASSEMBLY
```

단계는 실제 비동기 호출과 검증 전후에 이벤트로 기록한다. 아주 빠른 단계도
이벤트 이력에는 남기되 화면 표시를 위해 서버가 인위적으로 지연하지 않는다.

## 수용 기준

- 동일 공고 재분석은 공통 구조를 다시 생성하지 않는다.
- 다른 사용자에게 이전 사용자의 커리어 근거와 평가가 노출되지 않는다.
- 화면의 단계 수와 색은 실행별 `RUN_STARTED.stages`를 따른다.
- 공급자 실패와 구조 검증 실패는 어느 단계에서 실패했는지 기록한다.
- AI가 실패해도 사용자 공고 원문과 작업은 보존되고 재시도할 수 있다.
