# JOBIS 결정 기록

이 디렉터리는 대화에서 합의한 제품·기술 결정을 보관합니다. 각 문서의
`상태`를 확인해야 하며, `결정됨 · 구현 전`은 방향이 확정됐지만 현재 코드에
반영되지는 않았다는 뜻입니다.

## 결정 목록

1. [공고 중복 판별과 운영자 최종 승인](./0001-공고-중복판별과-운영자-승인.md)
   - 동일 공고의 정확 중복은 규칙으로 처리합니다.
   - 애매한 유사 공고는 AI가 판정안을 만들고 운영자가 최종 결정합니다.
   - 이 과정은 사용자 분석을 기다리게 하지 않습니다.

2. [역량 검증을 학습형 통과 관문으로 운영](./0002-역량검증-학습형-통과관문.md)
   - 높은 문제 수준과 회사 맞춤 상황은 유지합니다.
   - 핵심 검증과 현업 확장 문제를 분리합니다.
   - 미통과는 막다른 실패가 아니라 학습과 재도전의 시작입니다.
   - 잠금은 전체 로드맵이 아니라 관련된 회사 경로에만 적용합니다.

3. [현재 목표와 최종 목표를 활용한 문제 생성](./0003-목표-기반-문제-생성.md)
   - 현재 목표는 노드 통과 문제의 범위와 수준을 결정합니다.
   - 최종 목표는 미래 확장 문제와 다음 학습 방향을 결정합니다.
   - 사용자의 확인된 경험은 질문 방식과 기대 깊이를 조정합니다.
   - 두 목표를 하나의 통과 기준으로 섞지 않습니다.

4. [실제 작업 기반 AI 단계와 공통 분석 재사용](./0004-AI-단계와-공통분석-재사용.md)
   - 진행 단계는 실제 AI 호출과 결정론 검증 경계를 표시합니다.
   - 같은 공고의 사용자 무관 구조는 재사용하고 적합도는 매번 다시 계산합니다.
   - 사용자 정보와 준비도는 공용 분석 캐시에 저장하지 않습니다.

5. [Spring JDBC와 PostgreSQL SQL 안전 규칙](./0005-Spring-JDBC-PostgreSQL-안전규칙.md)
   - 이름 있는 파라미터와 PostgreSQL JSONB `?` 연산자를 혼용하지 않습니다.
   - nullable 파라미터를 SQL의 `is null` 조건으로 직접 판별하지 않습니다.
   - 금지 패턴은 자동 테스트로 재도입을 차단합니다.
