# 10. Agent Eval (다중실행 일관성 · 궤적 검증)

- **선행:** 07(agent) · 08(테스트 인프라)
- **참조:** design.md §8 "다음 주차 Agent Eval(final/step/trajectory)" · D12
- **상태:** ✅ 완료 (2026-07-27)

## 목표
**여러 상황 × 다중 실행**으로 agent를 돌려, 라우팅·분기·판단(계획)이 **일관되게** 올바른지 **궤적(trajectory)+통계**로 검증. (task 08 = "되나?" 단발 / task 10 = "**얼마나 일관되게** 잘 하나?" 반복)

> ⚠️ 이건 **구조·일관성 평가**야. 추천 적합도·매칭 정확도 같은 **품질 평가는 범위 밖**(LLM-judge/정답셋 필요 → 더 나중).

## 무엇을 재나 (design §8의 step/trajectory)
- **trajectory**: 입력별 **기대 tool 순서/패턴**을 실제 `meta.tools_called`가 따르나 (예: S3 = `load_posting → analyze_gap → (중/하면 search)`)
- **불변식**: `search 발동 ⟺ level 중/하` 가 다중 실행에서 유지되나
- **일관성**: 케이스당 N회 중 **몇 회** 기대 충족 (비결정성 정량화)

## ⟨확인 필요⟩ 결정
**1. 평가 케이스 셋** — 표준 6 + 엣지 몇 개. 제안:
| 케이스 | 입력 | profile | 기대 궤적 |
|---|---|---|---|
| S1 추천 | "내 이력서로 공고 추천" | O | `search_postings`, analyze_gap 없음 |
| S2 공고정리 | "이 공고 내용 알려줘 {url}" | X | `load_posting`, analyze_gap 없음 |
| S3 갭분석 | "이 공고 붙을까? {url}" | O | `load_posting→analyze_gap`, 불변식 |
| S4 직군검색 | "데이터 엔지니어 공고" | O | `search_postings` |
| S5 일상 | "취준 힘들어" | O | 툴 없음 |
| S6 무관 | "날씨 어때?" | O | 툴 없음 |
| E1 없는 URL | 존재X url | O | `load_posting`(NOT_FOUND), 크래시X |
| E2 이미지 공고 | need_ocr=O url | O | `load_posting→analyze_gap`(INSUFFICIENT), 크래시X |
| E3 애매 | "이 회사 괜찮아?"(url 없음) | O | ⟨관찰 대상 — 정답 미정, 어떻게 반응하나 로그로 관찰⟩ |

**2. 실행 횟수 N** — 케이스당 몇 회? **크레딧↔통계 신뢰도** 트레이드오프. 제안: **N=3**(작게 시작, `--runs`로 조정).
**3. 판정 방식** — **하드 pass/fail 아님, 일관성 비율 리포트**. 제안: 불변식은 **100% 기대**, tool-패턴은 **비율 표시**(예: "S3 analyze_gap 3/3"). 임계 미달만 ❌.
**4. 궤적 수준** — tool **집합**만 vs **순서**까지. 제안: **순서 포함**(load→analyze→search)이 진짜 계획 검증.
