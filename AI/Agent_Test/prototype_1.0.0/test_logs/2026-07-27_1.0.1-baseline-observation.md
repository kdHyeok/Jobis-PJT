## 발견된 약점 (강건화 타깃, 우선순위)

- **W1 (최우선)** — `analyze_gap`가 "학력무관/경력무관"을 **필수 요건으로 오추출**해 트리비얼 충족→**거짓 상**. 오세훈: 충족(필수)=`[학력무관, 경력무관]`뿐→1.00→상. 박지호: `[학력무관]`뿐→상.
- **W2** — 진짜 도메인 스킬이 대거 **`판정불가(uncertain)`로 빠져 점수에서 제외**(분모 제외 설계). 정민준: Linux·자료구조·알고리즘·운영체제·네트워크 전부 판정불가. → 점수가 트리비얼 소수 항목 위에서 계산. W1과 한 뿌리(추출·분류 단계).
- **W3** — 판정 불안정: 같은 (프로필,공고)인데 agent 실행(상) vs 직접 실행(중) 갈림(김도윤). LLM 폴백 비결정성 → **"결정론 우선" 하이브리드의 결정론이 허상**.
- **W4** — mock 검색 품질: ① 중복 결과(한유진), ② 키워드 떡칠 SI/SM 공고가 무관 프로필 공통 상위(아이비티에스·앱메이드 → 오세훈·이서현 양쪽), ③ 필드 적합성 약함(안드로이드 검색에 Java SI 공고).

## 덤 — rationale가 근거가 아님

캡처된 `rationale`가 전부 `"[중] 필수 N건 충족 / 우대 M건 충족 / 판정불가 K건"` 템플릿. **LLM의 진짜 "왜"가 아니라 코드가 개수로 찍은 문자열.** 진짜 근거는 matched/missing/uncertain 리스트에 있음. → 관측성 개선의 근거 데이터.

## 결론·다음

- W1+W2(요건 추출·분류)가 압도적 최우선 — 거짓 상을 직접 만들어 성공기준3 무력화. → **D16: analyze_gap을 LLM-as-judge로 전환**(structured output + 루브릭 + 0~100 점수→임계값 매핑).
- 리팩터 후 **본 스크립트 재실행**해 W1~W4 개선을 같은 잣대로 확인(A/B).
