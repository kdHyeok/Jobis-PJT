# 중간발표 — AI 에이전트 파트 · 기능/차별점 (슬라이드 2장)

> 팀 공유용. `0723.md`(구조·"챗봇이 아닌 에이전트")와 짝을 이루는 **기능·차별점** 편.
> 슬라이드 1 = **무엇을 해주는가(기능)**, 슬라이드 2 = **왜 우리여야 하는가(차별점)**.

---

## 슬라이드 1 — 무엇을 해주는가 (기능)

**제목**: 이력서 × 실제 공고 → 합격까지의 경로를 설계해준다
**부제**: 진단만 하는 게 아니라, 적합도에 따라 다른 길을 열어준다

### ① 맞춤 적합도 분석
사용자 **이력서**와 **실제 채용 공고**를 대조해 "지금 이 공고에 얼마나 맞는가"를 진단한다.

> 판단 알고리즘은 **파이썬 가중치 기반 벡터 매칭 + LLM** 혼용 —
> 점수·등급은 결정론적으로 계산하고, 비정형 문서 해석에만 LLM을 쓴다.

### ② 적합도 등급별 분기 — 등급마다 다른 처방

| 등급 | 사용자에게 주는 것 | 구현 방식 |
|---|---|---|
| **상** | 바로 지원 가능 → 강점 요약 중심 | RULE |
| **중** | **경로 로드맵** + 추천 공고 | RULE + LLM / **RAG**(공고) |
| **하** | **대체·우회 경로** + 추천 공고 | RULE + LLM / **RAG**(공고) |

- **로드맵(중)**: 부족한 요건을 채우는 단계별 계획을 제시한다.
- **대체 경로(하)**: 지금 공고가 무리면 도달 가능한 **우회 루트**를 찾아 제안한다.
- **공고 제공(중·하)**: 실제 존재하는 공고를 **RAG**로 추천한다 (지어내지 않는다).

### ③ 포트폴리오 양식·틀 제공
사용자에게 필요한 **포트폴리오 양식/틀**을 제공한다.
→ 도메인별로 다르게 주며, IT 도메인은 **알고리즘 스켈레톤 코드**를 제공한다.

## 슬라이드 2 — 왜 우리여야 하는가 (차별점)

**제목**: 취업 플랫폼도, 범용 챗봇도 못 하는 지점
**부제**: 경로를 설계하고, 데이터로 일관성을 보장한다

### ① vs 취업 플랫폼 — "공고만 보여주는 곳"과 다르다

| 플랫폼 | 우리 |
|---|---|
| 공고 나열·검색 | **대체·우회 경로 탐색**해서 도달 가능한 길을 제시 |
| 서류 양식 안내 정도 | **도메인별 포트폴리오 양식·틀 제공** |
| — | 그중 IT는 **알고리즘 스켈레톤 코드**까지 |

### ② vs 챗봇 / 범용 LLM — "매번 다르게 답하는 것"과 다르다

| 범용 챗봇 | 우리 |
|---|---|
| 모델 안의 지식으로만 답 | **실 공고 데이터 + 과거 합격자 데이터** 참조 |
| LLM 단독 판단 | **알고리즘 + LLM 혼용**으로 분석·판단 |
| 물을 때마다 답이 흔들림 | 데이터 기반 답변 → **일관성 확보** |

> **핵심 한 줄**: 사용자 입력을 **트래킹**하고, **실제 공고·과거 합격자 데이터**에 근거해
> 답하기 때문에 — 타 챗봇·범용 LLM 대비 **같은 질문에 같은 답이 재현된다.**

---

## 한 장 요약 (표지/마무리용)

- **기능**: ① 이력서×공고 맞춤 적합도 분석 → ② 등급별 분기(상=지원 / 중=로드맵 / 하=대체경로) + 공고 추천 → ③ 도메인별 포트폴리오 양식·틀(IT는 스켈레톤 코드)
- **차별점**: 플랫폼과 달리 **경로를 설계**하고, 챗봇과 달리 **데이터로 일관성**을 보장한다
