# 발표 내용 소스 — AI 에이전트 파트

> 발표에서 **입으로 말할 내용**. `>` 인용문은 그대로 읽어도 되는 대사고, 표는 슬라이드 재료다.
> `▸`는 질문 들어올 때만 꺼내는 카드, ★는 반응이 제일 좋을 자리.
> 근거: `에이전트-보고서.md` · `전체구조-에이전트-연결도.md` · `에이전트-툴-목록.md` · 코드.

**시간 배분 기준 (10분)**: 개요 1분 → 구조 2분 → 구현 2분 → **트러블슈팅 2.5분** → 핵심기술 1.5분 → 계약 1분
(15분이면 §2 한 턴 흐름과 §6 계약을 늘린다. 5분이면 §0 + §4-1 + §5-2 + §7만.)

## 0. 오프닝 30초

> "채용 공고와 이력서를 받아 **적합도를 판정하고, 부족한 걸 준비 로드맵으로 만들어 주는 AI**입니다.
> 하나의 큰 AI가 아니라 **에이전트 7명 + 도구 4개**가 나눠 일합니다.
> 원칙은 한 줄입니다 — **판단은 데이터가 하고, LLM은 말을 합니다.**
> 정형 비교가 되는 것은 알고리즘이, 문장을 읽어야 하는 것은 LLM이 맡습니다."

외울 숫자 3개:
- 라우팅 정확도 **1.0** · 재현성 **1.0** (52상황 × 3회) — 시작은 0.85
- 턴당 **48초 → 13~38초**
- 회귀 테스트 **798건 / 4.15초 / LLM 호출 0 / 비용 0**

## 1. 개요 — 무엇을, 왜 이렇게 쪼갰나

### 1-1. 왜 하나의 에이전트로 안 했나

> "처음엔 팀 시제품이 **단일 ReAct 루프** 하나였습니다. 같은 데이터로 재 봤더니
> **6프로필 중 5건이 기대와 어긋났습니다.**
> 그런데 진짜 문제는 정확도가 아니었습니다 — **어디서 틀렸는지 모른다**는 것이었습니다.
> 공고를 잘못 읽은 건지, 대조를 잘못한 건지, 말만 그렇게 한 건지 구분이 안 됐습니다."

멀티에이전트여서 가능해진 것 (발표에선 굵은 3개만):

| | 가능해진 것 | 단일 루프에서는 | 근거 |
|:--:|---|---|---|
| 1 | **어디서 틀렸는지 지목할 수 있다** | 실패가 전부 "답이 이상하다" 한 줄로 뭉개진다 | 개선 대장 31건이 **층을 지목**해서 고쳐졌다 |
| 2 | **층마다 따로 잴 수 있다** | "프롬프트 고쳤더니 느낌이 나아졌다"가 한계 | 평가 하네스 **4종** (계획/풀턴/자기루프/내용) |
| 3 | 판정이 재현된다 | 판정 재료가 한 콜 결과에 실려 있으면 정규화·연차·게이트가 놓일 자리가 없다 | 6프로필 중 5건 어긋남 |
| 4 | **무거운 일 앞에서 멈춰 물을 수 있다** | 멈출 경계 자체가 없다 | 동의 게이트, 정확도 1.0 |
| 5 | 독립 작업을 동시에 돌린다 | for 루프 순차 | 47.8초 → 13.3~37.6초 |
| 6 | 도구를 담당별로 다르게 준다 | 모든 도구가 한 컨텍스트에 | 제출·결제 도구는 **만들지 않았다** |
| 7 | 순서를 사람이 적지 않는다 | 대응표가 상황마다 커진다 | 전제·산출 선언에서 순서가 계산돼 나온다 |

> "**2번이 나머지를 떠받칩니다.** 오늘 제가 대는 모든 수치 — 정확도 0.85 → 1.0, 위반 5 → 0, 26.2초 절감 —
> 은 전부 **잴 수 있는 경계가 있었기 때문에** 나온 값입니다."

### 1-2. 에이전트 7 + 도구 4 — 가르는 기준은 하나

> "구분 기준은 딱 하나입니다 — **말을 하는가.**
> 에이전트는 LLM으로 사용자향 문장을 만들고, 도구는 값만 냅니다. 문장은 표현 계층이 따로 만듭니다."

**에이전트 7 (말하는 것)**

| 이름 | 하는 일 | 전제 | 루프 |
|---|---|---|---|
| 공고 담당 | 공고 원문 근거로 요건 정리·풀이·학습 방향. **적합도 판정은 안 함** | 공고 | 툴 3 · 5스텝 |
| 이력서 담당 | 항목 정리·강점·빈 섹션 보강 방향. 공고 없을 때 먼저 할 수 있는 일 | 이력서 | 툴 1 · 5스텝 |
| 선호 파악 | 추천용 선호(직군·도메인·지역·기술·경력) 수집 | — | 툴 3 · 5스텝 |
| 면접 준비 | 한 번에 한 질문 → 답변 점검 → 꼬리 질문. 여러 턴 이어짐 | 분석 | 툴 4 · 5스텝 |
| 자소서 초안 | 초안 작성 → 스스로 점검 → 수정. 초안 있으면 지목 문단만 | 이력서+분석 | 툴 4 · **7스텝** |
| 지원 경로 설계 | 목표 상태 + 지원 경로 2~3개. **판정은 룰, 문구만 LLM** | 분석 | 없음 |
| 진로 대화 | 기능 요청이 아닌 발화 · 자료 청구 · 플래너 폴백 | — | 없음 |

**도구 4 (계산하는 것)**

| 이름 | 하는 일 | 특성 |
|---|---|---|
| 적합도 분석 | 판정 엔진(LangGraph) 전체를 부르는 진입 래퍼. **판정 로직은 여기 한 줄도 없다** | **heavy** — 자동 삽입 시 먼저 묻는다 |
| 공고 추천 | RAG 의미 검색 + 후보별 재매칭. 실공고가 없으면 **지어내지 않고 빈 결과** | 전제가 "이력서 **또는** 선호" |
| 공고 수집 | URL·캡쳐 → 원문 승격 | **internal** — 플래너에 안 보인다 |
| 로드맵 조회 | 저장된 로드맵 | — |

> "자소서만 7스텝인 이유가 있습니다 — **쓰고, 스스로 점검하고, 다시 씁니다.**
> 5스텝이면 재작성 궤적이 잘립니다. **상한이 곧 '몇 번 고쳐 쓸 수 있나'**입니다."
>
> "공고 수집이 플래너에 안 보이는 이유도 같은 맥락입니다 —
> URL이 미수집이면 **반드시** 수집해야 합니다. **필연적 단계를 LLM이 고를 판단으로 만들지 않습니다.**"

▸ **툴 수는 일의 양이 아니다.** 이력서 담당이 툴 1개인 건 할 일이 적어서가 아니라
**근거가 진입 파이프라인에서 이미 다 만들어져 있어서**다 — 추출·증거매핑·항목화가 루프 전에 끝난다.
루프가 원문을 다시 볼 일은 "정리된 항목에 없는 서술"뿐. — ***자율성은 표현에, 근거는 도구에.***

### 1-3. 툴 콜링이 두 층이다 ★ (구조의 핵심)

> "**팀장이 누구를 부를지 고르고, 팀원이 무엇을 쓸지 고릅니다.**
> 위층은 플래너 LLM이 에이전트를 고르고, 아래층은 각 에이전트가 매 스텝 자기 툴을 고릅니다.
> **순서를 적어 둔 코드가 없습니다** — 같은 요청에도 궤적이 갈리고, 전부 정당한 갈림입니다."

각 루프의 성격 한 줄 (질문 들어오면):

```
공고 담당    원문 읽기 → 제안 기록(근거 ID 검증) → 시장 검색
이력서 담당  원문 읽기
선호 파악    선호 기록(+충분성 판정) → 공고 미리보기 → 자료 요청
면접 준비    소재 고르기 → 근거 확인 → 답변 채점 → 질문 기록
자소서       근거 수집 → 초안 저장 → 자기 점검 → 다시 쓰기   ← 7스텝인 이유
```

## 2. 한 턴에 무슨 일이 일어나나 (화이트보드에 그릴 그림)

```
발화 + 첨부
 ① 인테이크    [코드] 첨부 종류를 내용으로 바로잡는다(공고라고 준 게 이력서면 이력서로)
               발화 속 URL을 공고 자산으로 승격
 ② 플래너      [LLM] 이 턴의 유일한 "무엇을 할까" 판단
               manifest에서 이름·인자를 고른다. 확신 < 0.6이면 실행 대신 확인 버튼
 ③ 검증기      [코드] 전제 없는 항목 제거 or 그 자산의 생산자를 앞에 끼운다
 ④ 게이트      [코드] 이력서 확인(공고당 1회) · 동의 게이트(heavy는 먼저 묻는다)
 ⑤ 실행        [LLM] 최대 5스텝, 독립인 것은 최대 3개 병렬
 ⑥ 관찰→재선택 [코드] 판정이 실패했으면 그 산출물에 기대던 뒤 단계를 뺀다
 ⑦ 조립        문장별 화자 + 되묻기 카드 + 경고를 붙여 응답
```

말할 때 짚을 4가지:

1. **환각 차단은 프롬프트가 아니라 스키마입니다.** 플래너가 낼 수 있는 값은 레지스트리에 등록된 이름뿐입니다
   (`Literal` 강제). *"없는 에이전트를 부르지 마라"고 부탁하지 않습니다.*
2. **확신이 낮으면 버리되 잃지 않습니다.** 0.6 미만이면 실행하지 않고 **확인 버튼으로 남깁니다.**
3. **검증기가 순서를 계산해 냅니다.** 자소서를 청했는데 분석이 없으면 적합도 분석을 앞에 끼웁니다.
   순서를 대응표로 적지 않았습니다 — **전제·산출 선언에서 계산돼 나옵니다.**
4. **관찰 층에 LLM이 없습니다.** 등급이 낮으면 자소서·면접을 빼고 지원 경로를 넣습니다.
   *(여기 원래 LLM이 있었다는 얘기는 §4-1에서)*

▸ **오케스트레이터도 자기 툴을 쥐고 돕니다** — 플래너가 못 부르는 것 9개:
공고 수집 삽입 · **정리 단계 삽입**(자료가 방금 제출된 턴엔 판정 앞에 공고/이력서 정리를 끼운다 —
사용자는 판정만이 아니라 *무엇을 읽고 판정했는지*를 본다) · 첨부 재분류 · 전제 생산자 삽입 ·
동의 게이트 · 재계획 · 미완수 요청 재큐 · 이력서 확인 · 병렬 배치.
차이는 **누가 고르느냐**뿐입니다 — 에이전트 툴은 **LLM이**, 이것들은 **자산 상태가** 고릅니다.

## 3. 구현 내용

### 3-1. 프레임워크 — 층마다 다르게 골랐다

> "'LangChain 썼나요'는 예/아니오로 답할 수 없습니다. **둘 다 쓰고 있고, 쓰는 깊이가 층마다 다릅니다.**"

| 층 | 무엇 | 왜 |
|---|---|---|
| **판정 파이프라인** | **LangGraph** (`graph/builder.py` 1줄) | 경로가 고정이어야 하는 자리. 실제로 값을 하는 건 셋 — **팬아웃 병렬**(공고 파싱 ∥ 프로필 빌드) · **`defer=True` 합류**(먼저 끝난 분기의 조기 실행 차단) · **조건부 재시도 루프** |
| **LLM 호출** | langchain-core 계열 (import 4줄) | `with_structured_output`으로 Pydantic 스키마 강제 · 프로바이더 교체 |
| **에이전트 루프** | **자체 런타임 422줄** | 프레임워크가 표현 못 하는 규율 셋 (아래) |

`langchain` 본체는 **의존성에 없습니다.**
`AgentExecutor`·`create_react_agent`·`LLMChain`·`ChatPromptTemplate`·`RetrievalQA` — 저장소 전체 grep **0건.**
임베딩은 아예 SDK를 직접 호출해 LangChain을 안 거칩니다.

**왜 판정만 LangGraph인가:** 재현성(같은 이력서×공고에 같은 등급) · 측정 가능성(경로가 고정이어야 A/B가 성립) ·
디버깅(어느 분기로 갔고 재시도가 걸렸는지가 그래프에 적혀 있다).

**왜 에이전트 층만 자체 런타임인가 — 규율 셋:**

| 규율 | 무엇을 요구하나 | 프레임워크 루프에서 왜 어려운가 |
|---|---|---|
| **동의 게이트** | heavy가 **자동 삽입**됐을 때만 실행 없이 한 턴 묻고 종료. 명시 선택이면 그냥 실행 | 루프에 **"실행하지 않고 턴을 끝내는" 상태가 없다.** 삽입 경위(자동/명시)를 아는 것도 계획 층 정보 |
| **폴백이 이유를 삼키지 않는다** | 실패 시 결정론 문구로 떨어지되 **경고로 이유를 남긴다** | 표준 폴백은 문장만 돌려준다 — **우리가 세 번 대가를 치른** 실수가 정확히 그것 |
| **상태 전이 독점** | 에이전트는 세션을 못 고치고 신고만. 위임은 **세션 사본**으로 실행 | 노드가 공유 상태를 직접 갱신하는 모델과 정면 충돌 |

> "'LangGraph로 하면 몇 줄일 텐데'에 대한 답은 **줄 수가 아니라 표현 가능성**입니다.
> 이것들을 프레임워크 루프 위에 얹으려면 **우회 코드가 규율보다 커집니다.**"

**"프레임워크 안 쓴 게 자랑이냐"에 대한 답 — 정당해지는 5조건을 코드로 확인했습니다:**

| 조건 | 상태 |
|---|---|
| 필요한 루프만 구현했나 | `agent_loop.py` **422줄** — 스텝 상한·스키마 제약·검증·궤적 기록만 |
| 상태 모델이 명확한가 | 키 화이트리스트 · `get()`은 복사본 · 전이는 신고 독점 · SQLite 영속 |
| 실패 복구·재시도가 있나 | 4층 재시도 · 턴당 실패 대체 예산 1회 · 위임 실패가 호출자를 안 죽임 |
| 에이전트/툴 경계가 선명한가 | `kind`로 **코드에 존재**. 계산/표현 시그니처 분리 |
| 회귀 검증이 되나 | **798건 / 4.15초 / 비용 0** + baseline 30여 개 |

> "프레임워크를 **안 쓴 게 강점이 아닙니다.
> 자리마다 다르게 고르고, 그 판단을 숫자로 검증한 것**이 강점입니다."

▸ **정직하게 — 자체 런타임의 대가 둘**: 세션 상태에 타입이 없다(키는 막았지만 오타가 런타임까지 간다) ·
checkpointer가 없어 긴 파이프라인 중단·재개가 안 된다. 둘 다 **도입 조건을 코드 주석에 적어 뒀습니다.**

### 3-2. 프레임워크가 줬을 것들을 직접 만들었다 — 5계층

| 계층 | 무엇 | 없으면 답할 수 없게 되는 질문 |
|---|---|---|
| **상태관리** | 화이트보드 + 쓰기 통로 단일화 (246줄) | "왜 이 값이 바뀌었나" |
| **재시도 4층** | LLM 호출(3회+교정) / 자기 루프(5~7) / 판정 그래프(예산제) / **턴 실행(턴당 1회)** | "무엇이 실패를 부르나" |
| **로깅 3층** | trace(13종 이벤트) / 턴 덤프(opt-in) / **감사 로그**(append-only, 기본 켜짐) | "동의를 몇 번 물었고 몇 번 승인됐나" |
| **시각화** | 같은 trace를 단계실행기·진행스트림·`explain` 셋이 재사용 | "지금 어디까지 왔나" |
| **테스트** | 회귀 798건 + 평가 하네스 4종 | "고친 게 정말 나아졌나" |

> "다섯 다 **없어서 아팠던 질문이 먼저 있었습니다.
> 기능을 먼저 넣고 쓸모를 찾은 층이 하나도 없습니다** — 그 질문들이 §4의 사건 기록입니다."

세부에서 말할 것 3개:

- **재시도가 넷인 이유는 막는 실패가 다르기 때문입니다.** 특히 **교정 재시도** —
  형식 위반이면 **오류 메시지를 프롬프트에 붙여** 다시 보냅니다.
  *같은 프롬프트를 그대로 보내면 형식 위반은 같은 자리에서 반복됩니다* — flaky가 아니라 **stable-wrong**입니다.
- **턴 실행 재시도만 턴당 1회**입니다 — 스텝 상한(5)과 별도로 두는 이유는 **실패가 실패를 부르는 연쇄**를 막으려고.
- **감사 로그는 읽는 게 아니라 세는 것**입니다. 대상을 6종으로 좁혔고(동의·승인·이력서확인·위임·**위임거부**·상한),
  **거부를 반드시 남깁니다** — 성공만 세면 hand-off 성공률의 **분모가 없어집니다.**
- **모른다 ≠ 0** — 토큰을 안 주는 공급자의 콜은 추정하지 않고 따로 셉니다.
  **합계가 전부가 아닐 수 있다는 사실 자체가 숫자로 남습니다.**

### 3-3. 상태관리 — "블롭 하나가 진실, 테이블은 투영"

| 장치 | 왜 |
|---|---|
| **키 화이트리스트** | 목록 밖의 키로 쓰면 `KeyError`. 오염된 키가 쌓이면 "이 세션에 뭐가 있나"가 코드에서 사라진다 |
| **`get()`은 복사본** | 받아서 고쳐도 저장 안 됨. 예전 구현은 살아 있는 dict를 줘서 **두 구현의 동작이 갈렸다** |
| **전이 독점** | 에이전트는 신고만, 오케스트레이터가 턴 끝에 한 번 저장. 전이 지점이 하나여야 "왜 바뀌었나"에 답할 수 있다 |
| **위임은 세션 사본으로** | 읽기 전용을 규약이 아니라 **인자로** 강제 |
| **파생 자산 무효화** | 이력서가 바뀌면 분석·프로필을 지운다 (블랙보드의 알려진 함정 = stale 파생) |
| **재판정 방지 지문** | 같은 공고×이력서면 다시 판정 안 하고 경고를 남긴다. **판정은 입력의 함수** |
| **라이브러리(상한 5)** | 활성 공고·이력서가 교체돼도 이전 것이 남아 "아까 그 이력서로"가 성립 |

### 3-4. 판정 엔진 — 정형은 알고리즘, 서술형은 LLM

```
START ─┬→ 공고 파싱  ──┐   (병렬)
       └→ 프로필 빌드 ─┘
              ▼ defer=True 합류
        완결성 검사 → 충분성 검사
              ├ 부족 → 되묻는다 → 출력      (모른다 ≠ 아니다)
              └ 충분 → 격차 분석 → 로드맵 → (필요시) 대안 공고 ← RAG
                                    ▼
                            산출물 검증 ─(재시도 or 통과)→ 출력
```

> "각 노드 뒤에 **산출물 검증 라우터**가 붙습니다. 생성이 실패하면 다음으로 안 넘어가고
> 같은 노드에 다시 지시하고, 재시도 예산을 다 쓴 뒤에야 진행합니다.
> 경고·근거·툴로그는 누적돼 병합되므로 **왜 이 결과가 나왔는지가 항상 따라붙습니다.**"
>
> "요구사항별 판정은 **~0초**입니다. 정형 대조는 산술이고, 서술형은 N건을 **1콜로 배치**했습니다."

**08-04, 종합 등급만 하이브리드로 바꿨습니다 ★ (발표에서 가장 좋은 이야기)**

| 단계 | 누가 | 무엇 |
|---|---|---|
| 1. 사실 판정 | 룰 | 무엇을 갖췄나 (기존 그대로) |
| 1.5. **재검증** | **LLM** | 룰이 미충족·판정불가로 본 것 중 **근거로 뒤집을 수 있는 것**을 찾아 판정 기록 자체를 갱신 |
| 3. 등급 제안 | **LLM** | 검증 끝난 판정 결과만 보고 루브릭으로 상/중/하 |
| 4. 등급 확정 | 룰 | LLM 제안을 하드 룰 **G1~G6의 허용 범위로 클램프** |

> "왜 넣었냐면, 요구 문구가 달라 룰이 놓치는 자리가 있었습니다 —
> 보유 스킬 **Elasticsearch**와 요건 **'검색 엔진 기반 서비스 개발 경험'**이 안 맞아떨어집니다.
>
> LLM을 판단 계층에 들인 대신 **위험은 구조로 막았습니다**:
> **상향 전용** — 하향은 스키마가 아예 허용하지 않습니다.
> **근거 인용 강제** — 근거 인덱스 없는 override는 코드가 버립니다. 지어낸 근거로 못 뒤집습니다.
> **하드 룰 클램프** — 필수 미충족 2건 이상이면 '상' 불가, 필수 전부 충족이면 '하' 불가.
> **추적** — 클램프 전 LLM 제안과 발동한 규칙을 결과에 남깁니다.
> **입력을 넓히지 않습니다** — 등급 판단에 이력서 원문을 다시 주지 않습니다. 사실 재심은 1.5단계에서 끝났고,
> 입력을 넓히면 판단이 흔들립니다."

**"예전에 기각한 방향인데 같은 실수 아니냐" — 이 질문 반드시 옵니다:**

> "기준이 뒤집힌 게 아닙니다. 기준은 **'알고리즘이냐 LLM이냐'가 아니라 '입력이 정형이냐'**입니다.
> 전에 알고리즘으로 옮긴 것들은 *정형인데 LLM에 맡기고 있던* 것이고,
> 등급은 반대로 *정형이 아닌데 산술로 자르고 있던* 것입니다.
> 가중평균 0.7/0.4는 격차의 **크기는 세지만 성질을 못 봅니다** —
> '3개월이면 메꿔지는 2건'과 '주력 기술 미보유'가 같은 점수로 나왔습니다.
> **기준은 양쪽 방향으로 똑같이 적용됐습니다.**"

## 4. 트러블슈팅 ★★ 발표의 하이라이트

> "이 시스템의 규칙은 대부분 **책이 아니라 사고에서** 나왔습니다.
> **증상 → 진짜 원인 → 처방**으로 정리했는데, 세 칸이 다른 게 핵심입니다 —
> **증상에서 원인으로 가는 길이 매번 반직관적**이었습니다."

### 4-1. "정상처럼 보였는데 죽어 있던" 것들 ★

| 증상 | 진짜 원인 | 처방 |
|---|---|---|
| 검증 재시도 루프가 잘 도는 줄 알았다 | 라우터의 **이중 가드** 때문에 **한 번도 발동한 적 없었다** | 여러 번 돌아야 성립하는 기능은 **실기동**으로 확인 |
| 자기 루프가 도는 줄 알았다 | 설정 하나가 빠져 **층이 통째로 꺼진 채** 계산 폴백으로 답하고 있었다 | **실 모델로 한 번 돌린다**를 규약에 |
| 면접 담당이 테스트는 통과 | 선언한 산출물 키가 세션 허용 목록에 없어 **실서버에서 매번 실패** | 계약을 테스트로 못 박기 |
| 관찰이 "결과 보고 다시 정한다"는데 로그가 없다 | 로그를 남기기 **전에** 함수를 빠져나가고 있었다 | **아무것도 안 바꾼 결정도 기록한다** |

> "**'예외가 안 났다'는 동작의 증거가 아닙니다.** 이 네 건이 전부 단위 테스트 통과 상태였습니다.
> 그리고 **폴백이 그럴듯하면 결함이 안 보입니다** —
> 자기 루프가 통째로 꺼진 채 '정상처럼' 답하고 있었고, 아무도 몰랐습니다."

### 4-2. 숫자가 거짓말한 순간들 ★

| 증상 | 진짜 원인 | 처방 |
|---|---|---|
| 플래너 정확도 100%로 기록돼 있었다 | baseline 저장 **5시간 뒤** 프롬프트가 바뀌었다. 재측정하니 **67%** | **프롬프트 변경과 평가셋 재측정은 같은 커밋에** |
| 프롬프트 고쳐 총계 0.67 → 0.78 | 케이스별로는 **고친 것 8 / 깨뜨린 것 6** | **케이스별로 본다.** 좁히는 변경과 넓히는 변경을 같은 커밋에 안 넣는다 |
| 파싱 F1이 0.08로 나왔다 | 출력은 정답과 의미가 같았다. **정답 라벨의 띄어쓰기**가 채점기를 깨뜨렸다 | 지표가 상식과 어긋나면 **먼저 채점기와 라벨을 의심** |
| 실패 17건을 "불일치"로 뭉쳐 보고 있었다 | 축이 하나였다 | **정확도와 안정성을 분리** → flaky 3건 + 프롬프트 과잉 5 + 데이터셋 낡음 6 |

> "**측정하지 않은 것은 모르는 것이고, 측정 도구 자체도 틀릴 수 있습니다.**"

▸ **측정 방법 자체를 세 번 고쳤습니다**: ① 지표를 정확도/안정성으로 갈랐다(0/3이 *일관되게 틀린 것*인지
*무작위로 틀린 것*인지 구분이 안 되는데 **처방이 다르다**) · ② 새 평가 케이스가 **고치기 전에도 통과**하는지
검증했다(그러면 개선을 재는 게 아니라 결과를 베끼는 것 — 처음 만든 4문제가 전부 그랬다) ·
③ 같은 데이터가 **범위로는 "악화", 표준오차로는 "절반 개선"**으로 읽혔다.

### 4-3. LLM을 "부탁"으로 다루려다 실패한 것들 ★

| 증상 | 진짜 원인 | 처방 |
|---|---|---|
| 이력서를 냈는데 분석이 안 돌았다 | 스키마 필드에 **설명을 빼먹어** 모델이 확신도를 `0.0`으로 채웠고, **자기가 고른 계획이 문턱에서 잘렸다** | **스키마의 description은 문서가 아니라 지시문이다** |
| 회사명을 못 찾자 그 값으로 검색을 돌렸다 | LLM이 "값 없음"을 **`<UNKNOWN>`이라는 그럴듯한 문자열**로 채웠다 | 자리표시자를 씻어내고 **값의 존재 여부로 분기** |
| 모델이 직군을 멋대로 추측했다 | 프롬프트로 부탁하고 있었다 | **출력 스키마에서 그 필드를 제거** |
| 면접 답변 점검이 매번 템플릿으로 떨어졌다 | 금지 낱말에 `반드시`·`무조건` 같은 **코칭 일상어**가 있었다 | 목록을 푸는 게 아니라 **위반 낱말을 알려주고 다시 쓰게** |
| 도구 이름 환각을 막으려 형식을 제한했다 | 표기 형식까지 막아 **턴 전체를 실패시켰다** | 막을 것은 **없는 이름**이지 표기가 아니다 — 표기는 정규화 |

> "여기서 나온 원칙이 이겁니다 — **금지는 프롬프트가 아니라 구조로.**
> 줄 수 없는 답은 **출력 형식에서 칸을 뺐고**,
> 하면 안 되는 행동(제출·결제)은 **그 도구를 만들지 않았습니다.**
> '하지 마라'는 실측에서 지켜지지 않았습니다."

### 4-4. 원인이 실패한 곳에 없던 사건 둘

> "**① RAG가 계속 실패한다 → 서버 문제가 아니었습니다.**
> 첫 장문 검색이 수십 초 걸리는데 타임아웃이 짧아 **정상 동작을 실패로 오판**하고 있었습니다.
> 타임아웃을 늘리고, 자산이 도착하는 순간 **미리 한 번 예열**하게 바꿨습니다.
>
> **② RAG 서버가 아예 안 뜬다 → 에러 메시지 세 개가 전부 원인이 아니었습니다.**
> 화면에 찍힌 에러를 차례로 고쳤는데 전부 헛다리였습니다.
> **에러 메시지는 증상이지 원인이 아닙니다.**"

### 4-5. 정직함을 지키느라 만든 규칙들

| 사건 | 규칙 |
|---|---|
| LLM 호출이 실패했는데 **가짜 결과가 진짜처럼** 나왔다 | 키가 없으면 mock(개발 편의), **호출이 실패하면 빈 결과 + 경고.** 지어내지 않는다 |
| 폴백이 경고를 잃어 "왜 기본 문구가 나왔는지" 흔적이 없었다 (**두 번 겪음**) | 표현 계약을 `문장` → **`(문장, 경고)`** 로. 위임도 상대의 경고를 그대로 올린다 |
| 유사도 계산 실패를 `0.0`으로 돌려줬다 | `0.0`은 "안 닮았다"는 **판정**이다. 실패는 **"모른다"**여야 한다 |
| 신입이 "경력 2년 이상" 공고를 충족으로 나왔다 | 연속값(개월)을 **너무 일찍 구간으로 뭉갠** 탓. 원값을 끝까지 들고 간다 |

### 4-6. 전부를 관통하는 원칙 여섯 (클로징 전 슬라이드 1장)

| | 원칙 | 대표 근거 |
|---|---|---|
| A | 측정하지 않은 것은 모르는 것이다 | baseline이 5시간 만에 죽었다 |
| B | LLM은 **부탁이 아니라 구조**로 다룬다 | 파싱을 LLM 한 콜로 두는 안을 A/B로 기각 — 정확도는 동률인데 **재현성이 갈렸다** |
| C | 실패와 "모른다"를 정직하게 다룬다 | 가짜 폴백이 가장 위험하다 |
| D | 상태·계약은 파생하지 말고 **단일 출처** | 번역기 3개를 지운 이유 |
| E | 규칙에는 **근거를 함께 적는다** | "도구라서"가 아니라 "결정론이라 바꿀 게 없어서" |
| F | 한 번에 하나, 매번 잰다 | 총계가 케이스별 파손을 가렸다 |

## 5. 핵심 기술 — 성능을 어떻게 올렸나

### 5-1. 이렇게 했더니 이렇게 달라졌다 (전·후 전부 같은 하네스 실측)

| 무엇을 했나 | 전 | 후 |
|---|---|---|
| **담당 설명의 어휘를 좁혔다** (규칙 추가가 아니라) | 0.8478 · 일관 오답 3건 | **1.0** · **0건** |
| **아무것도 안 바꾸던 관찰 LLM을 걷어냈다** | 관찰 2회가 **26.2초** 쓰고 실행 변경 **0건** | 규칙 판정 **0초** |

| **컨텍스트를 원문 대신 정형 사실로** | 턴당 토큰 4,347 | **301 (−93%)** |
| **선빌드 최적화를 재 보고 도로 뺐다** | 임계 경로에 **8.3초** 추가 중 | 제거 |

> "**일곱 중 다섯이 무언가를 더한 게 아니라 덜어 낸 것입니다.**
> 관찰 LLM 제거, 선빌드 제거, 위임 감소, 규칙 5개를 사다리 1개로, 어휘를 넓히지 않고 좁히기.
> **이 프로젝트에서 성능을 올린 가장 확실한 방법은
> 재 보고 값을 못 하는 것을 걷어내는 것이었습니다.**"

### 5-2. 플래너 정확도 0.85 → 1.0 — 각 단계에서 무엇을 했나

### 5-3. 가장 강한 A/B — 이 두 숫자가 프로젝트 작업 순서를 바꿨다 ★★

같은 문제, 같은 모델, 두 가지 처방:

| 처방 | 정확도 | 부작용 |
|---|---|---|
| 판단 원칙에 **규칙을 추가**한다 | **−0.022** | 무관한 케이스 **4건 파손** |
| 선택지의 **정의를 좁힌다** | **+0.058** | 파손 **0** |

> "**모델이 못 고르는 이유는 규칙을 몰라서가 아니라 선택지의 뜻이 넓어서였습니다.**
> 이 뒤로 프롬프트에 규칙을 더하는 작업은 하지 않습니다."

▸ 되돌린 시도도 남아 있습니다 — 특정 케이스를 고치려고 규칙을 넣었다가 총계가 내려가 되돌렸고,
그 케이스는 지금도 **"알려진 실패"로 표기**해 뒀습니다. **고치지 못한 걸 고친 척하지 않습니다.**

### 5-4. 하네스 엔지니어링 — 발표에서 꼭 쓸 단어

> "성능을 올린 작업의 대부분은 **프롬프트 문장을 다듬는 일이 아니라, 모델의 작업 환경을 고치는 일**이었습니다.
> 그 환경을 저희는 **하네스**라고 부릅니다 — 모델이 한 스텝을 밟을 때 **실제로 손에 쥐는 것 전부**입니다."

| 부품 | 이걸 고쳐서 얻은 것 |
|---|---|
| 역할·규율 | 공고 담당 첫 응답을 6절로 재구성 — **하는 일을 요건보다 앞에** |
| **이번 턴 사실** | 이력서 담당에게 *근거 있는 스킬 / 이름만 있는 스킬*을 **갈라서** 주자 답이 달라졌다 |
| 도구 목록·인자 설명 | 형식만 정하고 **검색어는 LLM이 짓는다** — 자율성이 사는 자리 |
| **출력 스키마** | 칸을 **넣어서** 프롬프트로 안 되던 것을 해결 |
| 관찰 문자열 | 규칙이 계산한 분기점을 관찰로 돌려주자 **행동이 갈렸다** |
| 대화 창 | 최근 6항·항목당 300자, **답변만 4배** — 대칭으로 자르던 시절 *"내 말은 기억하는데 자기 말은 못 기억"* |
| 지속 사실 | 담당들이 매 턴 백지에서 시작하던 것을 닫았다 |
| 상한과 검증 | 상한이 곧 **"몇 번 고쳐 쓸 수 있나"** — 3이면 재작성 궤적이 잘렸다 |

**효과 순위(실측): 재료 > 스키마 > 어휘 > 모델 > 프롬프트 규칙**

> "**부탁(프롬프트 규칙)을 고친 처방이 유일하게 값이 음수였고,
> 자리(재료·스키마·어휘·상한)를 고친 처방이 전부 위로 움직였습니다.**
> 하네스 엔지니어링은 *모델에게 더 잘 부탁하는 법*이 아니라 **모델이 일할 자리를 만드는 일**입니다."

### 5-5. 도구 설계 규약 — 에이전트답게 만든 실제 장치

| 규약 | 예 |
|---|---|
| **사실만 담고 판단·권유를 넣지 않는다** | 관찰에 "안내하세요"를 넣었더니 답변이 도구 동작을 서술해버렸다("이력서를 요청드렸어요") |
| **거절할 땐 사유와 함께 다음 재료를 준다** | 커버 요구사항 ID 없는 제안을 거부하며 *"쓸 수 있는 ID: req-1, req-2…"*를 돌려준다 |
| **분기점을 관찰로 돌려준다** | *"선호 차원 3개, 충분한가: 예"* — 규칙이 계산한 결과를 문장으로 주면 LLM이 행동을 바꾼다 |
| **실패는 예외가 아니라 관찰이다** | 도구가 raise하면 루프가 죽지만, 문자열로 돌려주면 모델이 다른 걸 시도한다 |

> "외부 리뷰에서 **'프로젝트 제안이 아무 공고에나 나올 답'**이라는 지적을 받았습니다.
> 프롬프트로 근거를 강제하는 대신 **도구가 검증하게** 만들었습니다 —
> **커버 요구사항 ID를 못 대면 도구가 거부**하고, 무엇이 틀렸는지를 관찰로 돌려줍니다.
> 예상 소요 기간 칸은 **일부러 없습니다** — 데이터가 없어 지어내게 되니까요."

▸ 자소서의 근거 도구는 **인자가 필터가 아니라 정렬 힌트**입니다. 0건이어도 전체를 함께 돌려줍니다 —
이력서는 다른 말로 적혀 있고("트러블슈팅" ↔ "장애 대응"), **어느 문장이 해당하는지 판단하는 건
substring이 아니라 LLM의 일**이라서.

## 6. 다른 파트와 계약을 어떻게 했나 ★

### 6-1. 경계 한 문장

> "**프론트는 AI를 모릅니다. 백엔드만 AI를 압니다.**
> 백엔드는 AI를 **HTTP 문 5개**로만 부르고, AI는 자기 DB를 진실로 삼지 않습니다 —
> **매 요청에 실려 온 것이 문맥의 전부**입니다."

```
프론트(Vue) ─ /api/** ─▶ 백엔드(Spring :8080) ─ 공유 시크릿 ─▶ AI(FastAPI :8000) ─▶ RAG(:8765)
 AI 주소를 모름          PostgreSQL 유일 writer            무상태 · 문 5개
 폴링 2.5초              워커 4종이 AI를 호출               오케스트레이터 + 에이전트
```

### 6-2. 백엔드와의 문 5개

| 엔드포인트 | 부르는 쪽 | 무엇이 나가나 |
|---|---|---|
| `/v1/analyses` (+`/stream`) | AnalysisWorker | 완료 + 공고맥락·평가·역량제안, 또는 **되묻기**(객관식 1개) |
| `/v1/chat` (+`/stream`) | ChatReplyWorker | 답변 + **화자별 문장** + 진행단계 + 이번 턴 산출물 |
| `/v1/career-extractions` | CareerExtractionWorker | 커리어 조각(경력·프로젝트·자격) |
| `/v1/evidence-verifications` | EvidenceVerificationWorker | 판정·신뢰도·강점·격차·다음행동 |
| `/v1/competency-assessments` | CompetencyAssessmentService | 직전 답 채점 + 다음 문제 |

- 인증은 **서버 대 서버 공유 시크릿**. **사용자 토큰은 AI까지 오지 않습니다** — AI는 사용자를 모릅니다.
- 백엔드는 `AI_SERVER_URL` **한 줄**로 AI를 고릅니다 — **가짜 AI ↔ 진짜 에이전트 교체가 환경변수 하나**입니다.
- 스트림이 없거나 죽으면 백엔드가 **자동으로 단건 경로로 폴백**합니다.

### 6-3. 오류 코드가 곧 계약이다 ★ 이 이야기는 꼭

> "AI는 **'그럴듯한 결과'를 만들지 않고 실패를 실패로** 냅니다. 백엔드는 이 코드로 재시도 여부를 판단합니다."

| 코드 | 뜻 | 백엔드 행동 |
|---|---|---|
| `AI_PROVIDER_NOT_CONFIGURED` | LLM 미설정 — **가짜 성공을 만들지 않는다** | FAILED |
| `AI_PROVIDER_UNAVAILABLE` | 엔진이 결과에 못 이름 (재시도 가능) | 재시도/백오프 |
| `INVALID_AI_RESPONSE` | 산출물이 계약 검증 탈락 | FAILED + 안내 |
| `POSTING_TEXT_INSUFFICIENT` | 공고 원문 부족 — **재시도해도 같다** | 사유를 그대로 노출 |
| `CAREER_DATA_REQUIRED` | 이력서 없음 — **사용자가 할 일이 있다** | 사유를 그대로 노출 |

> "**뒤의 두 코드가 왜 따로 있는지가 협업의 핵심입니다.**
> 백엔드가 `AI_PROVIDER_UNAVAILABLE`을 '**AI 서비스 응답이 지연되었습니다**'로 덮어씁니다.
> 그래서 실측에서 **'이력서를 등록해 주세요'라는 진짜 사유가 그 문구에 지워졌고,
> 화면에는 있지도 않은 장애만 남고, 사용자가 할 일은 사라졌습니다.**
> 코드를 갈라 내니 그 함수가 우리 문장을 그대로 저장합니다.
> **폴백은 이유를 삼키지 않는다** — 이게 서비스 경계 너머까지 이어진 원칙입니다."

### 6-4. 등급은 AI가 정하지 않는다 (역할 분담 질문 대비)

> "AI는 **'무엇이 요구되는가'** — 역량·요건·경력 관문을 냅니다.
> `APPLY_NOW` / `STRENGTHEN_THEN_APPLY` / `ALTERNATIVE_FIRST` 판정은
> 백엔드가 **SQL로 셉니다** — 검증된 필수 역량 n/m, 요구 경력 개월 대비 확인된 경력.
> **판단은 결정론, 표현은 LLM**이라는 원칙이 **서비스 경계 너머까지 이어진 자리**입니다."

▸ **같은 공고는 한 번만 분석합니다.** 원문 지문 + 되물음 답변을 키로 임대를 잡아서,
두 사람이 같은 공고를 동시에 넣으면 **한쪽만 AI를 부르고** 다른 쪽은 기다렸다가 캐시를 재사용합니다.

### 6-5. 상태 계약 — "블롭 하나가 진실, 테이블은 투영"

```
매 턴 응답   세션 자산 전체를 통째로 내보낸다  →  백엔드가 저장
다음 요청    그대로 되돌아온다               →  AI가 번역 없이 복원
```

> "처음엔 AI의 말과 DB의 말을 **번역**했습니다. 번역 층이 셋 있었고,
> 그 번역이 에이전트의 **'방금 받았나' 판단을 덮어써** 단계별 행동이 무너졌습니다.
> **번역을 없애고 통째로 주고받게** 바꿨습니다 — ***번역이 없으면 번역 버그도 없습니다.***"

- 그 위에 **읽기 전용 투영**이 얹힙니다(화면·조회·통계용). writer는 **백엔드 하나.**
- 선언 표에 **없는 세션 키가 생기면 테스트가 깨집니다** = 조용한 유실 방지 장치.
- 프론트의 담당 키가 **에이전트 이름과 같은 이름공간**입니다. AI는 화자 키만 보내고
  색·아이콘은 프론트 한 곳에만 둡니다 — **세 곳에 두면 갈립니다.**
- 대화에서 만든 지도 재료도 **경로 A의 기존 적재 코드를 그대로** 씁니다 —
  **같은 걸 만드는 코드가 둘이 되면 언젠가 결과가 갈립니다.**

### 6-6. 진행 스트리밍 계약 (프론트 진행 휠)

> "NDJSON **한 줄 = 한 이벤트**입니다. 불변식을 어기면 그 잡이 FAILED로 끝납니다 —
> 순번 1부터 엄격 증가 / 첫 줄 시작 이벤트 / 마지막 줄 결과 또는 오류 / **결과는 정확히 1건.**
> **이벤트 1건 = 백엔드 DB 쓰기 1건**이라 한 분석당 예산 60건이고,
> 넘치면 진행 갱신만 멈추고(계획·결과·오류는 계속) 못 보낸 건수를 로그로 남깁니다."

▸ **2단 발행** — 플래너가 돌기 전엔 누가 실행될지 모르므로 백본 계획을 먼저 내고,
확정 후 에이전트별 스테이지로 시작 이벤트를 **다시** 냅니다. 프론트가 "마지막 것"을 쓰기 때문에 성립합니다.

▸ **계측을 새로 안 만들었습니다.** 내부 trace가 이미 있어서 이 모듈은 **옮겨 적기만** 합니다.

### 6-7. RAG 파트와의 계약

> "에이전트는 **RAG 내부 구현을 모릅니다.** 아는 것은 **인터페이스 둘**뿐입니다 —
> 범용 검색과 기업 맥락 조회. 반환은 `{결과, 출처, 경고}`입니다.
> **실패해도 예외를 던지지 않습니다** — 경고를 달고 빈 결과를 돌려줍니다.
> **RAG가 죽어도 그래프는 계속 돌고, 왜 결과가 얇은지는 경고에 남습니다.**
> provider는 환경변수 한 줄로 갈아끼웁니다 — 실 서버 / 로컬 공고 JSON / 미연결."

어댑터가 추가로 하는 일 셋:
- **중복 제거** — 같은 공고가 work24·saramin에 각각 크롤돼 있습니다. **후보를 만드는 자리가 여기 하나뿐이라
  중복 제거도 여기서 한 번만** 합니다.
- **"붙어 있는데 소스가 없음"을 미연결과 구별** — *붙어 있는데 미연결로 적으면 다음 사람이 없는 장애를 좇습니다.*
- **예열** — 콜드 첫 쿼리가 30초를 넘긴 실측이 있어서, 자산이 채워지는 순간 미리 쏩니다.

### 6-8. 실패하면 어떻게 되나 (질문 나오면)

| 어디가 죽나 | 사용자에게 보이는 것 |
|---|---|
| RAG 서버 | 결과는 나온다 (키워드 검색 강등 + 경고, 근거가 얇아짐) |
| 플래너 LLM | 대화는 이어진다. **대응표로 흐름을 대신 정하지 않는다** |
| LLM 전체 미설정 | 잡 FAILED — **그럴듯한 폴백을 만들지 않는다** |
| 스트림 없음/죽음 | 백엔드가 단건 경로로 폴백. 실시간이 아닐 뿐 |
| 계약 검증 탈락 | "다시 분석" 안내 + 무엇이 어긋났는지 로그 |
| 자료가 없음 | 에이전트가 청한 그 문장이 화면까지 **그대로** 간다 |

> "관통하는 원칙 하나 — **폴백은 이유를 삼키지 않습니다.**
> 문장만 돌려주는 계약은 '왜 기본 문구가 나왔는지'를 지웁니다.
> **이 저장소가 세 번 대가를 치른 실수**입니다."

**측정된 것**

| 무엇 | 결과 |

**아직 안 되는 것 — 이걸 말하는 게 포인트**

- **08-04 하이브리드 등급이 측정 없이 들어와 있습니다.** 하드 룰은 단위 테스트가 덮지만
  **LLM이 끼는 재검증·등급 판단은 한 번도 안 쟀습니다.** 평가 하네스가 개발 사본에 있고 정본으로 안 넘어왔습니다.
- **승격된 공고·이력서 담당의 루프 궤적을 재는 케이스가 없습니다** — 에이전트 7 중 2명이 측정 밖.
- **선호 파악이 5회 중 1회 도구를 하나도 안 쓰고 답했습니다** — 기록 없이 답하면 다음 턴이 아무것도 못 물려받습니다.
- **개조식 이력서를 못 알아봅니다** — "~했습니다" 문체를 신호로 쓰는데 명사형("개발", "구축") 이력서는
  판정을 포기합니다. **그런데 답변은 그럴듯하게 나와서 겉으로는 안 보입니다.**
- **추천 순위가 잘 안 갈립니다** — 전부 동률이라 사실상 검색 점수순.
- **추천 품질은 아직 측정하지 않았습니다** — 잰 것은 "누구를 부르나"와 "같은 답을 내나"이지
  **"좋은 답인가"가 아닙니다.**

> "**라우팅 정확도 1.0은 좋은 소식이자, 그 지표의 수명이 끝났다는 소식입니다.**
> 다음에 재야 할 것은 '누구를 부르나'가 아니라 **'좋은 답인가'**입니다."

## 8. 클로징 — 배운 것 다섯 줄

> 1. **LLM에게 재료와 권한이 없는 자리를 주면 일하는 것처럼 보이지만 일하지 않습니다** —
>    요약만 보던 관찰 층은 실측 발동 0건, 재료를 쥔 안쪽 루프는 같은 모델로 재작성·위임을 해냈습니다.
> 2. **금지는 프롬프트가 아니라 구조로** — 줄 수 없는 답은 형식에서 칸을 빼고,
>    하면 안 되는 행동은 도구를 주지 않습니다.
> 3. **규칙 추가보다 어휘 좁히기** — 같은 문제에서 −0.022 vs +0.058.
> 4. **총계가 아니라 케이스별로, 그리고 어떤 추정량으로 보는지까지** —
>    같은 데이터가 지표에 따라 "악화"와 "개선"으로 갈렸습니다.
> 5. **폴백이 그럴듯하면 결함이 안 보입니다** — 자기 루프가 통째로 꺼진 채 "정상처럼" 답하고 있었습니다.

**마지막 한 줄:**

> "3주간 결정 **164건**을 기록했고, **뒤집힌 결정도 지우지 않았습니다** —
> 다음 사람이 같은 것을 다시 시도하지 않도록."

## 부록 B. 예상 질문 → 답

| 질문 | 답 |
|---|---|
| **그냥 워크플로우 아닌가요?** | **agentic한 층 아래에 결정론 워크플로우 엔진을 둔 구조**입니다. 전부 agentic이면 아무것도 못 재고, 전부 워크플로우면 "이 공고 기준으로 뭘 공부할까"를 못 받습니다. 갈라 뒀고 **판정만 아래로 내렸습니다** |
| **LangChain 왜 안 썼나요?** | 안 쓴 게 아니라 **층마다 다르게** 골랐습니다. 판정은 LangGraph, LLM 호출은 langchain-core, **에이전트 루프만 자체 422줄** — 프레임워크 루프에 *"실행하지 않고 턴을 끝내는" 상태가 없어서*입니다 |
| **에이전트가 7개나 필요해요?** | 공고 읽기·이력서 읽기·등급 판정·글쓰기는 **실패 방식도 "잘했다"의 정의도 다릅니다.** 한 루프에 넣으면 차이가 사라지는 게 아니라 **안 보이게 됩니다** |
| **에이전트끼리 대화하나요?** | **화이트보드(공유 상태)로만**. 직접 대화는 읽기 전용 위임 1종, 깊이 1, 세션 사본. 위임이 잦던 시절의 정체는 협업이 아니라 **근거 빈곤의 보상 행동**이었고, 재료를 넓히자 **4/5 → 0/5**로 사라지면서 위반 5 → 0, 콜 −27%가 같이 왔습니다 |
| **MCP / A2A는요?** | 검토하고 **안 하기로 결정**했습니다(근거 기록). 내부 도구는 세션을 직접 만지는 결정론 함수라 프로토콜 경계를 넣으면 **표준화 이득 없이 직렬화 비용만** 붙습니다. 값이 있는 자리는 외부 경계이고, **외부 소스가 두 번째로 붙는 날**이 도입 시점입니다 |
| **환각은 어떻게 막나요?** | 프롬프트로 안 막습니다. 플래너 출력은 스키마 `Literal` 제한, 도구 이름도 `Literal`, 근거 없는 등급 override는 **코드가 버리고**, 제출·결제 같은 최종 행동은 **그 도구를 만들지 않았습니다** |
| **비용은요?** | 턴당 콜 **2.8회**, 컨텍스트를 정형 사실로 바꿔 토큰 **4,347 → 301(−93%)**. 다만 **지금 프로바이더가 토큰을 안 줘서 비용 환산은 못 합니다** — 추정하지 않고 따로 셉니다 |
| **테스트가 798건인데 LLM 없이 뭘 재나요?** | **규율을 코드로 잠급니다** — 도구는 표현 계층을 반드시 갖는다, 미선언 인자는 통과 못 한다, 세션 키는 목적지가 선언돼 있어야 한다. LLM이 필요한 것은 **평가 하네스 4종**이 따로 재고, baseline 30여 개가 남아 있습니다 |
| **재현성은 어떻게 보장하나요?** | 판정은 **입력의 함수**입니다 — 같은 공고×이력서면 재계산하지 않고 재사용합니다. 정형 대조는 산술이라 애초에 같은 값이 나오고, 라우팅은 52상황 × 3회에서 재현성 **1.0**입니다 |
