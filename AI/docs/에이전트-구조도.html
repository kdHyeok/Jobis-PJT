그림 3. 화이트보드 — 에이전트끼리 말을 걸지 않는다

직접 대화하면 통로가 N(N−1)로 늘고 통로마다 가드가 필요하다. 공유 상태 한 곳을 두고, 쓰기는 오케스트레이터가 독점한다.

쓰는 쪽 ▶
  • 공고 수집 → 공고 원문
  • 적합도 분석 → 분석 · 로드맵
  • 공고 추천 → 추천 목록
  • 선호 파악 → 선호
  • 자소서 초안 → 초안
  • 면접 준비 → 면접 진행
  • 지원 경로 설계 → 지원 경로
  • 사용자 첨부 → 이력서
아무도 직접 못 쓴다. 신고하고, 오케스트레이터가 턴 끝에 한 번 저장한다 — 전이 지점이 하나여야 "왜 바뀌었나"에 답할 수 있다.

전제가 비면 실행되지 않는다. 대신 검증기가 생산자를 앞에 끼운다 — 순서가 계산돼 나오는 원리다.
직접 대화는 하나만 열려 있다 — 자소서 → 이력서 담당 읽기 전용 위임(깊이 1, 세션 사본). 넓히지 않은 이유는 실측이다 — 위임이 잦던 시절의 정체는 협업이 아니라 근거 빈곤이었고, 재료를 넓히자 4/5 → 0/5, 위반 5 → 0, 콜 −27%가 같이 왔다.
