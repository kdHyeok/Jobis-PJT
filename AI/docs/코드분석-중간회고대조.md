# 에이전트 코드 전수 분석 — 중간회고 대조 보고 (2026-07-24)

> [`AI중간회고.md`](./AI중간회고.md)의 주장을 실제 코드와 전수 대조한 결과.
> 구조 정본은 [`agent-structure-current.md`](./agent-structure-current.md) 참조.

## 종합 결론

**중간회고의 핵심 주장들은 코드로 거의 전부 뒷받침된다.**
"판정은 코드, LLM은 입구(읽기)와 출구(말하기)만"이라는 원칙이 문서상 선언이 아니라
스키마·라우팅 표·폴백 구조로 실제 구현돼 있다. 다만 미세한 수치 불일치 3건이 있다
(→ [§2 불일치](#2-발견한-불일치-발표-전-정리-권장)).

### 1.1 하네스 7겹 코드 대응

| 겹 | 회고 표현 | 코드 실체 |
|---|---|---|
| ① | 출력 스키마 제약 | `nl_render.py:44-47` — `_Summary`는 summary 1필드, 판정 필드 자체가 없어 LLM이 판정을 바꿀 방법이 없음. `intent.py`의 IntentRead도 동일 전략 |
| ② | 도구 통제(제출 툴 미보유) | 제출 관련 툴이 코드베이스 어디에도 없음. 레지스트리(`agents/__init__.py:40-90`)에 등록된 이름만 호출 가능 |
| ③ | 재료 통제 | `coverletter_draft.py:50-79` `_collect_facts()` — 프로필 사실 문장만 조립(최대 20개). 프롬프트 규칙 + 스키마 3문단 제한 |
| ④ | 출력 검증 | `verify_rules.py` 4종: validate_schema / check_forbidden_lexicon / check_evidence_grounding(환각 근거 제거, 근거 전멸 시 met→uncertain 강등) / check_consistency. 자소서는 별도로 문장 단위 스킬 대조(`ungrounded_skill_removed`) |
| ⑤ | 제어 흐름 코드화 | 라우팅 표(`router.py`), 조건부 엣지 6개(`builder.py:43-89`), 재시도 예산 상수 3종(`nodes.py:65-66,93` — MAX_NODE_RETRY=2, MAX_VERIFY_RETRY=1, MAX_GEN_RETRY=1) |
| ⑥ | 실패의 정직한 처리 | None≠0.0이 `gap_matcher._weighted_score()`(판정 없으면 None) → `experience_estimator`(결측 시 totalMonths=None) → `rule_extractor`(연차 미상 None) → `overall_fit()`(전멸 시 "판정불가")까지 관통 |
| ⑦ | 인간 게이트 + 가시화 | 자소서 status 항상 `"draft_pending_review"`(`coverletter_draft.py:203`). ChatResponse가 intent/dispatched 노출 — 오라우팅을 사용자가 정정 가능 |

## 2. 발견한 불일치 (발표 전 정리 권장)

1. **"50% 초과" vs 코드의 `>= 0.5`** — `sufficiency_rules.py:131`은 50% **이상**(경계 포함).
   질문이 들어오면 걸릴 수 있는 차이이므로 문서를 "50% 이상"으로 통일 권장.
2. **테스트 수치 3곳 불일치** — README.md 133건 / 중간회고·current 문서 144건 /
   실제 코드 함수 162개(수집 케이스 ~190). README가 가장 뒤처짐 → 갱신 권장.
3. **"판정 계층 0초대" 표현 주의** — 결정론 노드 자체는 맞지만, gap_matcher의
   2·3차 캐스케이드가 LLM 의미판정(센서)을 부르는 경로가 있음(배치+캐시로 완화).
   "판정 계층에 LLM이 전혀 없다"로 발표하면 반례가 됨. 회고 §3.1의 "센서 역할"
   표현을 그대로 유지하는 것이 정확.

## 3. 코드에서 확인한 구조적 강점 (회고가 덜 강조한 것)

- **금지표현 사전의 단일 출처화** — `verify_rules.FORBIDDEN_EXPRESSIONS`를
  런타임 게이트 · nl_render 재검증(`nl_render.py:50,142-149`) · eval 지표(`metrics.py:14`)가
  모두 재사용. 지표와 게이트가 다른 사전을 쓰는 불일치를 원천 차단.
- **세션 캐시 무효화** — 이력서 갱신 시 profile/analysis 파생 자산 자동 폐기,
  공고 갱신 시 analysis 폐기(`orchestrator/chat.py:23-36`). 재사용 주장(§3.6)에서
  흔히 빠지는 stale 캐시 문제를 이미 처리.
- **GMS structured output 버그 우회** — langchain-openai ≥0.3의 json_schema strict
  모드가 기본값 있는 필드를 거부하는 문제를 `method="function_calling"` 강제로 방어
  (`structured.py:76-82`). "실측 기반 의사결정"(§5-5)의 또 다른 사례.
- **semantic_judge 배치 캐시** — 내용 전체를 키로 한 프로세스 캐시(`semantic_judge.py:50,77-80`).
  check_sufficiency와 analyze_gap이 같은 조합으로 두 번 호출해도 두 번째는 LLM 없이 종료.
- **시드 규모 실측** — skill_taxonomy **72개**(회고 "70여 개"와 일치) · cert_db 13 ·
  project_template 11 · role_taxonomy 12 · career_graph 12 · skill_to_cert 15.
  전부 `lru_cache` + "운영 시 외부 DB 교체해도 노드 불변" 구조.

## 4. 개선 방향(회고 §6)의 코드상 타당성

단기 4건은 전제 자산이 코드에 이미 있어 즉시 착수 가능:

| 개선안 | 전제 자산 확인 |
|---|---|
| 의도분류 평가셋 | 키워드 정규식 폴백(`intent.py:59-75`)이 있어 회귀 기준선 잡기 쉬움 |
| nl_render 실측 | 유일한 미측정 LLM 지점 맞음. 결정론 폴백(`_deterministic_summary`)이 이미 있어 "느리면 결정론 기본 + LLM 비동기" 전환 용이 |
| parse ∥ profile 병렬화 | 두 노드 데이터 의존성 없음 확인. START에서 fan-out + join으로 전환 가능 |
| 진행 상태 스트리밍 | `Status` 9종 상태 코드 이미 정의·각 노드가 갱신 중 |

중기의 checkpointer 전환도 세션 저장소가 "LangGraph checkpointer와는 별개"라고
docstring(`session.py:4`)에 명시된 상태라 마이그레이션 경계가 깨끗함.

## 5. 한 줄 평

회고의 **"금지는 프롬프트가 아니라 구조로"** 라는 문장이 과장이 아니라는 것이
코드의 가장 큰 강점이다 — 판단 필드가 없는 스키마, 제출 툴 미보유, None≠0.0,
단일 출처 금지사전이 전부 실물로 존재한다. 발표 전 [§2](#2-발견한-불일치-발표-전-정리-권장)의
불일치 3건(경계값 표현·테스트 수치·판정 계층 내 LLM 센서)만 정리하면
문서와 코드가 완전히 맞아떨어진다.
