# AI 에이전트 구현 작업 로그 (0721)

이 문서는 `skill_taxonomy` 의 **동의어 매칭을 "표기 변형 정규화" 방식으로 리팩터링**한
내역을 정리한다. 기존엔 "React.js"/"React JS"/"ReactJS" 같은 구분자·띄어쓰기 변형을
`aliases` 에 일일이 나열해야 했는데, 이를 **조회 시 구분자 제거 + 원문 검색 시 구분자 유연
매칭**으로 흡수하도록 바꿔, 별칭 나열 부담을 줄이고 놓치던 변형까지 잡히게 했다.

> **핵심 성과**: 표기 변형(대소문자·점·공백·하이픈·언더스코어)이 결정론 룰로 자동 흡수된다.
> `aliases` 에는 이제 **글자 구성 자체가 다른 표기**(리액트/React 같은 한글·영문)만 등록하면
> 된다. 특수문자가 이름의 일부인 `C++`·`C#` 은 정규화에서 제외해 서로 다른 언어가 뭉개지지
> 않게 했다. 전체 회귀 테스트 133건 통과.

## 2. 문제 — 표기 변형을 손으로 나열하고 있었다

`skill_taxonomy` 의 동의어 흡수에는 두 층이 있었다.

- **자동(정규화)**: 대소문자·앞뒤 공백만. 모든 경로의 `.strip().lower()`.
- **수동(aliases)**: 그 외 모든 표기. `_SKILLS` 사전에 손으로 등록.

문제는 **"구분자만 다른 변형"** 이 수동 영역에 남아 있었다는 것이다.

- `"React.js"` 와 `"ReactJS"` 는 서로 다른 dict 키였다 — 둘 다 등록해야 둘 다 잡혔다.
- 그래서 `node` 는 `("NodeJS", "Node.JS", "노드js", "노드 js")`, `spring-boot` 는
  `("스프링부트", "스프링 부트", "SpringBoot")` 처럼 같은 스킬의 표기 변형을 나열하고 있었다.
- 나열에서 빠진 변형(예: 사용자가 "react js" 라고 띄어 쓰면)은 dict 조회에서 **그냥 놓쳤다.**

---

## 3. 해결 — 구분자를 정규화로 흡수

### 3.1 `_normalize_key()` 신설 — 조회용 표준 키

소문자화에 더해 **구분자(`.`, 공백, `-`, `_`)를 제거**한 키로 조회한다.

```python
_SEPARATORS = re.compile(r"[.\s\-_]+")

def _normalize_key(text: str) -> str:
    return _SEPARATORS.sub("", (text or "").strip().lower())
```

- `_alias_index()` 의 키 생성과 `resolve()` 의 조회 **양쪽**에서 이 함수를 쓴다. 그래서
  `"React.js"` / `"React JS"` / `"ReactJS"` / `"react-js"` 가 전부 키 `"reactjs"` 하나로 모인다.
- `find_in_text()` 의 매칭 후 조회도 `_normalize_key(match.group(0))` 로 통일.

**특수문자 제외**: `'+'`·`'#'` 은 구분자 집합에서 뺐다. `C++`(`c++`)·`C#`(`c#`) 처럼 이름의
일부라, 지우면 `C`/`C++`/`C#` 이 같은 키로 뭉개진다.

### 3.2 `_flexible()` 신설 — 원문 검색의 구분자 유연 매칭

dict 조회만 고치면 `find_in_text`(원문 스캔)는 여전히 등록 문자열 그대로만 잡는다. 정규식
쪽도 구분자를 유연하게 만들었다.

```python
def _flexible(alias: str) -> str:
    parts = [re.escape(p) for p in _SEPARATORS.split(alias) if p]
    return r"[.\s\-_]*".join(parts)   # "Node.js" -> Node[.\s\-_]*js
```

- 별칭 안의 구분자를 **0개 이상 허용**(`*`)으로 바꾼다. 그래서 등록 별칭 `"Node.js"` 하나가
  원문의 `"Node js"` / `"NodeJS"` / `"Node-js"` / `"Nodejs"` 를 전부 잡는다.
- `_search_pattern()` 은 이제 정규화된 인덱스가 아니라 **원본 별칭 문자열**(`_SKILLS`)에서
  패턴을 만든다(구분자 정보가 필요하므로). 긴 별칭 우선 정렬·경계 lookaround(`[A-Za-z0-9+#]`)는
  그대로 유지.

### 3.3 중복 별칭 정리 — 나열 부담 감소(리팩터링의 실제 payoff)

정규화·유연 매칭이 흡수하는 변형은 사전에서 뺐다. 대표형 하나만 남긴다.

| 스킬 | 변경 전 aliases | 변경 후 |
|---|---|---|
| node | `NodeJS, Node.JS, 노드js, 노드 js` | `노드 js` |
| react | `ReactJS, React.js, 리액트` | `React.js, 리액트` |
| express | `ExpressJS, Express.js` | `Express.js` |
| spring-boot | `스프링부트, 스프링 부트, SpringBoot` | `스프링 부트` |
| c | `C언어, C 언어` | `C 언어` |

> 남긴 별칭 선택 기준: **구분자를 품은 대표형**을 남긴다("노드 js" 를 남기면 유연 매칭이
> "노드js" 까지 커버). 반대로 붙여 쓴 형태만 남기면 띄어 쓴 변형을 못 잡는다.

## 4. 검증

- `tests/test_taxonomy.py` 18건 통과.
- 전체 회귀 **133건 통과**(gap_matcher·nodes·rule_extractor 등 taxonomy 소비처 포함).
- 수동 확인:
  - `resolve` — `"React JS"`/`"react.js"`/`"REACTJS"`/`"react-js"` → 모두 **React**
  - `"노드 js"`/`"NodeJS"` → **Node.js**, `"스프링부트"`/`"Spring Boot"` → **Spring Boot**
  - `"C++"` → **C++**, `"C#"` → **C#**(특수문자 보존 확인)
  - `find_in_text("... React JS 와 Spring Boot, node js ... C++/C# 도.")`
    → `['React', 'Spring Boot', 'Node.js', 'C++']`

> **참고(설계 유지)**: `find_in_text` 는 2글자 이하 ASCII 별칭(`C`, `Go`, `C#`)을 여전히
> 원문 스캔에서 제외한다(짧은 영문 오탐 방지, 모듈 docstring '한계' 참고). `C#` 이 위
> 결과에 안 잡힌 건 이 기존 정책 그대로이며, `resolve("C#")` 은 정상 동작한다.
