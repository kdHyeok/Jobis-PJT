## 2. 흐름 하드코딩 제거 — 추론은 자율, 하네스는 코드

**문제**: (의도 라벨 × 보유 자산) 대응표와 자산별 강등 규칙이 흐름을 코드에 박아 둬서,
발화 문장이 조금만 달라져도 어긋나고 에이전트가 늘 때마다 표가 곱으로 커졌다.

**구조 확정** (서비스 핵심 원칙):
- **그라운딩**: `agent_feasibility()` 가 지금 각 에이전트의 실행 가능 여부(불가면 결측
  자산)를 계산해 플래너 프롬프트에 강제 주입. 세션 자산·최근 대화·**이번 턴 제출 자료
  종류**(`_submittedThisTurn`)도 함께 — 첨부만 온 턴에 플래너가 이력서/공고를 구분 못
  하던 오선택의 원인이었다.
- **액션 스페이스 제한**: 플래너 출력은 레지스트리 등록 에이전트 이름뿐(스키마 Literal).
  상태 전이는 `outcome.sessionUpdates` 로만.
- **사후 검증**: `validate_plan` 은 전제 확인·생산자 삽입·실행 불가 제거만 — **무엇으로
  대신할지는 정하지 않는다**. 남는 게 없으면 대화형 에이전트가 턴을 받는다(고정 문구로
  대화를 끝내지 않음). 문장은 금지표현 검증.
- 브릿지의 합성 발화도 중립화("이력서를 드렸어요. **이어서 진행해 주세요**") — 다음
  단계를 지시하던 문구 제거.

**과정에서 잡은 실버그**: `AgentPlan.confidence` 에 description 이 없어 모델이 0.0 을
채웠고, 자기가 고른 계획이 임계값에서 잘려 나갔다(이력서를 냈는데 분석이 안 돌던 원인).
스키마 필드 description = 지시문이라는 0724 교훈의 재확인.

## 4. LLM 공급자 claude_code — 팀 플랜으로 무과금 개발 반복

GMS(gpt-4.1-mini, 토큰 과금) 외에 **개발 머신에 로그인된 Claude 팀 플랜의 Claude Code
CLI**(`claude -p` headless)로 모든 호출을 돌리는 옵션. 모든 LLM 호출이
`run_structured → get_llm()` 단일 통로라 어댑터 하나로 전체 커버.
- 스키마를 프롬프트에 실어 지시 + pydantic 검증, 실패는 예외 → 기존 재시도·trace 적용.
- 레포 밖(cwd=tmp)에서 실행 + `--strict-mcp-config` — 프로젝트 설정 오염 방지·기동 단축.
- 실측: 구조화 추출 sonnet 5.0s / haiku 4.5s, 대화 한 턴 ~10s.
- 한계 명시: 로그인된 개발 머신 전용(서버 배포는 openai/anthropic), 임베딩은 GMS 잔존.
- 성능: preference_intake 의 선호 읽기+행동 선택을 한 호출로 병합 — 첫 발화 28s→9.8s.

## 5. 연차 판정 불일치 수정 — "신입이 '2년 이상' 충족" 오판 제거

**원인**: 룰이 정확히 뽑은 `minYears=2` 를 5칸 사다리(junior)로 뭉갠 뒤 버려서, 0년과
2년이 같은 칸에서 충돌(칸 비교 → met)하고 라벨 "주니어 신입"이 공고에 없는 단어를 냈다.

- `minYears`·`yearsEvidence`(원문 조각) 를 posting 에 보존, 합성 연차 요건에 실음.
- 판정: 숫자가 있으면 **연차 대 연차**(부족분을 개월로 서술), 칸 비교는 키워드만 있는
  공고의 폴백으로 강등.
- 표기: 공고가 한 말(yearsEvidence) 그대로 우선. "신입" 같은 공고에 없는 단어 근절.
- **중복 판정 제거**: 순수 연차 줄이 텍스트 의미판정(충족)과 연차 룰(미충족) 양쪽에서
  다르게 판정되어 요약이 자기모순이 되던 문제 — 연차 줄은 합성 요건이 단독 담당
  (기술 토큰 있는 줄은 유지). 회귀 테스트 4건.

## 6. 대화 페이지(ask.html) UX — 항목화·스트리밍·판정 가시화

- **우측 패널 3카드**: 공고 요건 정리(필수/우대/기술/도메인·요구 연차) / 내 이력서
  정리(스킬·프로젝트·경력·학력·자격·어학·근거 수) / **판정 근거**(등급·가중 점수,
  카테고리별 점수(가중치), 요건별 상태 배지 + 판정 방법(정확 매칭·의미 판정(LLM)·연차
  룰) + 사유). 데이터는 판정 엔진 trace(judgment/score)를 `/chat context` 로 승격 —
  항목 추출은 WS 경로(JOB_CONTEXT/PROFILE_CONTEXT)와 같은 코드 공유, 세션 캐시로
  새로고침에도 유지.
- **실시간 진행 스트리밍**: 브릿지 `/chat/stream`(SSE) → 백엔드 `/api/chat/stream`
  프록시 → fetch 스트림. 판정 10노드가 "채용공고 구조화 완료 → … → 최종 결과 조립"으로
  흐른다. 문구는 에이전트 라벨·노드 toolLog 만(지어내지 않음). trace 중첩 시 안쪽
  레코더가 이벤트를 독점하던 버그를 부모 체이닝으로 수정.
- **자료 제출 턴 흐름**: 제출 → 정리·항목화 → "진단해볼까요?" 확인 → 동의 시 판정 →
  다음 행동(로드맵·자소서·면접·대안) 제안. 이력서 정리 뒤 **빈 섹션 보완 카드** —
  칩 클릭 입력(`resume_extra` 첨부: 기존 이력서에 **덧붙임**, 교체 아님) 후 분석 or
  "이대로 분석 진행하기".
- **표시**: 답변 항목 라벨(**필수 요건** 등) red 굵게, 판정어 컬러 룰(충족=초록/부분=
  주황/미충족=빨강/수치=브랜드색), 말풍선 전송 시각(복원은 DB createdAt).
- 답변에 **적합도 등급 {상/중/하}(가중 점수 N)** 를 결정론으로 명시 — 등급을 문장
  뉘앙스로 추측하게 하지 않는다.
