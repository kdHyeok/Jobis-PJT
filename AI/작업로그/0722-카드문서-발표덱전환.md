# AI 에이전트 구현 작업 로그 (0722 — 에이전트 카드 문서의 16:9 발표 덱 전환)

이 문서는 전날 만든 에이전트 카드 HTML(`agent__visual/jobis-agent-cards.html`)을
**PPT에 그대로 넣을 수 있는 가로형(16:9) 슬라이드 덱**으로 재구성한 작업을 정리한다.
`0721-에이전트시각화-발표자료.md` 의 후속 작업이며 `src/` 코드 변경은 없다.

> **핵심 성과**: 세로로 긴 스크롤 문서를 **1600×900 슬라이드 7장**으로 재편하고,
> 세로쓰기(회전) 텍스트를 전부 제거했으며, 흐름도를 **좌→우 2단 가로 배치**로 다시 그렸다.
> 브라우저 인쇄만으로 **슬라이드 1장 = 페이지 1장(16:9) PDF** 가 떨어진다.

## 3. 흐름도 재작도 — 이번 작업의 본체

### 3.1 세로 1열 → 가로 2단

기존은 `viewBox 940×950` 의 **세로 1열** 배치라 가로 슬라이드에 넣으면 좌우가 텅 비고
글자는 읽을 수 없게 작아진다. `viewBox 1440×450`(비율 3.2:1)의 **2단 좌→우** 배치로 바꿨다.

| 단 | 노드 | 성격 |
|---|---|---|
| 윗줄 | `__start__` → 1 parse → 2 profile → 3 completeness → 4 sufficiency → 5 ask_user | 입력 정형화와 게이트 |
| 아랫줄 | 6 analyze_gap → 7 plan_roadmap → 8 find_alternatives → 9 verify → 10 assemble → `__end__` | 판정 · 계획 · 검수 · 응답 |

두 단은 `check_sufficiency` 하단에서 좌측으로 감아 내려오는 **줄바꿈 엣지**("정보 충분 →
갭 분석으로")로 연결된다. 텍스트가 줄바꿈되는 것과 같은 읽기 순서라 별도 설명 없이 따라온다.

**대안으로 검토했다 버린 것**: 10개 노드를 1행으로 늘어놓는 안. `viewBox` 폭이 2,000px을
넘어가 슬라이드에 맞추면 라벨이 10px 이하로 떨어진다. 2단이 가독성에서 명확히 앞선다.

### 3.2 회전 텍스트 4곳 제거 — "텍스트 방향" 요구의 실체

기존 흐름도에는 `transform="rotate(-90 …)"` 라벨이 4개 있었다. 세로 레이아웃에서 폭이
모자라 세로쓰기로 밀어 넣은 것들이다. 슬라이드에서는 **읽으려고 고개를 돌려야 하는 요소**라
전부 가로로 다시 앉혔다.

| 회전 라벨(기존) | 이번 처리 |
|---|---|
| 적합도 상 · 로드맵 생략 | 아랫줄 위쪽 **건너뛰기 아크** 위에 가로 배치 |
| 검증 실패 → 재분석 (1회) | 아랫줄 아래 **되돌림 엣지** 위에 가로 배치 |
| 생성 실패 재지시 ×2 | 노드 1·2 상단 **자기 루프** 위에 가로 배치 |

라벨은 `paint-order: stroke` + 흰색 6px 외곽선으로 엣지 선 위에 얹어도 읽히게 했다.

### 3.3 판독성 개선

- **노드 번호**: 박스 밖 작은 회색 숫자 → 좌상단 **계층색 원형 배지 + 흰 숫자**
- **LLM 표시**: 지름 3.5px 점(●) → **`LLM` 알약 배지**. 점은 프로젝터에서 사라지고,
  범례를 봐야 뜻을 알 수 있었다. 알약은 그 자체로 읽힌다
- **단계 라벨** 추가: "1단계 · 읽기와 게이트" / "2단계 · 판정 · 계획 · 검수 · 응답"
- **분기 라벨을 문장으로**: `적합도 상 + 대안요청` → `적합도 상 + 대안 요청 → 로드맵 생략`

### 3.4 작도 중 발견·수정한 오류

아랫줄 건너뛰기 아크 3개를 그리면서 `route_after_roadmap` 경로의 라벨을
`적합도 상 · 대안 없음` 으로 잘못 달았다. 이 엣지는 **plan_roadmap 을 거친 뒤**의 분기이므로
정의상 적합도 상이 될 수 없다(상이면 로드맵을 건너뛴다). `대안 요청 없음 → 대안 생략` 으로
정정했다. 라우터 표(§슬라이드 5)의 서술과 대조하다 걸렀다.

## 4. 타이포그래피 · 색

- **본문**: `Pretendard Variable` → `Pretendard` → `Inter` → `Segoe UI Variable Text` →
  `Segoe UI` → `Malgun Gothic`. Pretendard는 jsDelivr CDN에서 동적 서브셋으로 로드하고,
  오프라인이면 시스템 폰트로 자연 폴백된다
- **코드/키**: `JetBrains Mono` → `Cascadia Code` → `SF Mono` → Consolas
- `word-break: keep-all` — 한글이 단어 중간에서 끊기지 않게. 좁은 5열 카드에서 특히 유효
- **다크 모드 제거** — 인쇄·캡처 전제라 라이트 고정. 기존의 `prefers-color-scheme` /
  `data-theme` 3중 정의(약 30줄)를 걷어냈다. 대비를 위해 계층색을 약간 어둡게 조정
  (읽기 `#A9660A`→`#A05C00`, 판단 `#0E7C6E`→`#06705F`, 말하기 `#6142B0`→`#5636A8`)

**라우터 수 정정**: 기존 문서 머리말은 "6 routers"였으나 표에 실제로 적힌 라우터는
`route_after_parse / after_profile / after_alternatives`(동일 로직 3개), `route_sufficiency`,
`route_after_gap`, `route_after_roadmap`, `route_verification` 이다. 표 행 수 기준
**5개**로 표기를 맞췄다. (실제 함수 개수와의 대조는 미확인 — §7 참조)

## 6. 카드 밀도 조정 — 잘라낸 것

5열 배치로 카드 폭이 약 285px가 되면서, IN/OUT의 긴 필드 나열을 그대로 두면 세로로
늘어져 읽히지 않는다. **OUT 필드 목록을 핵심 키 위주로 축약**했다.

| 카드 | 잘라낸 것 |
|---|---|
| 01 parse | jobTitle · companyName · domainKeywords 등 |
| 02 profile | 항목별 세부 스키마 → 상위 배열명만 |
| 06 gap | requirementStatus 내부 필드(matchedEvidenceIds · reason · confidence) |
| 09 verify | violation 항목의 detail |

전체 필드 목록이 필요하면 이전 판(`git show aff8e16:agent__visual/jobis-agent-cards.html`)
또는 `contracts/domain.py` 를 본다. **발표용 요약본이지 계약 문서가 아니다**는 게 이번
판의 성격이다 — 계약 정본은 코드와 `jobis-agent-graph.html` 쪽에 둔다.

## 7. 결정 사항 · 미확인

- **파일 병존 구조가 3중이 됐다**: 표 중심판(`jobis-agent-graph.html`) / 카드판·발표용
  (`jobis-agent-cards.html`) / 요약(`중간발표-요약.md`). 구조가 바뀌면 **세 곳 다** 갱신해야
  한다. `README.md` 부록의 설명은 아직 "카드판 = 상세 문서" 기준이라 **갱신 필요**
- **렌더링 육안 검증 미완료** — 이번엔 헤드리스 캡처를 돌리지 않고 브라우저로 열어만 뒀다.
  전날 작업에서 칩 오버플로가 그렇게 걸린 전례가 있으므로, 발표 전
  **흐름도 라벨-엣지 겹침**과 **5열 카드 하단 넘침**을 눈으로 확인할 것
- 슬라이드 05의 "라우터 5개"가 `nodes.py` 의 실제 라우터 함수 개수와 일치하는지 미대조
- 전날 기록한 미해결 코드 이슈는 이번에도 손대지 않음:
  `nodes.py:1231` `pathComparison` 미반환, `MAX_NODE_RETRY` 미사용, RAG 훅 2곳 미연결
- 발표 자료 숫자(테스트 144건 / 1.8초 / LLM 3회)는 **2026-07-21 기준 실측치**. 재확인 권장
