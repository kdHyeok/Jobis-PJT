# AI 에이전트 구현 작업 로그 (0721 — 에이전트 시각화 · 중간발표 자료)

이 문서는 에이전트 구조를 **에이전트별 카드 형태로 시각화**하고, 그 내용을 **중간발표용
슬라이드 2장 분량**으로 압축한 작업 내역을 정리한다. 같은 날 앞선 작업
(`0721.md` skill_taxonomy 리팩터링, `0721-적합도등급분기.md` 등급 분기)과는 별개의
**문서·산출물 작업**이며 `src/` 코드 변경은 없다.

> **핵심 성과**: 노드 10개에 각각 전용 SVG 일러스트를 부여한 단일 HTML 문서를 만들고,
> 발표에서 쓸 **구조 명명(naming)을 코드 근거로 확정**했다 —
> "멀티/오케스트레이터"가 아니라 **"챗봇이 아닌 에이전트 구조"** 로 어필한다.
> 발표 어필 축은 **"판단을 LLM이 아니라 파이썬으로 구현한 이유와 효과"** 로 잡았다.

## 2. 에이전트 카드 HTML 제작

### 2.1 방식 결정

에이전트마다 "이미지"를 부여하는 방법으로 세 가지를 검토하고 **전용 인라인 SVG**를 택했다.

| 방식 | 채택 | 사유 |
|---|---|---|
| **인라인 SVG 일러스트** | ✅ | 라이트/다크 테마 자동 대응, 확대해도 선명, 외부 요청 0, 파일 가벼움 |
| AI 생성 일러스트(base64) | ✕ | 파일 수 MB, 생성 시간, 텍스트 왜곡 위험 |
| 이모지 + 기하학 배지 | ✕ | "이미지"라기엔 약함 |

기존 `jobis-agent-graph.html` 은 **그대로 두고 새 파일로 제작**했다(표 중심판 / 카드판 병존).

### 2.2 구성

- **아이콘 스프라이트** — 노드 10개의 성격을 그림으로 옮긴 `<symbol>` 을 문서 상단에 정의하고
  `<use>` 로 재사용. 흐름도와 카드가 **같은 아이콘**을 공유해 지도-카드가 눈으로 이어진다.
  - parse=문서→표 · profile=사람+근거카드 · completeness=체크리스트(미기입 칸) ·
    sufficiency=판정 게이지 · ask=물음표 말풍선 · gap=요구/보유 막대의 갭 ·
    roadmap=간트 · alt=경로 분기 · verify=방패+체크 · assemble=문서 겹침→최종본
- **01 전체 그래프** — 기존 흐름도에 아이콘·번호를 삽입
- **02 에이전트 카드** — 노드당 카드 1장(일러스트 타일 / 계층·LLM 배지 / 역할 / 툴 칩 / IN·OUT 계약)
- **03 라우터 · 04 툴 카탈로그 · 05 GraphState**
  - 툴 카탈로그의 "쓰는 노드" 칸은 텍스트 대신 **해당 에이전트 아이콘을 나열** — 툴 하나가
    어느 에이전트에 걸쳐 있는지 한눈에 보인다

계층 색(읽기 주황 / 판단 청록 / 말하기 보라)을 아이콘·카드 테두리·타일 배경·칩까지 일관 적용.

### 2.3 검증

헤드리스 Chrome(`--screenshot`)으로 전체 페이지를 렌더해 육안 확인했다.

- 태그 균형 검사(HTMLParser) 통과
- **발견·수정**: 카드 08의 `pathComparison` 경고 칩이 `white-space:nowrap` 때문에 카드
  밖으로 넘침 → `.chip.wrap` 추가해 줄바꿈 허용, 재렌더로 확인

## 3. 중간발표 자료 — 압축과 메시지 설계

`중간발표-요약.md` 에 **슬라이드 2장** 분량으로 정리했다(발표 전체가 아닌 일부 파트).
초안은 6장이었으나 "최대 2장" 제약에 맞춰 재구성했다.

### 3.1 잘라낸 것과 이유

| 잘라낸 것 | 이유 |
|---|---|
| 라우터 6개 상세 | 흐름도가 안 읽힘. 분기 3개만 남김 |
| 신뢰성 장치 5종 슬라이드 | 핵심(근거 ID 관통)만 본문에 녹임 |
| 에이전트 10개 개별 나열 | 계층 단위 3행으로 묶음 — 기억할 건 이름이 아니라 구조 |
| 툴 17종 카탈로그 | 질문 나오면 답할 거리로 부록 이동 |

### 3.2 어필 축 전환

처음엔 "구조 설명" 중심이었으나, **"LLM에 다양한 일을 맡기지 않고 순수 파이썬으로 구현한
이유와 효과"** 를 전면에 세우는 구성으로 바꿨다.

- 슬라이드 2를 **좌우 대비표**로: `LLM에 맡겼다면` ↔ `파이썬으로 얻은 것`
  (재현성 · 근거 추적 · 환각 차단 · 자동 검증 · 수정 가능)
- **실측 숫자 확보** — 발표에서 그대로 말할 수 있도록 `pytest tests/` 실행해 확인

| 지표 | 값 |
|---|---|
| 전체 회귀 테스트 | **144개 통과 / 1.8초 / API 비용 0원** |
| 요청당 LLM 호출 | 3회 고정 (재시도 포함 최대 5회) |
| 판정 로직 결정론 비율 | 100% |

> "테스트 1.8초"가 가장 강한 근거다. **판정이 결정론이라 LLM 없이 전 구간을 검증할 수
> 있다**는 뜻이고, "그래서 그게 왜 좋은데?"에 즉답이 된다.

- 마무리 문장을 방어에서 공격으로: **"LLM을 안 쓴 게 아니라, 쓸 자리를 골랐다."**

## 4. 구조 명명(naming) — 코드로 확정한 것

발표에서 이 시스템을 뭐라 부를지 정리했다. 코드를 확인해 근거를 잡았다.

### 4.1 오케스트레이터(supervisor) 구조가 **아니다** — 확인됨

`nodes.py` 의 라우터 6개는 전부 **상태를 읽는 순수 파이썬 `if` 문**이다. LLM 호출도 판단도 없다.

```python
def route_after_gap(state):
    if _fit_grade(state) == "상":
        return "find_alternatives" if state.get("includeAlternatives") else "verify_result"
    return "plan_roadmap"
```

→ 다음 단계를 LLM이 정하지 않는다. **분기 조건이 그래프에 명시된 상태 머신.**
질문이 오면 "몰라서 안 쓴 게 아니라 **의도적으로 안 썼다** — 경로가 매번 달라지면 진단을
재현할 수 없다"로 답한다.

### 4.2 "멀티"는 빼고, **"챗봇이 아닌 에이전트"** 로 간다

명명 후보를 좁힌 과정:

| 후보 | 판단 |
|---|---|
| 멀티 에이전트 | ✕ 빼기로 결정 |
| 오케스트레이터/supervisor | ✕ 사실과 다름 (§4.1) |
| **AI 에이전트 구조 (vs LLM 챗봇)** | ✅ 채택 |

**초기 우려와 그 해소** — "에이전트가 판단하지 않는다"고 말하면서 "에이전트"라 부르면
모순처럼 들린다는 문제가 있었다. 해소 논리는 한 줄이다.

> **에이전트 ≠ LLM.** 에이전트가 판단을 안 하는 게 아니라,
> **판단을 LLM이 아니라 알고리즘으로** 한다.

### 4.3 "챗봇이 아니라 에이전트"의 코드 근거

발표 대비표의 5행은 전부 실제 구현에 대응한다 — 반박당하지 않게 근거를 붙여 둔다.

| 주장 | 코드 근거 |
|---|---|
| 10단계 자율 실행 | `builder.py` 노드 10 + 조건부 엣지 |
| **도구를 상황에 따라 선택** | `plan_roadmap`: 자격증 DB 없으면 과제 템플릿 / `analyze_gap`: 회사명 없으면 RAG 스킵 |
| **스스로 검수하고 재분석** | `verify_result` → `route_verification` 재시도 루프 |
| **정보 부족 시 되묻는다** | `check_sufficiency` 게이트 → `ask_user` |
| 구조화된 산출물 | `AnalyzeResponse` 계약 |
| 파이프라인이 아님 | 되돌아가는 엣지 존재 — **DAG가 아닌 순환 그래프** |
