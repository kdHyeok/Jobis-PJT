# AI 에이전트 구현 작업 로그 (0721 — 종합 적합도 등급 분기)

이 문서는 갭 분석 결과에 **종합 적합도 등급(상/중/하/판정불가)** 을 도입하고, 그 등급에 따라
**진단·로드맵·대안 공고 제공을 분기**한 작업 내역을 정리한다. 같은 날 앞선
`skill_taxonomy` 리팩터링(`작업로그/0721.md`)과는 별개 작업이다.

> **핵심 성과**: `scoreBasis`(카테고리별 점수)를 가중 평균해 종합 등급을 매기고,
> **상이면 진단만, 중·하면 진단 + 로드맵 + 대안 공고**까지 제공하도록 파이프라인을 분기했다.
> 그 전제로 그동안 항상 `None` 이던 `roleRelevance`/`domainFit` 점수도 실제로 계산되게 했다.
> **"합격 예측 안 함" 원칙은 유지** — 상 등급도 "합격"이 아니라 "요구 역량 충족" 으로만 말한다.
> 전체 회귀 테스트 144건 통과.

## 2. 선행 — 그동안 `None` 이던 두 점수를 실제로 계산

등급을 매기려면 카테고리 점수가 있어야 하는데, `roleRelevance`/`domainFit` 은 `_score_basis`
에서 **무조건 `None`** 으로 하드코딩돼 있었다("계산 근거 없음 — 지어내지 않는다"). 그런데
매칭 신호는 이미 `match()` 안에 있었고(`domain_keyword`·`seniority` 요구사항) 단지
집계에서 안 쓰였을 뿐이다.

- `Match` 에 **`kind` 필드**(`text`|`domain_keyword`|`seniority`)를 추가해 요구사항 카테고리를
  판정 결과까지 보존. `method`(어떻게 판정했나)와는 다른 축이다.
- `_score_basis` 가 `kind` 로 분류: `domain_keyword` → `domainFit`, `seniority` → `roleRelevance`
  를 `_weighted_score` 로 집계. **해당 매칭이 없으면 여전히 `None`**(근거 없으면 지어내지 않는
  원칙 유지). 이 매칭들이 `techSkill`/`certLanguage` 로 새지 않도록 분류도 정리.

## 3. 종합 등급 산출 — `overall_fit()`

`gap_matcher.py` 에 신설. `scoreBasis`(dict)를 받아 `(종합 점수, 등급)` 을 돌려준다.

```python
_CATEGORY_WEIGHT = {          # 카테고리 상대 중요도 (합 1.0일 필요 없음 — 계산된 것만 정규화)
    "techSkill": 0.35, "projectExperience": 0.25,
    "roleRelevance": 0.15, "domainFit": 0.15, "certLanguage": 0.10,
}
_GRADE_HIGH, _GRADE_MID = 0.7, 0.4   # 상 ≥ 0.7 / 중 0.4~0.7 미만 / 하 < 0.4
```

- **계산된 카테고리만**(None 제외) 골라 가중 평균하고, 그 가중치 합으로 정규화한다.
  `_score_basis` 가 None 을 남기는 원칙과 동일 — 모르는 항목을 0점으로 깔지 않는다.
- 계산된 게 하나도 없으면 등급을 단정하지 않고 **`(None, "판정불가")`** 로 남긴다.
- 등급 경계는 사용자 결정(2026-07-21): 상 ≥ 0.7, 중 0.4~0.7, 하 < 0.4.

`analyze_gap` 노드가 이 함수로 등급을 계산해 `GapAnalysisResult.overallScore`/`fitGrade` 에
싣는다. 계약(`GapAnalysisResult`, `AnalyzeResponse`)에도 두 필드를 추가(기본값 있는 추가
필드라 기존 소비자 무시 가능).

## 4. 등급 기반 라우팅

| 등급 | 로드맵 | 대안 공고 | 경로 |
|---|---|---|---|
| 상 | ✕ (진단만) | 옵션 요청 시에만 | `route_after_gap` → `verify_result` (옵션 시 `find_alternatives`) |
| 중·하 | ○ | ○ (옵션 없이도) | `route_after_gap` → `plan_roadmap` → `find_alternatives` |
| 판정불가 | ○ | 옵션 시 | 중·하와 동일 경로(상이 아니면 로드맵) |

- `route_after_gap`: **상이면 로드맵을 건너뛴다.** 단 사용자가 `includeAlternatives` 를 명시
  요청했으면 대안은 존중해 보여준다(로드맵만 생략). → 옵션 계약도 유지하고 spec(상=로드맵
  없음)도 지키는 절충.
- `route_after_roadmap`: **중·하는 대안 공고까지** 제공(옵션 없이도). 기존 `includeAlternatives`
  옵션도 계속 존중.
- `builder.py`: `route_after_gap` 의 목적지에 `find_alternatives`/`verify_result` 추가.

## 5. 등급별 진단 문장 (`nl_render.py`)

'합격/불합격'을 말하지 않는다(설계 12.3-2, `FORBIDDEN_EXPRESSIONS`). 등급을 **충족도 언어**로
번역한다.

```python
_DIAGNOSIS_BY_GRADE = {
    "상": "핵심 요구 역량을 대부분 충족합니다. 지원에 충분한 경쟁력이 있습니다.",
    "중": "요구 역량을 부분적으로 충족합니다. 부족한 부분을 보완하면 경쟁력을 높일 수 있습니다.",
    "하": "요구 역량과 격차가 있어 준비가 필요합니다.",
}
```

- 결정론 요약과 LLM 요약 모두 **첫 문장**에 진단을 배치.
- LLM 에는 등급 라벨('상'/'판정불가')을 넘기지 않고 **자연어 진단 문장만** 넘긴다 — 라벨을
  그대로 읊으면 어색하기 때문. 판정불가/미설정이면 진단은 빈 문자열(생략).

## 7. 결정 사항·짚어둘 점

- **합격 예측 금지 원칙 유지**: 상 등급도 "합격 가능"이 아니라 "요구 역량 충족"으로만 표현.
  이 표현이 verify 의 금지 표현 검사도 통과한다.
- **상 + `includeAlternatives`**: spec("상=진단만")과 옵션 계약 충돌을 "로드맵은 생략, 명시
  요청한 대안은 제공"으로 절충. `includeAlternatives` 옵션은 사실상 상 등급에서만 유효한
  플래그가 됐다(중·하는 어차피 항상 대안 제공).
- 향후 재검토 여지: 등급 경계값·카테고리 가중치는 실측으로 조정 가능. `roleRelevance`/
  `domainFit` 이 실제로 계산되는 케이스가 늘면 종합 점수 분포를 보고 경계를 재보정.
