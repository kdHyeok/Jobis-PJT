# AI 에이전트 설계 작업 로그

이 문서는 `agent_tool_langchain_langgraph_plan.md`를 중심으로 진행한 에이전트 설계 작업 내역을 정리한다.

---

## 1. 작업 개요

| 항목 | 내용 |
|---|---|
| 대상 파일 | `기획/ai agent/agent_tool_langchain_langgraph_plan.md` |
| 기반 자료 | `회의록/20260712_취업준비_AI에이전트_회의정리_v0-1-1.md`, `회의록/0713_프로젝트_면담_정리.md` |
| 작업 성격 | 회의·면담 결정사항을 근거로 멀티에이전트/LangChain·LangGraph 설계 이어작성 |
| 부수 작업 | 최상위 `CLAUDE.md`(Git 협업 규칙) 작성 |

---

## 2. 작업 전 상태

설계 파일은 다음까지만 작성되어 있었다.

- 1~7장: 설계 방향, LangGraph/LangChain 역할 구분, 멀티에이전트 전체 구조, 공통 툴, 데이터 조회 우선순위, MVP 우선 에이전트
- 8장: Job Posting Parser의 LangChain 설계
- 9장: User Profile Builder의 LangChain 설계
- 10장: "다음 설계 순서"(예고만 존재) / 11장: 최종 한 줄 정리

즉 Gap Analyzer 이후 노드와 오케스트레이터, 운영·평가 설계가 비어 있는 상태였다.

---

## 3. 1차 이어작성 (핵심 노드 + 오케스트레이터)

예고 상태였던 10장을 실제 설계로 전개했다.

| 장 | 제목 | 핵심 내용 |
|---|---|---|
| 10 | Gap Analyzer LangChain 설계 | 요구사항↔evidence 매칭·충족 판정, 강점/gap 도출, 점수는 보조·근거 없으면 `null`, 우선순위 랭킹 |
| 11 | Roadmap Planner LangChain 설계 | 회의록 로드맵 최소 필드·JSON 예시를 스키마화, 기간/주당 시간 제약 반영, 캘린더 JSON 출력 |
| 12 | Result Verifier 검증 체인 | 스키마·금지표현·근거·정합성 검사, 표현 완화 또는 재시도 신호 |
| 13 | LangGraph 오케스트레이터 | 공유 State 스키마, 노드 구성, 충분성 분기·검증 재시도 루프·조건부 대체경로 엣지, 전체 그래프 흐름, MVP 범위 |

- 회의록 9.2 기본 흐름과 1:1 대응되도록 그래프를 구성.
- 표현 원칙(합격/불합격 단정 금지)을 Result Verifier가 게이트로 강제.

---

## 4. 2차 이어작성 (운영·계약·평가)

14장에서 예고된 5개 항목을 실제 설계로 전개했다.

| 장 | 제목 | 핵심 내용 |
|---|---|---|
| 14 | Alternative Path Finder (2차 우선순위) | 직접 경로 vs 대체 경로 비교, 저장벽 후보 필터·추천 근거, `pathComparison` 시각화 스키마 |
| 15 | GraphState 타입 명세 + 백엔드 계약 | `TypedDict` 상태(누적 필드 `Annotated[..., add]`), `POST /api/v1/analyze` 요청/응답 JSON 확정, `need_more_info` 재개 흐름, 계약 우선 병렬 개발 |
| 16 | failure_handler / retry_manager | 실패 3계층(툴/노드/검증), 재시도 상한·지수 백오프, fallback(URL→원문, 파일→직접입력), `meta.retriedNodes` 추적 |
| 17 | status 스트리밍 + 프론트 시각화 | 진행 문구→상태 코드 표준화, SSE 우선(→WebSocket 승격), `from→to` 핸드오프 이벤트로 에이전트 시각화 연동 |
| 18 | RAG·프롬프트 성능 평가 | 지표표(F1/Recall@k/Groundedness 등), 테스트 데이터셋 구성, 개선 전후 회귀 루프, 발표용 시각화 전제 |

- 19장 "다음 설계 순서", 20장 "최종 한 줄 정리"로 갱신.
- 면담에서 강조된 "성능을 지표로 반복 개선한 경험"을 평가 체계(18장)로 반영.

## 5. 부수 작업 — CLAUDE.md (Git 협업 규칙)

최상위 디렉토리에 `CLAUDE.md`를 작성. 개발자들이 가장 널리 쓰는 관례를 기준으로 구성했다.

- **브랜치 전략**: GitHub Flow (`main` + 짧은 수명의 작업 브랜치)
  - 초안은 Git Flow(`main`/`develop`)였으나, 팀 요청으로 GitHub Flow로 단순화.
- **커밋**: Conventional Commits (`feat`/`fix`/`docs`… + scope + 명령형 제목)
- **PR**: 작게 자주, 템플릿, 최소 1인 승인 + CI 통과, Squash and merge, 병합 후 브랜치 삭제
- **이슈 규칙 / 워크플로 요약 / 기본 수칙**(.env 커밋 금지, 공용 브랜치 force push 금지 등)
