## 1. AI (`AI/src/jobis_ai/`)

### P1. 선언된 `sourceType` 보다 본문 내용이 사실이다
- `orchestrator/attachment_kind.py` — **`is_bare_url(text)` 신설.** 본문이 URL 하나뿐인지 판별.
  같은 판별식이 네 곳에 흩어져 있었고(`v2bridge/service`·`webbridge/http_handlers`·
  `webbridge/runner`) 새 자리는 이 함수를 쓴다. (webbridge 는 폐기 예정이라 손대지 않았다 —
  복사본 두 개가 그쪽에 남아 있다.)
- `v2bridge/service.py:analyze` — `is_url_only` 를 본문 내용으로 판정. `sourceType=TEXT` 인데
  raw_text 가 주소 한 줄이면 URL 자산으로 넘겨 `posting_fetch` 가 수집한다.
- **고친 실패**: 주소 문자열을 공고 원문으로 파싱 → 요건 0건 → `fitGrade=판정불가` →
  `overallScore=None` → `verdict_from_plan` 이 `VerdictUndetermined` → 분석 전체 503.

### P2. 필수에 검증 가능한 역량이 없으면 우대에서 증명 대상을 잡는다
- `v2bridge/mapping.py:build_competency_proposal` — `provable`(=`roadmap_eligible ∧ REQUIRED`)이
  비면 `PREFERRED` 로 한 번 더 시도. 계약(`CompetencyProposal.validate_references`)은 relation 을
  보지 않으므로 안전하고, 지도에는 선택 퀘스트로 그려진다. 사유는 WARNING 으로 남긴다
  (`AnalysisResponse` 에 warnings 칸이 없어 로그가 유일한 자리다).
- **고친 실패**: 잡코리아 49692518 — 요건 13건 중 필수는 `학력: 대졸이상`(산문)과 `요구 연차`
  (검증 불가)뿐이고 기술은 전부 우대(techStack → preferred)여서 provable 이 ∅ → proposal None →
  503. 로드맵만 없는 게 아니라 **적합도 판정까지 버려졌다.**

### P3. 실패 사유가 백엔드 일반 문구에 덮이지 않게
- `v2bridge/service.py` — `EngineFailed(message, code=...)`. 새 코드
  `POSTING_TEXT_INSUFFICIENT`(= `service.POSTING_INSUFFICIENT`)를 두 실패 지점에 붙였다.
- `v2bridge/app.py` — `_run` 의 예외 → HTTP detail, 그리고 **스트림 `ERROR` 이벤트**(실제 경로)
  둘 다 `exc.code` 를 쓴다.
- 왜: 백엔드 `AnalysisWorker.safeMessage` 가 `AI_PROVIDER_UNAVAILABLE` 을 "AI 서비스 응답이
  지연되거나 중단되었습니다"로 덮어써서, 우리 사유가 DB·화면에서 사라지고 있지도 않은 장애가
  기록됐다. 코드를 갈면 그 함수가 예외 메시지를 그대로 저장한다.

### P4. 채팅은 로드맵을 읊지 않는다 (D142)
- `agents/tool_render.py:render_roadmap_manager` — 항목 나열과 "항목 수정이나 진척 체크 기능은
  준비 중이에요" 제거. 개수 + "로드맵은 커리어지도에 그려져요" 까지만. 지도의 상태를 모르므로
  "이미 그려져 있다"고 단정하지 않는다. `_MAX_ROADMAP_ITEMS_IN_REPLY` 상수 삭제(미사용).
- `v2bridge/mapping.py:_MAP_PRODUCERS` — `fit_analysis` 추가(적합도 판정 뒤가 지도로 갈 지점).
- 테스트 `test_agents_roster.py::test_roadmap_manager_reads_session_roadmap` 을 **반전**했다
  (§3-5 대로 지우지 않고 근거를 적어 뒤집음): 이제 제목이 **없어야** 한다.

### P5. 대화로 확보한 자산을 응답에 싣는다 (D141)
- `v2bridge/models.py` — `CollectedPosting`(sourceType·sourceUrl·rawText) ·
  `CollectedResume`(sourceType·title·rawText) · `CollectedAssets` 신설,
  `ChatResponse.collected` 추가.
- `v2bridge/service.py:_collected_assets` — 이 턴에 자산이 승격됐거나 `posting_fetch` 가 돈
  경우에만 싣는다. 주소만 남았으면(수집 실패) 싣지 않고, 백엔드가 보낸 확정 요약

  `AnalysisWorker.complete` 가 이미 그 열들을 채우는 유일한 writer 다. 두 writer 를 만들면
  언젠가 갈린다(이 저장소가 반복해서 치른 대가).

## 6. 후속 작업 (다음 세션이 이어서 할 것, 우선순위 순)

0. **PostgreSQL(55432)이 내려가 있다.** 도커 컨테이너(`compose.yaml` 의 `postgres:17-alpine`)
   인데 이 머신에 docker CLI 가 없다(Docker Desktop 미설치·WSL 에도 없음). 아래 1·2 는 DB 가
   올라와야 확인할 수 있다 — 컨테이너를 띄우는 것이 첫 단계다.
1. **채팅 경로 적재의 실 브라우저 확인** — 채팅에 URL 을 붙여 ① 사이드바 채용공고 페이지에
   나타나는지 ② 분석 작업이 자동으로 도는지 ③ 커리어지도에 노드와 **상세 관계 보기**가
   그려지는지. MySQL 없이 PostgreSQL(55432) + AI(8000) + backend(8080) + Vue(5173).
2. **멈춰 있던 분석 작업 1건이 V21 로 회수되는지 확인** — 마이그레이션 적용 후 백엔드를 띄우면
   `32700782` 작업이 다시 집혀 COMPLETED 로 끝나야 한다(AI 는 이미 판정·로드맵을 냈다).
   그러면 `roadmap_targets` 에 첫 행이 생긴다.
3. **적재 대상이 남은 자산** — `recommendations`·`coverletter`·`interview`. 대응 테이블이 없어
   범위 밖이다(선호·사실은 §4 에서 끝냈다). 새 테이블은 백엔드와 함께 정한다.
4. **채팅/분석의 이중 판정** — P5 로 입력(공고 원문)은 같아지지만 `fit_analysis` 는 여전히 두 번
   돈다. 판정 결과 공유(채팅이 분석 작업 결과를 재사용)가 다음 순서다.
5. **`webbridge` 의 `is_bare_url` 복사본 2개** — 폐기 예정이라 손대지 않았다. webbridge 를
   지울 때 함께 사라진다.
6. **`safeMessage` 의 근본 수정** — P3 은 코드를 갈아 우회한 것이다. 사용자에게 보일 문구와 별개로
   AI 원문 사유를 `analysis_jobs.error_message` 에 남기는 쪽이 옳다.

## 7. 그 밖에 남은 것

- 채팅 경로 적재의 **실 브라우저 확인** — 채팅에 URL 을 붙여 사이드바 채용공고 페이지에
  나타나고 분석 작업이 도는지. 백엔드·프론트를 함께 띄워야 한다.
- `preferences`·`user_facts`·`recommendations`·`coverletter`·`interview` 는 대응 테이블이 없어
  적재 밖이다(새 테이블은 백엔드와 함께 정한다).
- `webbridge` 에 `is_bare_url` 복사본 2개가 남아 있다(폐기 예정이라 손대지 않았다).
- 채팅의 `fit_analysis` 와 분석 작업의 `fit_analysis` 는 여전히 각각 판정한다. P5 로 **입력**은
  같아지지만 판정 결과 공유는 다음 순서다.
