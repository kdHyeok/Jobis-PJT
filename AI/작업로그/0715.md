## 3. 구현 내용

### 3.1 공통 계층 추가 (부품 교체식 모듈화)

| 파일 | 역할 |
|---|---|
| `config.py` | 환경변수/.env 로더. 개인 키·모델명 등 사람마다 다른 값을 외부화 (기본 모델 `claude-haiku-4-5`) |
| `llm.py` | LangChain Chat 모델 팩토리. `get_llm()` 하나만 호출하면 provider 교체와 무관하게 동작 |
| `extract.py` | 입력 텍스트 추출(`document_text_extract`, 설계 5장). `text`/`file(.docx·.pdf·.txt)`/`url` 지원. 실패해도 예외 없이 warning으로 남김 |
| `structured.py` | 구조화 출력 헬퍼. 프롬프트+Pydantic 스키마만 넘기면 됨. 키 없거나 실패 시 `(None, warnings)` 반환 → 노드가 mock 폴백 |

### 3.2 노드 교체

- **`parse_job_posting`**: 공고 입력(url/text/file) → `extract_text()` → `run_structured(NormalizedJobPosting)` → requirementId 결정적 재부여(req-N/pref-N). 실패 시 mock 폴백.
- **`build_user_profile`**: `resumeInput`(이력서 원천) → `extract_text()` → `run_structured(NormalizedUserProfile)`. evidenceMap·clarificationQuestions까지 한 번에 구조화. `resumeInput` 없으면 폴백.

### 3.3 계약 유지 원칙

- **API 계약(`AnalyzeRequest`)은 불변.** 이력서 원천은 계약에 없으므로, `GraphState`에 내부 optional 필드 `resumeInput`{sourceType, value}을 추가해 주입.
  - 실서비스: 백엔드가 `selectedExperienceIds`로 DB 조회 (미구현).
  - 로컬 테스트: `resumeInput`에 `.docx` 경로를 직접 주입.
- **키 없어도 그래프는 돈다** — 스켈레톤 성질 보존 (LLM 미설정 시 mock 폴백).

### 3.4 의존성·테스트

- deps 추가: `python-docx`(.docx 추출), `pypdf`(.pdf 추출).
- `.env.example`을 "개인 값만 채우는 칸" 형태로 정리.
- 확인 스크립트 `tests/run_user1.py` 추가 — user1 픽스처로 두 노드를 실행해 결과 출력.

## 5. 알려진 한계

- **잡코리아 GI_Read 공고는 본문이 JS 렌더링**이라 stdlib fetch로 못 가져온다. URL 경로는 회사명·제목만 잡고 필수요건은 잡코리아 공용 푸터(경력/학력/우대 체크박스)를 오파싱한다.
- 파서 로직 자체는 정상이며(`text` 소스타입으로 검증 완료), 실사용 시 공고는 **`text` 소스타입(본문 붙여넣기)** 권장.
- URL 완전 수집은 headless 브라우저(playwright 등) 도입이 필요 — 후속 과제.

## 6. 2차 보완 — 핸드오프 문서(`docs/claude_code_next_instructions0715.md`) 반영

핸드오프 문서의 지시(오케스트레이션 골격 집중, RAG는 hook만, 계층 보존, warning 중심, 작은 단위)를 반영해 다음을 추가했다.

### 6.1 Job Posting Parser 고도화 (문서 1순위)
- 설계 8.3 체인을 **단계 분리**: input normalize → extract → parse → **schema normalize** → **output validate**.
- `_normalize_job_schema`: requirementId 결정적 재부여 + techStack/domainKeywords 중복 제거. **taxonomy/DB 매핑이 이후 이 함수 안으로 들어오는 seam**.
- `_validate_job_posting`: 필수 필드(직무명/필수요건/기술스택) 검사 → **예외 대신 warnings** 생성.

### 6.2 RAG adapter/hook point 정의 (문서 핵심 요구·권장 산출물)
- `src/jobis_ai/rag.py` 신규: `RagAdapter`(Protocol) + `NullRagAdapter`(빈 결과+warning, 절대 예외 없음) + `get_rag_adapter()` 팩토리.
- **오케스트레이터가 RAG를 호출하는 구조**: 노드는 어댑터만 부르고, 실제 검색 구현은 RAG 담당자가 나중에 Protocol 구현으로 교체(부품 교체식).
- `config.py`에 `RAG_PROVIDER`(기본 `null`) 추가.

### 6.3 Gap Analyzer 실제 구현 + RAG hook 연결 (문서 4순위·다음 노드)
- `analyze_gap`: `normalizedJobPosting` + `normalizedUserProfile`(evidenceMap) → `GapAnalysisResult`(요구사항별 충족 판정·강점·gap).
- **기업 맥락은 `get_rag_adapter().fetch_company_context()`로 조회** — RAG 미연결이면 `companyContext=[]` + `rag_not_connected` warning, 프로필 근거만으로 판정(RAG 실패를 전체 실패로 만들지 않음).
- **표현 원칙 강제**: 합격/불합격/가능성 % 단정 금지. 충족도까지만.
- LLM 미설정 시 mock 폴백. `sources`/`warnings`를 상태에 일관 축적.

### 6.4 검증 (user1 체인)
- parser(text) → profile(.docx) → gap 체인 실행: 요구사항 6건 전부 판정(evidenceMap id 인용), 강점 4·gap 2, 표현 원칙 준수, RAG hook 정상 발화(빈 컨텍스트+warning).
- 회귀: `pytest` 3건 통과, `run_demo` end-to-end `completed`.

## 7. 3차 — Result Verifier(환각 검출) + Roadmap Planner

### 7.1 verify_result 실제 구현 (설계 12장, 결정적 규칙 기반)
근거 검사는 설계상 규칙(RunnableLambda)이라 **LLM 없이 결정적으로** 구현 — 환각 검출에 정확·빠름.
- **Schema Validate**: 핵심 산출물 존재 검사 → `missing_field`.
- **Policy Check**: 합격/불합격/반드시/무조건 등 금지 표현 탐지 → `forbidden_expression`(표현 수준 → 완화 warning 후 통과).
- **Evidence Check(환각 검출)**: `requirementStatus.matchedEvidenceIds` ⊆ `evidenceMap` 의 id 인지 검사. 존재하지 않는 `ev-N`(환각)은 **제거(sanitize)** 하고 `no_evidence` 위반 기록. 근거가 전부 환각인데 `met` 단정이면 **`uncertain`으로 강등**·신뢰도 하향.
- **Consistency Check**: 로드맵 기간 vs 요청 기간 등 → `inconsistent`.
- **Retry 판단**: 표현 수준은 완화 통과, 구조 결함(다수 `no_evidence`/`inconsistent`)은 `analyze_gap` 재시도 신호. **retryCount 증가로 무한루프 방지**(MAX_VERIFY_RETRY=1).
- 검증 결과로 sanitize된 `gapAnalysisResult` 를 상태에 되돌려 씀.

### 7.2 plan_roadmap 실제 구현 (설계 11장)
- **Constraint Normalize**: 시작일(오늘)·총 시간 예산(주×주당시간) 계산.
- **Task/Timeline/Completion(LLM structured)**: gaps·미충족 요구사항 → 기간별 항목(제목/기간/목표/tasks/측정가능 doneCriteria/우선순위/관련요구/estimatedHours).
- **Constraint Reflect/Validate**: totalWeeks/weeklyLoadHours 반영, 예산 초과·빈 로드맵은 **예외 대신 warning**.
- LLM 미설정 시 mock 폴백.

### 7.3 검증
- 환각 타깃 테스트: evidenceMap `{ev-1,ev-2}` 에 대해 `ev-99/ev-77` 인용 → 제거+`no_evidence`, `met`→`uncertain` 강등, 금지표현·기간불일치 탐지, retrySignal+retryCount=1 확인.
- 전체 파이프라인 `run_demo`: `completed`, 로드맵 5항목(측정 가능한 doneCriteria), 재시도 루프 정상. `pytest` 3건 통과.

## 8. 4차 — 골격 안정화 (테스트 + 재시도 루프 검증)

기능 확장보다 오케스트레이션 골격의 신뢰성·병합 안전성을 우선(핸드오프 문서 지침)해 다음을 추가했다.

### 8.1 테스트 결정화·고속화
- `tests/conftest.py`: autouse fixture로 `get_llm` 을 강제 미설정 → 모든 자동 테스트가 **mock 폴백 경로**로 결정적·고속 실행. 실제 LLM 검증은 `tests/run_user1.py`(수동)가 담당.
- 결과: 전체 스위트 **76초(실 LLM) → 1초(결정적)**, 25개 통과.

### 8.2 유닛 테스트 (순수 결정적 로직)
- `test_verify_result.py`: 환각 근거 제거, `met`→`uncertain` 강등, 금지표현, 기간 정합성, retrySignal+retryCount 증가, 예산 소진 시 미재시도.
- `test_extract.py`: text/빈소스/파일없음/미지원형식/docx(픽스처)/HTML 파서(script·style 제거).
- `test_nodes_and_rag.py`: 파서 `_normalize_job_schema`(id 재부여·대소문자 무시 dedup)·`_validate_job_posting`, `NullRagAdapter`(빈 결과+warning·무예외)·`get_rag_adapter` 기본 null.

### 8.3 재시도 루프 통합 테스트 + **버그 수정**
- `test_retry_loop.py`: `analyze_gap` 을 환각 유발 stub으로 교체해 컴파일된 그래프가 **1회 재시도 후 종료**(무한루프 없음)함을 검증.
- **발견·수정한 버그**: `route_verification` 이 `verify_result` 가 이미 증가시킨 `retryCount` 를 다시 검사하는 **이중 가드** 때문에 첫 재시도조차 막혔음. 재시도 예산 판단을 `verify_result` 한 곳으로 모으고, 라우터는 `retrySignal` 만 따르도록 수정. → 재시도 루프가 실제로 동작(1회 재시도 후 종료).

## 9. 5차 — Alternative Path Finder + RAG hook 연결 (설계 14장)

`find_alternatives` mock 을 실제 구현으로 교체하고, 두 번째 RAG hook 을 연결했다.

- **Candidate Search = RAG hook**: `_build_alternative_query()`(공고·gap 기반 쿼리) → `get_rag_adapter().search(query)`.
  `analyze_gap` 의 `fetch_company_context` 에 이어 **두 번째 hook point**. Null 어댑터면 빈 후보 + `rag_not_connected` warning.
- **LLM structured**: currentJob·gaps·strengths·ragCandidates → `AlternativePathResult`(alternativeJobs + pathComparison).
- **정직성 가드**: RAG 미연결로 후보가 없으면 **실제 회사/공고를 지어내지 않는다** — `companyName=""`, `sourceJobPostingId=null` 로 두고 경로 '유형'(similar_role/lower_seniority/stepping_stone 등)만 제안, uncertainty 기록. RAG 연결 시 같은 노드가 실제 공고에 근거를 붙인다.
- 검증: 유닛 테스트 2건 추가(쿼리 빌드, RAG 호출·정직성). 실 LLM 확인 시 3개 경로 제안·회사명 공란·근거 정상. 전체 **27개 통과(0.87s)**.

## 10. 6차 — 평가 하네스 (설계 18장)

"성능을 지표로 반복 개선"할 수 있는 체계를 구축했다. **순수 지표 함수 + 러너 + 시드 평가셋** 구조.

- `src/jobis_ai/eval/metrics.py` (순수·결정적, LLM 불필요):
  - `requirement_f1`: 공고 파싱 정확도(정답 라벨 대비 토큰 유사 매칭).
  - `groundedness`: 판정이 인용한 근거 중 evidenceMap 에 실재하는 비율(환각률의 역).
  - `policy_violations`: 금지 표현 위반 수(검증 게이트와 동일 규칙 재사용).
  - `roadmap_compliance`: 시간 예산 초과·필수 필드 누락 검사.
- `src/jobis_ai/eval/harness.py`: 평가셋 로드 → 파서→프로필→갭→로드맵 실행 → 지표 집계 → 리포트, `--save` 로 baseline 저장(개선 전후 비교).
- `evals/dataset.sample.json`: 시드 2케이스(명확 매칭 backend / 갭 많은 data-eng), 정보 없는 라벨은 null(설계 18.2).
- 유닛 테스트 11건 추가(순수 지표) → 전체 **38건 통과**.

### 10.1 baseline 결과 (실 LLM)
| case | F1 | 근거성 | 금지표현 | 로드맵 |
|---|---|---|---|---|
| backend-clear-match | 1.0 | 1.0 | 0 | OK |
| data-eng-gap-heavy | 1.0 | 1.0 | 0 | **X (예산 초과 206h > 180h)** |

- 요약: avg F1 1.0, avg 근거성 1.0, 금지표현 0, 로드맵 준수율 0.5.
- **하네스가 잡은 실제 신호**: 촉박한 제약(12주×15h=180h)에서 Roadmap Planner 가 예산을 재적합하지 못하고 206h 를 계획 → 예산 초과. 프롬프트/후처리 개선 대상으로 기록.

## 11. 7차 — Roadmap 예산 재적합 (평가 하네스로 발견→수정→재측정)

10.1에서 하네스가 잡은 "촉박 제약에서 로드맵 예산 초과" 문제를 고치고, **동일 평가셋으로 개선을 수치 증명**했다.

- `_refit_roadmap_to_budget()`: 시간 예산 초과 시 **우선순위 낮은 항목부터 제외**해 예산에 맞춘다(설계 11.3-3/6). 최소 1개는 유지, 단일 항목이 초과하면 예산으로 캡. 제외 항목은 assumptions/warning 에 기록.
- `plan_roadmap` 의 6단계(Constraint Reflect)에서 over_budget warning 대신 실제 재적합 호출.
- 결정적 유닛 테스트 3건 추가(낮은 우선순위 제외·예산 내 무변경·단일 초과 캡) → 전체 **41건 통과**.

### 11.1 개선 전후 (동일 평가셋, 실 LLM)
| metric | before | after |
|---|---|---|
| avg_requirement_f1 | 1.0 | 1.0 |
| avg_groundedness | 1.0 | 1.0 |
| total_policy_violations | 0 | 0 |
| **roadmap_compliance_rate** | **0.5** | **1.0** |

- data-eng 케이스: 예산 초과(206h>180h) → 재적합 후 180h ≤ 180h, 준수로 전환. 다른 지표 회귀 없음.
- `evals/baseline.json` 을 개선본으로 갱신(향후 회귀 기준). 이 흐름(발견→수정→재측정→수치 비교)이 곧 설계 18.3 실험 루프의 실사례.

## 12. 패키지명 통일 + LLM 실패 처리 강화

### 12.1 패키지명 `jarvis_ai` → `jobis_ai` 통일
- 폴더명 변경에 맞춰 전 파일 import·설정 일괄 변경(27개 파일 + pyproject `name`). 잔여 0건, 테스트 통과.

### 12.2 "가짜 폴백" 제거 — 정직한 실패 처리
- 문제: mock 폴백이 "키 없음(개발)"과 "호출 실패(실운영)"를 구분 못 해, LLM 호출 실패 시 그럴듯한 **가짜 결과**가 진짜처럼 나왔음.
- `structured.py`: LLM 호출을 **최대 3회 재시도**(일시적 오류 흡수) + `llm_unconfigured()` 헬퍼로 "키 없음/호출 실패" 구분.
- `nodes.py`: 5개 노드 폴백을 분기 — 키 없음이면 mock(개발), **호출 실패면 빈 결과 + `generation_failed` 경고**(가짜 금지).

### 12.3 오케스트라의 노드별 산출물 검증·재지시 (설계 16.2)
핵심 설계 개선: **다음 에이전트를 호출하기 전에 직전 에이전트 산출물을 검증**하고, 생성 실패면 다음으로 넘어가지 않고 **같은 에이전트에게 다시 지시**한다.
- 각 실 LLM 노드가 `nodeFailed[node]` 플래그 + `retryCount[node]` 를 상태에 기록(`_gen_retry_updates`).
- 각 노드 뒤에 검증 라우터(`route_after_parse/profile/gap/roadmap/alternatives`) — 실패+예산 남으면 자기 노드로 루프백, 아니면 다음. `MAX_GEN_RETRY=1`(무한루프 방지).
- 빈 답으로 그냥 진행하지 않음. 재지시 예산 소진 시에만 정직한 빈 결과로 진행.
- 검증: 라우터 유닛 + 통합(대체경로 1회 실패→재지시→2회차 성공→결과 반영). 전체 **44건 통과**.
- 부수: `run_demo`·스모크 테스트를 network 의존(example.com) → text 공고로 교체(결정적).
