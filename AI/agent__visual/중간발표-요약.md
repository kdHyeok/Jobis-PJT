# 슬라이드 1 — 에이전트 구조

## 제목
**AI 에이전트 구조 — 한 번 답하고 끝나는 챗봇이 아니다**
### 부제
**입력을 받아 10단계를 스스로 돌고, 스스로 검증하고, 모르면 되묻는다**

## 레이아웃
좌 45% 흐름도 캡처 (10개 노드 · 순환 엣지가 보이게) · 우 55% 아래 내용

## 본문

**LLM 챗봇과 무엇이 다른가**

| | LLM 챗봇 | 이 시스템 |
|---|---|---|
| 실행 | 질문 1회 → 답변 1회 | **입력 1회 → 10단계 자율 실행** |
| 도구 | 없음 (모델 안의 지식) | **17종 도구·DB를 상황에 따라 선택** |
| 오류 | 사용자가 발견 | **스스로 검수하고 재분석** (검증 루프) |
| 정보 부족 | 그럴듯하게 지어냄 | **판정을 멈추고 되묻는다** |
| 산출물 | 텍스트 | **구조화된 진단 + 로드맵 + 대안** (그대로 서비스에 연결) |

**에이전트 구성 — 3계층 10개**

| 계층 | 에이전트 | 구현 |
|---|---|---|
| **읽기** 2 | 공고 파싱 · 프로필 구축 | LLM (추출 전용) |
| **판단** 6 | **갭 판정 ★** · 충분성 게이트 · 로드맵 · 대체경로 · 검수 · 결측보완 | **순수 파이썬** (룰·DB·계산) |
| **말하기** 2 | 최종 응답 조립 · 되묻기 | LLM (표현 전용) |

**데이터는 공유 상태 하나로 오간다** — 에이전트끼리 직접 호출하지 않는다.

```
공고  ─▶ 정형 요구사항 ─┐
                       ├─▶ 갭 판정 ─▶ 로드맵 ─▶ 검수 ─▶ 최종 응답
이력서 ─▶ 프로필+근거 ─┘              └── 실패 시 재분석 ◀┘
```

## 말할 것 (슬라이드에는 안 씀)
- **에이전트 = LLM이 아니다.** 판단을 안 하는 게 아니라, 판단을 LLM이 아니라 알고리즘으로 한다
- 흐름이 위에서 아래로 한 번 흐르는 파이프라인이 아니다 — **되돌아가는 엣지가 있는 순환 구조**
- ★ 갭 판정 하나만 판정한다. 판정 로직이 여러 곳으로 갈라지지 않게 한 설계

# 슬라이드 2 — 왜 판단을 LLM에 안 맡겼나

## 제목
**에이전트의 판단을 파이썬으로 구현한 이유**
### 부제
**"합격 가능성"은 재현되고 설명돼야 한다**

## 본문

| LLM에 맡겼다면 | 파이썬으로 구현해서 얻은 것 |
|---|---|
| 같은 이력서에 매번 다른 진단 | **재현성** — 같은 입력이면 항상 같은 결과·같은 경로 |
| "왜 그렇게 봤는지" 설명 불가 | **근거 추적** — 판정마다 이력서 원문 문장 ID가 붙는다 |
| 없는 자격증·회사를 지어냄 | **환각 차단** — 자격증은 내부 DB, 대안은 실존 공고에서만 |
| 결과 검증 불가 | **자동 검증** — 산출물을 룰로 4단 검사하고 실패 시 재분석 |
| 틀리면 프롬프트를 달램 | **수정 가능** — 룰 한 줄 고치면 끝, 회귀는 테스트가 잡는다 |

**측정된 효과**

| 지표 | 값 |
|---|---|
| 전체 회귀 테스트 | **144개 통과 / 1.8초 / API 비용 0원** |
| 요청당 LLM 호출 | **3회 고정** (재시도 포함 최대 5회) |
| 판정 로직의 결정론 비율 | **100%** — 점수·등급·갭 판정에 LLM 미개입 |
| 판정 근거 | 요구사항별로 **원문 근거 ID 연결** |

**정리 — LLM을 안 쓴 게 아니라, 쓸 자리를 골랐다**
비정형 문서를 읽는 일과 결과를 사람 말로 옮기는 일은 룰로 안 된다 → **거기만 LLM**.
매칭·점수·기간 계산은 파이썬이 더 정확하고 빠르고 싸다 → **거기는 전부 코드**.

## 말할 것 (슬라이드에는 안 씀)
- 테스트 1.8초의 의미: 판정이 결정론이라 **LLM 없이 전 구간을 검증**할 수 있다. 고칠 때마다 즉시 회귀 확인 → 개발 속도가 붙는다
- 진행 상태: 10개 에이전트와 라우팅 전 구간 동작. 판정·로드맵·검증은 내부 DB와 룰로 완결
- RAG 2곳(기업 정보 · 공고 검색)은 인터페이스만 잡고 연결이 남음 — 연결 전에도 회사를 지어내지 않고 신뢰도 0으로 표시

## 예상 질문

**Q. 결국 GPT에 이력서 붙여넣고 물어보는 거랑 뭐가 다른가?**
챗봇은 한 번 답하고 끝이고 근거가 없다. 이건 10단계를 스스로 돌면서 도구를 고르고, 산출물을 스스로 검수하고, 정보가 부족하면 되묻고, 모든 판정에 이력서 원문 근거를 붙인다.

**Q. 에이전트라면서 LLM을 왜 3곳만 쓰나?**
**에이전트는 LLM이 아니다.** 에이전트가 판단을 안 하는 게 아니라, 판단을 LLM이 아니라 알고리즘으로 한다. 자율성은 LLM 호출 횟수가 아니라 **스스로 도구를 고르고 검증하고 되묻는 능력**에 있다.

**Q. 그럼 LLM은 왜 쓰나?**
비정형 문서 읽기와 자연어 표현은 룰로 안 된다. 그 두 곳에만 쓴다.

**Q. 다음 단계를 LLM이 정하는 구조(supervisor)인가?**
의도적으로 안 썼다. 실행 경로가 매번 달라지면 진단을 재현할 수 없다. 분기 조건 6개를 전부 코드에 명시했다.

**Q. 룰이 많아지면 유지보수가 어렵지 않나?**
그래서 판정을 한 곳에 몰았고, 지식은 룰이 아니라 **데이터(자격증 DB·스킬 사전·커리어 그래프)** 로 뺐다. 새 스킬 추가는 코드가 아니라 사전 한 줄이다.
