# RAG 파이프라인 환각(Hallucination) 테스트 결과

- **테스트 대상 생성 모델:** Claude Haiku 4.5 (`claude-haiku-4-5`) — 프로덕션 생성 모델(GMS Gemini 2.5 Flash Lite)의 API 키 없이, 로그인된 Claude CLI/에이전트로 대체 생성
- **테스트 목적:** LLM API 키(GMS_KEY) 없이도 검증 가능한 범위에서 (1) 검색 파이프라인의 계약 위반, (2) 생성 단계의 환각(허위 공고/조건 왜곡)을 결정적으로 검출
- **실행 방식:** 검출기 자체는 100% 결정적(LLM 불필요) 로직. LLM 호출은 "생성 응답을 만드는" 단계에만 사용.

## 2. 검출기(하네스) 설계

LLM 판정자 없이, 구조화된 데이터 대조만으로 아래를 검출:

- **1층 — 검색 계약 위반**: 지역/연차 하드필터 위반, 중복 공고, 빈 결과, 정렬 위반
- **2층 — 생성 환각**: 답변이 추천한 회사가 검색 컨텍스트에 실존하는지(fabrication), 언급한 기술 조건이 해당 회사 컨텍스트와 일치하는지(distortion)
- **검출기 신뢰성 검증**: 허위 회사 3종·기술 왜곡 3종을 인위적으로 주입해 검출기가 실제로 잡아내는지, 정상 표기 변형(별칭·㈜생략)에서 오탐하지 않는지 확인

### 검출기 검증 결과: **9/9 통과**
- 허위 회사 3종 → 전부 fabrication으로 검출
- 기술 왜곡 3종 → 전부 distortion으로 검출
- 정상 응답 변형 3종(원본/별칭표기/㈜생략) → 오탐 없음

## 3. 1차 소규모 테스트 (15건, ragas_dataset 기반)

| 지표 | 기존 template 응답 | Haiku 생성 응답 |
|---|---|---|
| 허위 공고(fabrication) | 0/15 | 0/15 |
| 조건 왜곡(distortion) | 0/15 | 0/15 |
| 추천 항목 grounding | 45/45 | 17/17 |
| 답변 누락(검색된 정답을 답변에서 빠뜨림) | 0건 | 7건 |
| 오답 추천(정답 아닌 공고 추천) | 18건 | 9건 |
| 검색 recall@3 (상한 보정) | 0.733 | 0.733 (동일 검색 결과 사용) |
| 검색 precision@3 | 0.622 | 0.622 |

**해석:** Haiku는 프롬프트 지시("조건에 안 맞으면 그렇다고 말하라")를 충실히 따라, 무조건 top-3을 나열하는 template 방식보다 오답 추천은 절반으로 줄었으나 정답 누락이 늘어나는 트레이드오프를 보임. 환각(허위 공고·조건 왜곡)은 두 방식 모두 0건.

> 참고: 최초 보고 시 검색 recall을 0.406으로 오산정한 바 있음 — k=3으로 절단 저장된 데이터에 전체 reference 개수 기준 recall을 적용한 지표 선택 오류였음. `min(retrieved, reference)`로 상한 보정한 recall@3 = 0.733이 정확한 값이며, 이는 프로젝트 문서(`RESULTS_v2.md`)의 nDCG@3 0.84와 정합.

| Grounded(검색 결과에 실존) | 251/251 (100%) |

### 검출기 개선 이력 (최초 채점 3건 → 재검증 후 0건)

최초 채점에서 3건이 fabrication으로 플래그되었으나, 수동 대조 결과 전부 검출기 오탐으로 확인:

1. **"유한회사○○" 표기 미인식**: 정규화 로직이 "㈜/(주)/주식회사"만 제거하고 "유한회사"를 놓쳐, 실제로는 일치하는 회사가 불일치로 처리됨 → 정규화 목록에 "유한회사/유한책임회사" 추가
2. **헤더-상속 패턴 미지원**: "인투씨엔에스의 백엔드 개발자 채용 공고들" 처럼 회사명을 헤더 문장에서 한 번만 밝히고, 아래 번호목록이 그 회사의 여러 실제 공고를 나열하는 경우 — 번호 항목 자체엔 회사명이 없어 오탐 → 헤더에서 확정된 회사명을 후속 번호목록에 상속하는 로직 추가

수정 후 재채점 결과 3건 모두 정상(환각 아님)으로 정정됨.

## 7. 한계 및 주의사항

1. **검출 범위의 한계 (하한선 지표)**: 이 테스트는 "회사가 실존하는가", "기술 조건이 일치하는가"처럼 구조화된 필드로 결정적 대조가 가능한 환각 유형만 잡아낸다. 아래는 검출 범위 밖:
   - 컨텍스트에 없는 부가 주장(예: "재택근무 가능", "복지가 좋음")
   - 과장되거나 근거 없는 적합도 서술("완벽히 일치합니다")
   - 추론성 문장의 사실 왜곡
2. **테스트 모델 ≠ 프로덕션 모델**: 실제 프로덕션 생성 모델은 GMS Gemini 2.5 Flash Lite. Haiku 4.5로 대체 생성했으므로 이 수치는 "Haiku의 환각률"이며, 모델별 환각 성향 차이로 인해 Gemini의 실제 환각률과 다를 수 있다. 프롬프트(SYSTEM_PROMPT) 수준의 grounding 지시가 얼마나 잘 작동하는지에 대한 신호로는 유효.
3. **헤더-상속 로직의 잠재 맹점**: 5절의 검출기 개선으로 "헤더에서 회사를 밝히고 번호목록이 그 하위 공고를 나열"하는 정상 패턴은 인식하게 됐으나, 이 로직이 향후 "가짜 헤더 + 실제 회사명을 흉내낸 하위 항목" 같은 새로운 환각 패턴을 놓칠 가능성은 재점검 필요.
4. **조합생성 질의의 분포 편향**: 335개 조합생성 질의는 직군×기술×지역×경력의 균등 조합이라, 실제 사용자 질의 분포(특정 인기 기술·지역에 쏠림)와 다를 수 있다.
5. **1층 recall/precision은 골든 15건 기준**: 대규모 400건 검색 테스트는 계약 위반(하드필터) 여부만 검증했고, 관련성 기반 recall/precision은 인간 라벨이 없는 신규 335개 질의에는 적용하지 못했다(라벨링 비용 문제).
