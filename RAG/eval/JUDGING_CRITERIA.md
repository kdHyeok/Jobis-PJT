# 적합성 판정 기준서 v1

> 대상: 앵커 채점자(사람) 및 judge 프롬프트 작성자.
> 근거: 2026-07-29 사람 채점 118쌍에서 **역추출**한 실제 적용 기준 + 코퍼스 실태 조사.
> 목적: 채점자 자기일관성(현재 κ=0.855)과 judge-사람 일치도(현재 κ=0.5921)를 함께 올린다.

## 0. 왜 이 문서가 필요한가

게이트 3(judge 신뢰도 κ≥0.60)이 판정 불가 상태이고, 불일치가 **경력 요건 질의에 집중**된다
(불일치율 22.1% vs 풀스택 8.3%). 판정 기준이 미정의라 **사람조차 흔들린다** — 사람 자기일관성
κ=0.855가 상한을 만들고, judge는 그 69%에 머문다. **기준을 정의하면 천장 자체가 올라간다.**

판정기 모델을 키우는 것은 해법이 아님이 확인됐다(gemini-2.5-flash로 상향했을 때 사람 대비
κ 0.4535로 오히려 악화). 남은 수단은 기준 정의다.

---

## 1. ⚠ 선행 결함 — 연차 정보가 구조화되지 않았다

**기준을 정하기 전에 알아야 할 사실.** 판정에 쓰는 `[핵심조건] 경력 …` 표시를 믿을 수 없다.

| 실태 | 수치 |
|---|---|
| active 공고 | 1,172건 |
| `exp_min` NULL (= "경력 무관/미상"으로 표시됨) | **930건 (79.4%)** |
| 그중 **본문에는 "경력 N년" 명시** | **476건 (NULL의 51.2%, 전체의 40.6%)** |
| 원인: `raw.experience`가 값 없이 라벨만 수집됨 (`'경력'`) | **785건 (67.0%)** |

`jobrag/sources.py::parse_exp_range('경력')`은 숫자가 없어 `(None, None, False)`를 반환하고,
`jobrag/search.py:96`의 `(p.exp_min IS NULL OR p.exp_min <= %s)`가 NULL을 **항상 포함**시킨다.
→ **연차 필터가 코퍼스 79%에서 무력화된다.** 명세서 입력 3요소(직군·기술·연차) 중 하나가
사실상 작동하지 않는 상태다.

**판정 시 규칙: 요구 연차는 `[핵심조건]` 표시가 아니라 본문 전문을 근거로 판단한다.**
표시가 "경력 무관/미상"이어도 본문에 "경력 5년 이상"이 있으면 **5년 이상으로 취급**한다.
(앵커 시트는 본문을 절단 없이 싣고 있으므로 판단 가능하다.)

> 후속 과제: 본문 보강 추출로 `exp_min`을 채우는 것. 앵커 관련 공고 111건 중 **40건(36%)**이
> 즉시 복구 가능함을 프로토타입으로 확인했다. 이건 판정 기준 문제가 아니라 파이프라인 수정 사항이다.

## 2. 연차 (최대 불안정 구간 — 불일치 22.1%)

### 2-1. 판정 순서

1. 본문에서 요구 최소 연차를 읽는다 (§1 규칙). 없으면 "미상".
2. 질의 연차와 비교한다. 질의가 "신입"이면 0년으로 본다.
3. 아래 표를 적용한다.

### 2-2. 규칙 (사람 라벨 근거)

| 상황 | 판정 | 근거 |
|---|---|---|
| 요구 ≤ 질의 연차 (양립) | 연차 사유로 감점하지 않음 → 직군·기술로 판정 | 사람 라벨 34건 중 Incorrect 32.4% (직군 사유) |
| **요구 > 질의 연차 (초과)** | **기본 Incorrect** | 사람 라벨 29건 중 **Incorrect 65.5%** |
| 초과폭 1년 이내 **이면서** 직군·기술이 정확히 일치 | Ambiguous 허용 | 초과 29건 중 7건을 사람이 Correct 판정 — 절대 규칙 아님 |
| 요구 미상 (본문에도 없음) | 연차 사유로 감점하지 않음 | 사람 라벨 55건, Incorrect 45.5%가 전부 직군 사유 |
| 질의=신입, 공고 요구 3년 이상 | **Incorrect** | 사람 라벨 일치 (해당 사례 전부 Incorrect) |
| 질의=신입, 공고 "신입 가능"/무관 | Correct 가능 | — |
| 질의=경력 N년, 공고 **신입·인턴 전용** | **Incorrect** | 인턴 전용은 경력자 지원 불가 |

**핵심: 연차 초과는 강한 부정 신호이지만 절대 규칙이 아니다.** 초과 시 기본 Incorrect,
단 초과폭 1년 이내 + 직군·기술 정확 일치일 때만 Ambiguous로 올린다.

### 2-3. 하지 말 것

- `[핵심조건] 경력 무관/미상` 표시만 보고 "연차 조건 없음"으로 처리 → §1 결함 때문에 틀린다
- 초과폭이 2년 이상인데 기술 스택이 좋다고 Correct 주기

## 3. 직군 (풀스택 ↔ 백엔드/프론트엔드 — 불일치 8.3%, 문제 아님)

사전에 확정하려던 쟁점이었으나 **사람 판정이 이미 일관적**이었다(12쌍 중 Correct 8 / Ambiguous 1 /
Incorrect 3, 판정기 불일치 8.3%). 기존 관행을 그대로 성문화한다.

| 상황 | 판정 |
|---|---|
| 질의=풀스택, 공고=풀스택 | Correct |
| 질의=풀스택, 공고=백엔드 또는 프론트엔드 (한쪽만) | **Correct** — 사람이 대체로 인정했다 |
| 질의=백엔드, 공고=풀스택 | **Ambiguous** — 백엔드 업무 포함하나 범위가 다르다 |
| 질의=백엔드, 공고=프론트엔드 | Incorrect |

### 3-1. 인접 직군은 구분한다 (실측 최약점)

데이터·ML 축이 성능 최하위(정규화 nDCG@3 0.362, dense 0.100)이며 원인이 인접 직군 혼동이다.
**아래는 서로 다른 직군으로 판정한다:**

- 데이터 엔지니어 ↔ 데이터 사이언티스트 ↔ ML 엔지니어 ↔ 데이터 분석가
- QA 엔지니어 ↔ 개발자 (기술 스택이 겹쳐도 다른 직군)
- SRE ↔ DevOps: **Ambiguous** (실무 경계가 모호하므로 예외)

기술 스택 겹침은 직군 일치의 근거가 되지 못한다. 이미 judge 프롬프트 v3에 반영된 원칙이며 유지한다.

## 4. 지역

정규화 질의(명세서 입력)에는 **지역 조건이 없다**(`regions=[]`). 따라서 이 트랙에서
**지역을 사유로 감점하지 않는다.** 자연어 30질의 트랙에는 지역 조건이 있으므로 별도 기준을 쓴다.

## 5. 등급 배점의 의미 (채점자가 알아야 할 것)

| 라벨 | 점수 | 지표 반영 |
|---|---|---|
| Correct | 2 | nDCG·P@3·AP@3 모두 적합으로 계산 |
| **Ambiguous** | **1** | **nDCG는 절반 인정, P@3·AP@3는 불인정** |
| Incorrect | 0 | — |

Ambiguous가 88건으로 Correct 99건과 거의 맞먹어 **nDCG@3을 0.107 밀어올린다**
(0.7521 → 애매=0이면 0.6450). **Ambiguous는 "잘 모르겠다"가 아니라 "부분 적합"이다.**
판단이 어려우면 Ambiguous로 도피하지 말고 위 규칙을 적용해 Correct/Incorrect로 내린다.

## 6. 적합 공고가 없는 질의

질의 15종 중 **2종(데이터 사이언티스트, QA 엔지니어)은 적합 공고가 0건**이다. 이때:

- 채점자는 억지로 Correct를 만들지 않는다. 전부 Incorrect가 정답이다
- 이 질의는 지표에서 **별도 케이스로 분리 집계**한다 (옳은 제품 동작은 "결과 없음"이며,
  현재 지표는 이를 상 주지도 벌 주지도 않아 평균만 왜곡한다)

## 7. 변경 이력 및 적용 절차

- **v1 (2026-07-29)**: 사람 채점 118쌍에서 역추출해 최초 성문화. §1 연차 추출 결함 발견 포함

**적용 시 사전 등록 원칙**(PLAN_v5 §2 계승):
1. 이 기준서를 judge 프롬프트 v4에 반영하기 전, **채택 기준을 먼저 등록**한다
   (예: 사람 대비 κ ≥ 0.60 또는 v3(0.5921) 대비 +0.05 이상)
2. 앵커에 과적합하지 않도록 **확인된 결함 1건 단위**로 수정하고 매번 검증한다
3. 기준서 개정 시 기존 사람 라벨의 재검토 필요 여부를 명시한다 — 규칙이 바뀌면
   과거 라벨과 새 라벨이 섞여 κ가 오염된다
