# RAG 성능 평가 계획 v4

> 목표: **"이 검색이 어느 수준인가"에 방어 가능한 숫자로 답한다.**
> 제약: 사람 작업 1시간 이내, LLM 판정 2천 건 이내, 코드 5파일 이내.

---

## 0. 왜 v3를 버렸나

v3는 설계가 틀려서가 아니라 **끝나지 않아서** 버렸다.

| v3 실적 | 값 |
|---|---|
| 계획한 판정 | 23,780건 (20질의 × 코퍼스 1,189) |
| 실제 완료 | **3질의 (15%)** — 429 스로틀에 막힘 |
| 사람 앵커 100쌍 | **0건 채점** |
| 산출된 성능 수치 | **없음** |

v3의 핵심 통찰(순환성 제거, 랜덤 바닥, 사람 검증)은 옳다. 틀린 건 **완전판정이라는 수단**이다.
코퍼스가 1,189건이라 "전량 판정이 가능하다"는 판단이 출발점이었지만, 실제 병목은 코퍼스 크기가
아니라 **게이트웨이 호출률**이었다. 20배 비싼 방법을 골라서 0배의 결과를 얻었다.

**v4의 교환**: 완전판정 → 풀링. recall 상한 측정을 포기하는 대신 **완주한다.**
명세서가 `top_k = 3`을 요구하므로 recall은 애초에 헤드라인이 될 수 없다 — 잃는 것이 거의 없다.

## 1. 지표 — 2계층

### Tier 0 · 결정적 검증 (LLM·사람 불필요)

판정자가 개입하지 않으므로 **무조건 객관적**이다. 초 단위로 돌고 CI가 필요 없다. 합격선은 전부 100%.

| 지표 | 정의 | 합격선 |
|---|---|---|
| `contract.fields_intact` | 출력 공고의 원본 15개 필드 `sha256` == DB row 해시 | 100% |
| `contract.sorted` | `score` 내림차순 단조 | 100% |
| `contract.topk` | `len(postings) ≤ 3` | 100% |
| `contract.empty_ok` | 0건 시 `{"postings": []}` (예외 금지) | 100% |
| `contract.accepts_both` | 입력 A(문자열)·B(profile JSON) 모두 수용 | 100% |
| `reason.skills_grounded` | `matched_skills` ⊆ 공고 `detail_text` | 100% (환각 0) |
| `reason.fields_grounded` | `matched_fields` ⊆ 입력에서 비어있지 않은 필드 | 100% |
| `latency.p50 / p95` | 질의 1건 end-to-end | 사전 등록 후 측정 |

> Tier 0은 **성능이 아니라 계약 위반을 잡는다.** 여기서 FAIL이면 Tier 1 수치는 의미가 없다.

### Tier 1 · 랭킹 품질 (헤드라인)

> **정규화 nDCG@3 = (실측 − 랜덤) / (풀오라클 − 랜덤)**

- 컷오프 **@3** — 명세서 `top_k=3`에 맞춘다. v3의 @10은 계약과 무관한 눈금이었다.
- 등급 관련성: Correct=2, Ambiguous=1, Incorrect=0 → graded nDCG
- 보조: `P@3`, `MAP@3`. **Recall은 보고하지 않는다** (풀링이라 상한 미측정)
- arm 5종: `random` / `bm25_only` / `dense_only` / `rrf` / `rrf_ce`
- arm 쌍마다 **쌍대 부트스트랩 95% CI**. 0을 걸치면 `significant: false`

## 2. 정답 집합 — 풀링 + 미검출 보정

### 구성

| 항목 | 판정 수 |
|---|---|
| 질의 30개 × 5 arm **top-30** 합집합 (≈60건/질의) | 약 1,800 |
| 난이도 축 1질의 **완전판정** (교정용) | 1,189 |
| **합계** | **약 3,000** (v3 대비 8배 절감, 약 7분) |

### 순환성을 어떻게 다루나 — 균등 랜덤은 폐기했다

초안은 질의당 **랜덤 20건**으로 미검출률을 추정하려 했다. 보존한 완전판정으로 검산한 결과 **성립하지 않는다.**

| 질의 | Correct 비율 | 랜덤 20건의 기대 양성 |
|---|---|---|
| q08 서울 개발자 | 61.7% | 12.3 |
| q03 Python 백엔드 | 17.7% | 3.5 |
| **q05 AWS 엔지니어** | **4.7%** | **0.94** |

희소 질의에서 기대 양성이 **1건**이다. 0~1 성공으로 낸 비율의 95% CI는 [0%, 17%] →
코퍼스 환산 **[0건, 200건]**. 추정치가 아니라 잡음이다.

**대체 — 포획-재포획 (Chapman 추정량)**

이미 평가 대상인 두 검색 계열의 중첩으로 모집단을 추정한다. **추가 판정 비용 0.**

```
N̂ = (n₁+1)(n₂+1)/(m+1) − 1
    n₁ = BM25 top-30 중 관련, n₂ = dense top-30 중 관련, m = 중첩
풀 미검출 = N̂ − |풀 내 관련|
```

- **Chapman을 쓰는 이유**: 소박한 `n₁n₂/m`는 희소 질의에서 m이 작아 분산이 폭발하고 **m=0이면 정의되지 않는다.** q05가 정확히 그 구간
- **N̂은 하한선이다.** 두 검색기가 독립이 아니라 (둘 다 진짜 관련성과 상관) 중첩이 부풀고 → N̂ 과소추정

**편향 교정 — 점추정 금지, 구간 전파**

교정 질의 4건(`_archive` 3건 + 난이도 축 신규 1건)은 진실을 알고 있으므로 `진실/N̂` 보정비를 준다.
**단일 스칼라로 곱하지 않는다** — 교정 질의의 밀도가 4.7~61.7%로 **13배** 흩어져 있어, 여기서
점추정 하나를 뽑아 30질의에 곱하는 것은 "3질의로 보정치를 만들면 과적합"이라는 지적을
그대로 재현하는 것이다. 관측된 보정비의 **[min, max]를 구간으로 전파**하고 미검출률을 **범위로만** 보고한다.

> **이 숫자는 헤드라인이 아니라 각주다.** 정규화 nDCG@3의 **arm 간 비교는 풀 미검출에 불변**이다
> (풀 밖 정답은 모든 arm에 동등하게 불리). 미검출률은 절대 수치의 해석 폭을 정하는 용도이며,
> 여기에 정밀도를 부여하려 애쓰면 없는 확실성을 만드는 셈이다.

**교정 질의의 한계(명시)**: `_archive` 3건은 기술·지역 축뿐이다. 난이도 축 1건을 추가해도
**제약 축은 교정 없이 외삽**된다. 제약 축 미검출률은 `extrapolated: true`로 표기한다.

### 질의 선정

기존 [golden/queries.py](../golden/queries.py) 65건에서 **결정적 선정**(`sha256(id:text)` 정렬).
14개 카테고리를 4축으로 통합, **축당 정확히 7~8질의**.

| 축 | 카테고리 | n |
|---|---|---|
| 기술 | tech_only / tech_alias / multi_tech | 8 |
| 지역 | region_only / colloquial_region | 7 |
| 제약 | exp_only / boundary_exp / combo2 / combo3 | 8 |
| 난이도 | sparse_relax / low_resource_role / parser_trap / negative_signal / freeform | 7 |

축당 n≥7이므로 축 단위 결론에 CI를 붙일 수 있다. **카테고리 단위(n=2~3) 결론은 내지 않는다.**

## 3. 라벨 신뢰성 — 사람 앵커 120쌍

LLM 라벨은 그 자체로 객관적이지 않다. **사람 채점으로 교정될 때만** 지표가 된다.

| 층 | n | 이유 |
|---|---|---|
| `pos_dense` | 25 | LLM=Correct·밀집 질의. 헤드라인 분자를 직접 구성 |
| `pos_sparse` | 25 | LLM=Correct·희소 질의. v3에서 **κ=0.22**가 관측된 구간 |
| `ambiguous` | 20 | 배치 크기에 4.6배 흔들린 유일한 클래스 |
| `neg_top` | 30 | Incorrect인데 어떤 arm의 top-3에 뜬 것. 위양성이 여기 숨으면 P@3이 **과대**평가 |
| `pool_tail` | 20 | 풀 하위(rank 11~30). 포획-재포획 입력의 정확도를 잰다 |

- 채점 시트에 **LLM 라벨을 넣지 않는다** (anchoring 방지). 정답 키는 별도 파일
- 층별 모집단 크기 `N_h` 저장 → **사후가중**으로 불편 추정
- 산출: 이진 κ, 사후가중 일치도, **McNemar 편향 방향**(정답 집합이 부푸는지 줄어드는지)

### 세션 격리 — 인지 부하가 다른 과업을 섞지 않는다

`ambiguous` 20쌍은 본문을 읽어야 해서 쌍당 40초 이상이고, 나머지 100쌍은 제목·기술스택
대조로 5~10초다. 한 세션에 섞으면 피로가 라벨 품질을 오염시킨다.

| 세션 | 대상 | 예상 시간 |
|---|---|---|
| `--session easy` | `pos_dense` / `pos_sparse` / `neg_top` / `pool_tail` 100쌍 | 30~40분 |
| `--session ambiguous` | `ambiguous` 20쌍 | 20~30분 |
| `--session recheck` | 세션 1·2에서 무작위 20쌍 **재채점** | 10분 |

- **총 60~90분.** 초안의 40분은 낙관이었다
- 출력 파일 분리. 세션 간 휴식은 코드가 강제할 수 없으므로 **측정으로 대체**한다:
  판정별 타임스탬프를 기록해 세션 내 순번 대비 소요시간을 회귀, 후반부 급락 시
  리포트에 `fatigue_suspected` 플래그
- 세션 내 제시 순서 무작위화 (질의·라벨 블록화 방지)

**`recheck` 세션이 필요한 이유**: 평가자가 1명이면 게이트 3의 κ는 "사람 vs LLM"일 뿐,
**사람이 정답이라는 가정은 검증되지 않는다.** 20쌍 재채점으로 사람 자기일관성을 재야
사람 쪽 잡음과 LLM 오류를 구분할 수 있다. 사람 자기일관성이 LLM과의 κ보다 낮으면
게이트 3의 해석 자체가 무효다.

### 게이트 (측정 전 강제)

| # | 조건 | FAIL 시 |
|---|---|---|
| 1 | 풀 커버리지 100% (판정 누락 0) | 재개 실행 |
| 2 | arms에 `random` 포함 | 코드 예외 |
| 3 | 사람 ≥100쌍, **이진 κ ≥ 0.60** (사전 등록) | **헤드라인 무효** |
| 3b | 사람 자기일관성 κ > 사람-LLM κ | 게이트 3 해석 무효 표기 |
| 4 | 모든 보고 축 n ≥ 7 | 코드 예외 |
| 5 | arm 비교에 쌍대 CI | 코드 예외 |

게이트 FAIL이면 `report.json`을 쓰지 않는다. `--force` 우회 시 `gate_failed` 배너가 박히고 인용 금지.

## 4. 파일 구성 — 5개

v3는 11+11개 모듈이었다. 그 중 `pilot.py` `calibrate.py` `headroom_diag` `ce_inversion_diag`
`label_hygiene_diag` 등은 **결론에 한 번도 쓰이지 않았다.**

| 파일 | 역할 |
|---|---|
| `eval/core.py` | 스냅샷 해시 검증 · qrels 로드 · nDCG/P/MAP · 쌍대 부트스트랩 · Chapman 추정 |
| `eval/judge.py` | LLM 판정 (배치 50, 워커 3, `thinkingBudget:0`, **백오프 + 재개 루프**) |
| `eval/anchor.py` | 120쌍 층화추출 → 3세션 채점 시트 → κ·사후가중·McNemar·피로도 |
| `eval/contract.py` | Tier 0 결정적 검증 전부 |
| `eval/run.py` | 풀 구성 → 판정 → 게이트 → 측정 → `report.json` |

### 호출 제어 — `GmsClient`를 판정에 재사용하지 않는 이유

[jobrag/generate.py:54](../jobrag/generate.py:54) 는 재시도가 **0회**다.

```python
r = self._rq.post(self._url, json=body, timeout=30)
if r.status_code != 200:
    raise RuntimeError(f"GMS 호출 실패 {r.status_code}: ...")
```

`Retry-After` 미확인, 429에서 즉시 예외. v3가 커버리지 91.7%에서 멈춘 원인이다
(v3 `judge.py`가 자체 재시도 큐를 따로 갖고 있었고 그건 삭제됐다).
`thinkingBudget` 주입 경로도 없다. 따라서 `eval/judge.py`가 호출을 직접 소유한다:

- `Retry-After` 헤더 우선 → 없으면 **지수 백오프** (1·2·4·8·16초) + 지터
- 전역 스로틀 1.0초, 워커 3
- 배치 단위 재시도 큐 → 최종 실패분은 `pending`으로 남기고 **재실행 시 미판정분만 채움**
- 게이트 1(커버리지 100%)이 완주를 강제한다

### 재사용 (v3에서 이미 실측된 것 — 다시 재지 않는다)

- 모델 `gemini-2.5-flash-lite` (게이트웨이에 `2.5-flash` / `-lite`만 열림)
- `thinkingBudget: 0` 필수 — `2.5-flash`는 사고 토큰이 `maxOutputTokens`를 전소시키고 빈 응답 반환
- 배치 50 / 워커 3 — 워커 6은 429 연쇄. 병목은 지연이 아니라 **호출률**
- 프롬프트 v1 (3분류 직접 질의). v2(축 분리 합성)는 자기일관성이 κ 0.85→0.67로 **악화되어 기각됨**
- 헤드라인은 **strict**(Correct만 관련). Correct 이진 일치율 0.977로 배치 크기에 불변

### 재검증 (승계하지 않고 다시 재는 것)

v3의 파라미터 근거는 전부 **자기일관성**이지 **정확도**가 아니다. 일관되게 틀릴 수 있다.
예산이 8배 줄었으므로 이제 감당 가능하다:

- **thinking on/off A/B를 앵커 120쌍 한정으로 실행.** 사람 정답 대비 정확도로 비교한다.
  판정 대상이 v3와 같은 (질의, 공고) 관련성 과업이라 파라미터 자체는 이전 가능하지만,
  *정확도* 기준 비교는 이번이 처음이다. thinking on이 유의하게 나으면 승계를 철회한다

## 5. 실행 순서

```bash
python -m eval.contract                     # Tier 0 — 즉시, LLM 불필요
python -m eval.run --build-pool              # 풀 구성 (30질의 × top-30 × 5 arm)
python -m eval.run --judge                   # 약 3,000 판정, 약 7분, 백오프+재개형
python -m eval.anchor --session easy         # 100쌍 시트
python -m eval.anchor --session ambiguous    # 20쌍 시트
python -m eval.anchor --session recheck      # 재채점 20쌍 시트
# ── 사람이 3세션 label 열을 순서대로 채움 (60~90분, 세션 간 휴식) ──
python -m eval.anchor --score                # 게이트 3 + 3b(자기일관성)
python -m eval.run --measure                 # report.json
```

`--judge`는 재개형이다. 429로 죽으면 다시 실행하면 미판정분만 채운다.

### 임계경로

Tier 0(`contract.py`)은 나머지와 **완전 독립**이므로 병렬로 먼저 끝낸다.
전체 소요: 사람 60~90분 + 기계 약 10분.

## 6. 아직 계획에 없는 것 — 입력 B (이력서 profile)

명세서는 입력을 **직업명 또는 profile JSON** 둘로 규정하는데, **현재 코드에 profile 경로가 없다.**
[jobrag/rag_adapter.py](../jobrag/rag_adapter.py)는 `sub_roles → requiredSkills` 라는 **다른 계약**을 구현하고 있다.

→ 구현이 없으므로 평가 계획도 세우지 않는다. **구현 후 별도 트랙**으로 붙인다.
profile 8건에 위 풀링 기계를 그대로 재사용하면 판정 약 440건으로 끝난다.

## 7. 이 평가가 말할 수 없는 것

리포트에 영구 표기한다.

1. **Recall 상한을 재지 않는다.** 풀링이므로 풀 밖 정답은 포획-재포획(Chapman) 추정으로만 다룬다.
   추정량은 **하한선**(검색기 간 양의 상관으로 과소추정)이고, 편향 보정비는 교정 질의 4건의
   **구간**으로만 전파한다 — 점추정을 리포트 헤드라인에 쓰지 않는다.
2. **미검출률 교정은 기술·지역·난이도 축뿐이다.** 제약 축은 교정 없이 외삽되어 `extrapolated: true`.
3. **사람 앵커는 120쌍, 3세션 분리.** 층별 20~30쌍이므로 층별 CI는 넓다.
   이진 κ가 0.60 미만이면 헤드라인 무효. 사람 자기일관성이 사람-LLM κ보다 낮으면 게이트 3 해석도 무효(게이트 3b).

   돈다 — A/B가 유의하게 다르면 이 실행 자체가 재작업 대상이 된다는 뜻이며, 그 결과는 보고서에 남는다.
