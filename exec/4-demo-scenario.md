# 4. 시연 시나리오

기준 주소는 `http://localhost:8088`(로컬 Docker)이다. 운영 시연은 배포 도메인으로 바꿔 읽는다.
화면 이름은 실제 라우트와 좌측 사이드바 메뉴 이름을 그대로 쓴다.

## 0. 시연 전 점검 (무대 뒤)

```powershell
docker compose ps
Invoke-RestMethod http://localhost:8088/api/health | ConvertTo-Json -Depth 5
```

- `postgres`·`ai`·`backend`가 `healthy`, `frontend`가 `running`이어야 한다.
- LLM 키가 실제로 통하는지 확인한다. **health 200은 프로세스가 떴다는 뜻일 뿐이다.**
- 공고 분석은 완주까지 수십 초~수 분이 걸린다. 시연 흐름이 끊기지 않도록 **미리 분석을
  완료해 둔 공고 1건**과, 현장에서 새로 돌릴 공고 1건을 나눠 준비한다.
- RAG 추천까지 보여준다면 `http://localhost:8765/health`의 `corpus_chunks > 0`을 확인한다.

## 2. 커리어 대화 — 사용자 메시지 즉시 저장과 비동기 응답

| 순서 | 화면 | 클릭 위치 | 확인할 것 |
|---|---|---|---|
| 1 | 사이드바 | **새 대화** | `/app/chat`로 이동, 입력창 포커스 |
| 2 | 채팅 | 하단 입력창에 질문 입력 후 전송 | 사용자 메시지가 **즉시** 목록에 남는다 |
| 3 | 채팅 | — | 진행 표시가 돌고, 답변이 도착하면 교체된다 |
| 4 | 채팅 | 답변 카드 | 에이전트 산출물 카드와 근거 표시 |

**설명 포인트**: 대화·질문·답변·분석 상태의 정본은 Spring + PostgreSQL이다. AI 응답이
지연되거나 실패해도 사용자 메시지는 유실되지 않는다.

## 3. 공고 등록과 분석 — 핵심 시연

| 순서 | 화면 | 클릭 위치 | 확인할 것 |
|---|---|---|---|
| 1 | 사이드바 | **채용 공고** | `/app/postings` 목록 |
| 2 | 공고 목록 | 새 공고 등록 진입 | `/app/postings/new` |
| 3 | 새 공고 | **공고 입력** 탭에서 URL 입력 | URL 탭은 입력창 1개(textarea 없음) |
| 3' | 새 공고 | 텍스트 탭으로 전환 | 원문 붙여넣기용 textarea 1개 |
| 4 | 새 공고 | **원문 확인** | 수집된 원문·**원본 이미지**를 사람이 검증 |
| 5 | 새 공고 | **확인 후 분석** | 분석 잡 생성 → 목록으로 이동 |
| 6 | 공고 목록 | 상태 필터 | `분석 대기 / 분석 중 / 답변 필요 / 분석 완료 / 분석 실패` |
| 7 | 공고 상세 | 해당 공고 클릭 | `/app/postings/:postingId` |

**설명 포인트**
- 수집 → **사람 확인** → 분석 순서다. AI가 읽은 원문을 사용자가 승인하기 전에는 분석하지 않는다.
- 복수 직무가 걸린 링크는 확정할 직무를 되묻는다. 상세 공고 URL이 아닌 채용 목록 URL을
  넣으면 그 이유를 명시한 오류가 뜬다 — 지어내지 않는다는 원칙의 실례로 보여줄 수 있다.
- 분석 중 **분석 취소**를 눌러도 실패로 기록되지 않고 취소로 구분된다.

### 3.1 되묻기(답변 필요) 흐름

분석이 근거 부족으로 멈추면 상태가 **답변 필요**가 된다. 공고 상세에서 질문에 답하면
분석이 이어서 진행된다. "모른다"는 부족(`not_met`)이 아니라 `uncertain`으로 분모에서 빠진다는
점을 설명한다.

### 3.2 분석 결과

공고 상세에서 적합도 판정, 판정의 **근거**, 요구 역량, 지원 판단을 보여준다.
근거는 도구가 제공한 사실만 쓰며, AI가 만들어낸 회사명·수치는 표시되지 않는다.

## 4. 커리어 지도 — DRAFT → 미리보기 → 적용/취소

| 순서 | 화면 | 클릭 위치 | 확인할 것 |
|---|---|---|---|
| 1 | 사이드바 | **커리어 지도** | `/app/map` |
| 2 | 지도 | 로드맵 제안 배지 | 분석 결과가 **바로 덮어쓰지 않고** 제안으로 대기 |
| 3 | 지도 | 제안 열기 | 미리보기 그래프에 추가/변경될 단계 표시 |
| 4 | 지도 | **적용** 또는 **취소** | 적용 시 새 **버전**으로 발행 |
| 5 | 지도 | **버전** 선택 | 이전 버전 조회 |
| 6 | 지도 | 단계 카드의 **먼저 학습하기** / **나중에 하기** | 학습 우선순위 조정 |
| 7 | 지도 | **검증 전 확인** | 아직 검증되지 않은 항목 구분 |

**설명 포인트**: AI 결과는 제안이다. 사용자의 확인 없이 커리어 저장소·공고·로드맵을
변경하지 않는다. 적용 이력은 버전으로 남아 되돌릴 수 있다.

## 7. 활동 내역과 설정

| 순서 | 화면 | 클릭 위치 | 확인할 것 |
|---|---|---|---|
| 1 | 사이드바 | **활동 내역** | `/app/activity` — 분석·대화·적용 이력 |
| 2 | 사이드바 | **설정** | `/app/settings` — 계정, 저장소 연동(GitHub/GitLab) |
| 3 | 사이드바 | **대화 검색** | 지난 대화 검색 |

설정 화면의 **코드 저장소 연결** 카드는 항상 보이지만, **로컬 Docker 시연에서는 연결 버튼이
동작하지 않는다** — `compose.yaml`이 `GITHUB_APP_*`·`GITLAB_*`을 backend로 전달하지 않아
"설정되지 않았습니다" 오류가 난다([2-external-services.md](2-external-services.md) 4장).
로컬에서 시연할 때는 이 카드의 **목적만 설명하고 클릭하지 않는다.** 실제 연결 왕복은 운영
배포 환경에서 보여준다.

## 9. 마무리 멘트용 요약

- **판단은 데이터가, 말은 LLM이**: 매칭·계산·검증·분기는 결정론 코드가 하고, LLM은 읽기와
  표현만 맡는다.
- **모른다 ≠ 아니다**: 판정하지 못한 항목은 부족으로 세지 않고 되묻는다.
- **최종 확정은 사람**: 제출·전송 도구를 AI에 주지 않는다. 생성물은 초안까지다.
- **되돌릴 수 있다**: 로드맵은 버전으로, 저장소 병합은 되돌리기로 복구된다.

## 10. 시연 중 문제가 생기면

브라우저의 일반 오류 문구만 보지 말고 응답 코드와 요청 ID를 확인한 뒤 로그를 본다.

```powershell
docker compose logs --since 10m backend
docker compose logs --since 10m ai
```

분석이 오래 걸리는 것은 정상 범위일 수 있다(`AI_HTTP_TIMEOUT_SECONDS=660`).
동시 분석은 `AI_MAX_CONCURRENT_ANALYSES=2`로 제한된다.
